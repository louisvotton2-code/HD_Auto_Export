# CACHE-300 网关首页缓存

固定 OPS 工作区 `codex/ops-cache-300`，基线 `v1.0.10`／`a556b9721331fb39bbcf13233d51ed80b393ec1f`。本轮改动网关、部署模板及隔离测试。首页整页缓存由显式配置启用，默认继续动态渲染。只覆盖无查询的中英俄匿名 GET。配置绑定同一应用槽与发布 SHA，每槽最多三个 512 KiB 文档。对外响应保持 `no-store`，车辆 404、入口限流和静态文件策略沿用原有行为。[运行手册](../../../deploy/runtime/production/ext09-release.md#可选的内网首页缓存)

- 与 FE 冻结的协议使用私有版本和渲染两个接口，带尾斜线。版本检查使用 v2，并分别承载目录和筛选的实时标记。私有渲染基于当次页面真正使用的标记完成证明，网关只在完整 HTTP EOF 后验收、比较发布标识和两个版本域及汇率。采用数据和汇率等最早有效期，总上限 300 秒。独立单调时间避免时钟回拨延长活期。
- 公共及旧内网协议保留 15 秒上限，已复用 BE 的隔离协议证据。未确认 v2、缺少健康证明、过期、不匹配、超限、私有响应或请求带 Cookie／鉴权／RSC／预取时走动态路径。完整的降级 HTML 可立即返回并保持不缓存。私有流截断后回源获取完整动态 HTML。版本检查或私有渲染收到的 429 直接返回 `Retry-After`，不读旧缓存也不再次渲染。
- 组合验证从基线纳入 FE 冻结补丁 `9f1d6438517ec3fc276b4551c4eeb2a6c78ac6961c8c9d5e678aab7d4200deef`，以及 BE 的契约、SSR hooks、API 和必要 503 依赖切片 `78c77cb25857907137a6cea5a52836898ad4a4844a538437b409e9144b300b13`，应用迁移 `0032_public_filter_revision`。运行 Next.js 16.4.5 构建产物、Fastify、真实 Nginx、临时 PostgreSQL 18.6 和 1,000 条合成车源。API 使用内存缓存，Next 与网关读取同一个 0600 临时密钥文件，拒绝符号链接和宽松权限。
- 实测两个带尾斜线的私有接口直连均为 200，首次访问有实际健康证明，第二次从缓存返回前仍查两个实时版本。撤车提交后，首次请求立即由 1,000 降至 999。真实汇率过期使同版缓存立即失效。模拟过期和不匹配证明、筛选降级、外层截断时均显示完整 200 页面且不写缓存。还验证了 Cookie 绕过、对外控制头剥离和 /internal/ 404。API 真实限流后，热页只各查一次目录和筛选版本，对外返回 429 并保留 `Retry-After`。
- Node 28 项、实际 Nginx 11 项、发布槽 12 项通过。独立复审无未决 P0／P1。本地缓存镜像构建与入口语法检查通过，组合证据保存在本机临时工作目录。生产发布、生产负载变化及 Redis 生产配置不在此轮验证范围，成果保留在本地工作区。

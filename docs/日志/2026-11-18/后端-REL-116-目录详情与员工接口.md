## 目录与详情

PostgreSQL 18.6 实测 10 万条合成车源，其中供应商 99,000 条。下表是相同数据上 7 次本机读取的中位数，包含驱动往返或相应 DTO 组装。执行计划和原始抽样留在本机 `docs/private/rel116-be/`。

| 供应商路径 | 基线 | 候选 |
| --- | ---: | ---: |
| 无筛选精确计数 | 8.0 ms | 4.2 ms |
| 常见品牌精确计数 | 4.4 ms | 5.1 ms |
| 首屏原币价升序 | 15.8 ms | 5.9 ms |
| 首屏里程升序／年份降序 | 14.6／16.5 ms | 6.7／4.6 ms |
| 首屏美元价升序 | 50.9 ms | 23.3 ms |
| 概览／带车型概览 | 22.1／35.5 ms | 20.5／40.5 ms |
| 完整筛选字典 | 69.7 ms | 45.7 ms |

索引按空值置底及 UUID 平局顺序选页，四类原值排序的数据库执行计划只读所需页的 24 个索引条目。实时版本读取仍查同一事务更新的版本行。缓存隔离核验中，目录及筛选版本每项 300 次读取的 P95 为 0.85／0.88 ms。20 并发、四类列表／筛选合计每轮 80 次，本机 API 冷启动进程下各路径 P95 为 99–159 ms，热缓存为 28–29 ms，两轮均为 80 次 HTTP 200。生产同步负载下的延迟须单独复测。

美元排序与展示金额使用相同的精确分位舍入，缺价置底后仍能继续分页。上一版生成的美元价格排序游标返回 409，从第一页重新读取。

详情通过 `titleView=english` 同时取当前语言详情和可公开英文标题。合成供应商样本上，俄文详情加英文标题由两次完整详情读取减为一次，快照内 SQL 调用由 10 次减至 5 次，未压缩 DTO 由 8,481 字节降至 4,374 字节。FE 与 AD 消费格式见[车辆接口](../../开发/车辆接口.md)。

## 同步、缓存及员工验收

- 同步隔离通过 33 项单元和 33 项 PostgreSQL 用例。正式 worker 的模拟流程覆盖完整 CSV、截断后同快照续跑、改价、101 条增量写入中断和重放、旧事件、撤回及人工标题和里程保留。
- 隔离预热首页 HTML 和 API 后模拟 Redis 不响应。撤回后的首读中首页和目录均移除挂牌，详情返回 404。26 个冷查询同时进入故障路径，20 个成功，6 个在容量耗尽时返回 503。实际回源并发峰值 4，Redis 连接峰值 8。此三层演练基于 v1.0.15，候选仅改动查询和详情契约，另有版本一致性及缓存键定向回归。
- 同版 Chrome 及 PostgreSQL 组合通过管理员与两个合成员工用例。验证了北京时间零点前后、分页和回收站归属、员工越权 403、改密与撤销后旧会话 401、审计保留和旧首页列表形状。供应商账户和同步进度限管理员，编辑员继续读取挂牌和历史批次。生产同步状态的 15 秒计数超时已定位并在隔离验证简化查询，真实线上耗时待复查。

## 集成与迁移

迁移 `0033_external_catalog_order_indexes` 增加五个索引。99,000 条供应商挂牌上迁移约 5.8 秒，索引合计约 17.8 MiB，随后重复应用成功。事务建索引期间普通读取继续，供应商更新等写操作等待。OPS 在同步批次边界安排迁移窗口并保留断点，锁等待超过 5 秒时迁移会回滚。旧应用兼容新增索引。

AD 的真实隔离组合由 AD 执行，采用新版 `includeUploader=true`。OPS 的最终组合、正式入口计时、PR／CI 和生产复查仍需完成。准确后端提交及门禁回执随本机交接记录。

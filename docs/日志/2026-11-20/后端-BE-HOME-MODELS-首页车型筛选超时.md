# BE-HOME-MODELS 首页车型筛选超时

固定工作树 `codex/be-home-models-timeout`，基线 `7e1912222559446cafa4effd058a3645474cf262`。此前生产公开请求返回 503 和 `Retry-After: 5`，对应同一请求的 API 日志记录 `catalogReason: deadline`，服务耗时约 3.04 秒。随后同一查询直连 API 成功。旧日志无法确定首次超时具体停在哪一步。

## 本次改动

- 首页车型筛选冷查只读取供应商推荐车的品牌和车型 ID、首张有效封面到期时间，继续按推荐页里的精确配对统计目录车型数量。员工车复用现有公开快照与可见性规则。美元筛选缓存仍使用有效报价版本和期限。
- 迁移 `0035_home_model_filter_revision` 只更新版本触发器。检测报告、价格历史证据及问题标记单独更新时推进全局版本，筛选缓存仍可复用。涉及价格、标签、可见性、图片和首页配置等变化时按原有规则失效。保留原请求期限、公开接口、SSR 缓存协议和网关 gzip 配置。
- 首页车型筛选返回 5xx 或成功耗时达到 750 ms 时，服务日志按请求 ID 记录缓存查询或共享等待、数据库连接、车型选择与汇总等阶段。共享等待阶段需结合当时回源日志判断。

## 验证

- PostgreSQL 18.6 隔离回归覆盖筛选相关与非相关写入、混合事务、回滚、撤回、三语计数、公开和受保护 SSR 路径以及美元报价版本。报告提交后，首页车型筛选返回相同结果且没有再次计算，首页载荷仍获得更新后的全局版本。
- API 类型检查、构建、OpenAPI 和 workspace 边界检查通过。缓存和车辆单元定向共 22 项通过。目录与供应商集成 26 项通过，另有受保护 SSR、美元报价及目录投影定向共 23 项通过。最终迁移函数独立只读审查无 P0／P1。
- 十万条合成车源和 18 个车型配对的本机 API 注入测试共 15 次返回 200。冷启动首查 190.1 ms，八次仅报告更新后查询 2.3–6.4 ms，筛选计算执行零次。六次价格更新后重新计算，查询 75.6–85.4 ms，车型及数量一致。另在隔离库锁住首页配置，以不同语言冷查复现 503，仍返回 `Retry-After: 5`。对应日志记录 `home_scope` 约 3001 ms，公开响应不含阶段耗时。
- 两项隔离网关 gzip 回归通过，覆盖带尾斜杠的公开筛选路由、gzip 协商、解压后内容一致及 `no-store`。

## 交接

按常规发布流程在切换前显式应用迁移 `0035`，核对迁移记录。该迁移只替换两个触发器函数，没有表结构变更、回填或索引构建。切换前后核对唯一供应商 worker、活动快照 ID、应用与准入检查点和积压恢复。同步期间核对中英俄首页车型结果、成功率、阶段耗时，以及公开 API 的 gzip。

如需应用回退，恢复上一版 API 镜像并保留数据库和当前同步检查点。旧 API 可读取迁移后的表结构，报告更新仍会推进全局版本。真实目录、Redis、供应商同步负载和跨网络时延留待同版发布验收。

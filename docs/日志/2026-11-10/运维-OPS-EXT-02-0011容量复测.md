## Redis 冷波诊断与下一轮复测

- v1 原始冷波只保存聚合 `redisErrors=12`，没有逐连接失败类型。用同一 v1 镜像、实际隔离 Redis 和 ACL 做低开销复现。探针固定版本并用延时模拟两次数据库回源，不启动 PostgreSQL。首轮模拟回源过快产生额外 SET 拒绝，不能与原冷波直接比；把回源模拟延迟至 100 ms 后，20 个并发 GET 中 8 个建立连接并成功，12 个在拨号前被应用的 8 个并发 socket 上限拒绝；2 个 SET 成功，实际 ACL 错误、socket 错误和请求超时均为零。该组恰好复现 `redisErrors=12`、`originLoads=2`。
- 把探针上限临时设为 16 后，拨号前拒绝降至 4 个。20 次串行读及一次写全部建立连接；越权键单独得到 1 个可识别的 Redis ACL 拒绝。没有改应用、Redis ACL 或正式配额。结论基于可重复诊断而非原始逐请求追踪。Redis 读发生在同键回源合并之前，不能把 12 次保护拒绝当作 SQL 延迟来源或 HTTP 失败。原始证据为 `docs/private/ops-ext-02/retest-500k/redis-cold-probe-recheck.json`，探针源码留在同一私有父目录。

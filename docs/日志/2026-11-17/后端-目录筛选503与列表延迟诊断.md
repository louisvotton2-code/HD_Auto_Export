## 后续改动和验证顺序

1. BE 提供显式轻量筛选投影，概览在 SQL 层只聚合总数、品牌、动力、驱动、年款和配置可用标记。品牌选定后查车型，品牌和车型选定后查配置及代际。FE 的首屏和动态筛选统一接入，保留旧链接已选车型、无脚本流程与完整筛选接口。用当前规模的隔离数据核对精确计数、三语选项、按范围过滤、缓存体积和冷／热耗时。
2. OPS 验证公开目录 JSON 的协商压缩，检查 `Content-Encoding`、`Vary`、内容等值、`no-store` 和边缘 CPU。比较首字节与下载阶段。线上变更走现有验收和发布流程。
3. 用固定枚举记录回源等待、版本读取、数据库连接等待、SQL、版本重试、超大小与超时，保留网关与 API 的耗时及请求关联。再用同一失效窗口判断列表是否受筛选回源并发影响，以及是否需要按目录版本和筛选条件复用跨页精确计数。现有数据库查询可以长于 HTTP 等待时间，需实测并验证两者的取消和释放行为。

仓库钩子检查通过。独立只读核验覆盖官网代理、Nginx、目录 SQL、缓存与已有生产证据。当前代码与生产配置未改，服务器历史日志与数据库查询计划待取得。

## 优化实现与隔离验证

- 增加 `overview`、`overview-models`、`models` 和 `variants`，由 PostgreSQL 按投影聚合。官网首屏、动态目录与首页接入分层请求。中英俄可见性和精确总数以原查询作对照，完整接口省略投影即可继续使用。见[接口契约](../../开发/车辆接口.md#官网目录首屏与按需筛选)。
- 正式网关配置为公开目录 JSON 和 `/catalog-facets.json` 开启 gzip 协商，压缩级别 4，最小 256 B。隔离 TLS 核对 gzip、`gzip;q=0`、无压缩声明、`Vary`、`no-store` 和解压逐字节相同。独立审查发现新增 include 会被正式热重载的文件集合校验拒绝，已将设置并入既有配置。用双槽生成器和正式预检比对现有、候选六个文件路径，结果通过。
- API 记录固定 503 类别及回源、版本、缓存超限和连接等待计数。公开错误码、文案和等待头沿用原契约。独立评审复核修正后无未决阻断。

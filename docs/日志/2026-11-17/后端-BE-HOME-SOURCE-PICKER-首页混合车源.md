# 首页混合车源 API

固定 BE 工作树 `codex/be-home-source-picker`，基线 `7267abbad6656769badcc85a53acd04a39b88589`。已核对上一轮 REL-107 本地提交 `0afdc00` 与主线采纳的 `72c6de4` 树一致，旧分支保留。

首页配置沿用版本化 PUT 与既有 JSON 存储。保存按员工 UUID 与供应商 `ext-*` 分流，校验员工发布状态和供应商公开投影、可见性与主身份。记录顺序、默认语言规则、每组 30、两组配置、权限保护及旧客户端形状沿用原契约。供应商候选沿用后台列表和详情，不新增参数。 [接口契约](../../开发/车辆接口.md)

公开 localized 首页按当前语言批量读取所选供应商车，只取已有公开字段与一张有效封面。legacy／未传 view 时过滤直供 ID。已有目录版本触发器覆盖隐藏、撤回、代表切换对应的目录投影修改及首页保存变动。

真正回退到旧 API 前，先备份当前首页混合配置，在新版 API 仍运行时以当前 `version` 原子保存仅含员工 UUID 的配置，确认返回版本和公开首页成功，再切换旧产物。保留标题、区块和员工顺序供恢复。旧版将全部 ID 转成 UUID，无法读取已经写有 `ext-*` 的配置。新版上线后通过同一版本化 PUT 恢复原混排，并重新核资格。

## 验证与联调

- 隔离 PostgreSQL 18.6 的外部目录测试文件 14 项通过。混合保存覆盖位置顺序、三语读取、询价短号和公开字段、重复选择边界、版本、匿名和 Origin、隐藏及撤回版本失效，另模拟残留投影验证非主身份防御过滤。正常切换主身份的版本失效由独立审查核对现有投影触发器，未专门再跑实际代表切换。
- 原员工车辆生命周期及回收站 2 项定向回归通过。契约构建、API 类型与 OpenAPI、钩子及差异检查通过。未调用供应商、翻译或生产接口，无数据库迁移。
- 本机 `3320/health/ready`、`3363/admin/` 以及两端口的 localized 首页 API 均返回 200。既有本机配置返回 6 辆员工车辆、0 辆供应商，未向共享库写入。实际混排写入与删减是在一次性数据库验证，浏览器组合验收由 OPS 执行。

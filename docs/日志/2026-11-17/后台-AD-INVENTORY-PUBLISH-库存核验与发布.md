# AD-INVENTORY-PUBLISH 库存核验与发布

本轮从 `6bffd14bd444e05526c6b36f549c734003754480` 接手，在固定后台工作树的 `codex/ad-inventory-publish` 修复。变更位于 `vehicle-actions.tsx` 和 `translation-cases.ts`，沿用 BE 已有的库存更新和发布契约。

用模拟接口复现库存已保存、响应未送达时，提前返回的发布检查读到了新版本。旧页面同时进入库存结果核对与版本冲突，导致「读取当前状态」按钮禁用。修复后这次检查仍判预览过期，库存结果可以读取并由员工采用。库存接口明确返回 409 时仍进入版本冲突。采用当前版本后可以继续保存草稿，发布仍绑定新版本的员工预览确认。

已发布车源仅核验库存时，成功提示说明官网库存已同步，无需重复保存或发布。已保存的公开资料有变化时，提示继续核对当前草稿。

后台类型、构建、124 项单元、6 项隔离守卫及 17 项定向浏览器测试通过。独立审查无阻塞项。按审查建议补强待发布草稿在库存结果未确认时的禁用断言，并增加库存接口明确返回 409 的用例，两项增量复测通过。模拟覆盖库存回执丢失、核对恢复、按新版本保存与发布，以及成功更新库存后保留待发布资料。3363 已提供新版组件，API 就绪返回 200。验证使用模拟车源和接口，未在员工实际车源上更新库存或发布。

## 发布候选隔离联调

复用定向自测及独立审查，在一次性 PostgreSQL、合成员工与合成图片上跑一条组合浏览器场景。中、英、俄受保护预览读取排量、发动机功率、零里程、车身级别和所在地。从三语配置补充显示制造日期，仍保留真实基础日期为空。已显示的排量和日期从配置区去重，座位项仍在。

首次发布后，真实 API 接受预订库存更新。浏览器故意丢弃该回执，并在旧页面收到新版本的发布检查结果。「读取当前状态」仍可用，采用后继续保存新价格。此时公开快照维持原价，库存已更新。由同一草稿版本完成预览确认和再次发布后，公开中、英、俄三种响应均返回新价格及配置内容，未包含内部采购成本或备注。两次发布均由隔离用例明确操作，期间翻译请求为零。

第一轮将员工预览专用的 `technicalDetails` 错用于常规公开响应断言。改为检查公开契约中的规格与配置后，组合用例通过，未改应用代码。测试使用 BE `096a397` 的 API 与契约和当时的 FE 源码快照。测试期间 FE 增加供应商数据的独立分支，自录车辆的补齐逻辑相同，供应商专项由对应端验证。发布前仍须核对最终集成树和 CI。

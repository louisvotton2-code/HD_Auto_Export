# REL-117 公开车图条件重验

- 固定 BE 工作树 `codex/be-rel117-media`，基线 v1.0.16／`7624502fb4bebe81129fa6a329dc9d3935e13f6b`。范围为自录公开原图、240px 缩略图、员工预览的缓存边界及接口资料。
- 公开 GET／HEAD 每次检查当前发布引用和所选的私有文件。原图与缩略图独立生成弱 ETag，同大小同修改时间的原地写入也会使对应标签变化。有效 `If-None-Match` 命中时只发送 304 响应头。公开 200／304 为 `private, no-cache`。撤销、未发布、缺文件及私有预览保持原访问保护。非活动槽的原图回退、预览以及 API 错误使用 `no-store`。
- 直出和 Nginx 路径已接线。公开 200 内部跳转为 `/_hd_public_media/`，员工预览沿用 `/_hd_media/`。正常公开 304 无需内跳或读正文。带条件头的私有预览鉴权后直出，避免静态处理误返回 304。状态、缓存及 ETag 约定见[车辆接口](../../开发/车辆接口.md#固定协议)。
- Node 24.22.1 类型检查和 73 项定向测试通过。隔离 PostgreSQL 18.6 有 11 项媒体回归通过，覆盖两种模式的原图、缩略图和 GET／HEAD，携带旧 ETag 的软删除后请求仍返回 404。独立审查结论随准确提交登记。
- 与 OPS `e47bb08` 在本机 Nginx 1.29.0 做双域隔离联测，109 次请求通过。两域均只发一个 Cache-Control 与相应 ETag，匹配返回空 304，撤销或缺文件为 404，内部地址外部访问为 404。带通配符的鉴权预览仍 200、`no-store`。单域配置检查通过。
- 实测新域名片段与 v1.0.16 的旧 `00-edge.conf` 混用报映射变量缺失。OPS 集成须在启用本轮 API 前使新版共享配置进入实际网关并核对 `nginx -t`。正式镜像及生产浏览器复测由 OPS 完成。

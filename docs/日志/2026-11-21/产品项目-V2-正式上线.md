## 跨端业务口径

**事件与报表。** 保留旧版同源批量入口和旧版 7／30 天总览。一次成功导航产生一次浏览，车辆页浏览同时计入 PV 和详情浏览。卡片激活、主动点击联系方式、筛选提交、零结果和成功完成费用计算分别记数；自动弹窗、预取和员工预览排除。零结果要求查询成功且结果确为零。联系点击记录 WhatsApp／Telegram 等通道；实际收到的询盘需另有客服回执。

使用新的同意状态分别控制本站分析和 Meta。30 分钟无操作结束匿名会话。使用同一会话按时间顺序计算“目录→点车→详情→联系”，防止把不同车辆或倒序的事件拼成成交；从站外直接进入详情单列。当地日界采用既有 Asia/Shanghai，今日环比用相同时段；会话可以跨午夜。车辆排行先在整个所选区间和结果中按所选指标排序，平局使用稳定车辆标识，随后分页。详情联系率用有详情浏览的会话作分母、其中详情后联系该车的会话作分子；分母为零时显示无可比值。按来源分析提供相应来源的会话分母。旧客户端缺少会话的事件可进入次数，不补造转化会话。

国家仅通过可信网关提供的 IP 在本机判断。分析日志、报表及导出不留完整 IP、完整来源 URL、聊天内容或自由搜索词；来源和 UTM 只允许已知枚举／登记值。每日独立 IP 估算单列，跨日不相加。短期去重保留 7 天，经营聚合 90 天，恢复后继续执行到期清理。历史未采集、采集停顿与实际零次需可区分。Meta 只有在有效 Pixel ID、广告开关和广告同意均满足时加载；PageView、ViewContent、Contact 均来自同一次真实操作，金额以当时展示的 USD 为准。缺少 Pixel ID 时保持广告关闭，有权限时再验 Meta Test Events。

**SEO。** 同一份可发布名单供详情资格和地图使用，最多选 1,000 个优质第三方车辆身份，再按资料完整的语言生成链接。首页、目录、指南、关于、国家计算器和合格自录车列入首批；筛选组合、搜索、未完成配件、后台及预览排除。临时故障返回 503，永久撤回／删除使用真实 404 或 410；复核缓存、地图与语言互链均随资格变化生效。分片最多 10,000 URL，未压缩不超过 50 MiB，发布完整的一代后原子切换。

**同步。** 分别记录供应商事件、本站收到、应用、详情更新和公开投影体现新值的时间。待处理与失败事件须计入积压并报告最老年龄。用隔离车测试人工覆盖、撤回、重放、重挂、缓存冷热与图片临期。线上低频只读观察；展示 24 小时窗口的样本数、未完成项和缺失区间。撤回收件到公开 P95 ≤5 分钟，已公开车改价收件到公开报价 P95 ≤30 分钟。实际数据不足时继续观察。

## 同版联调用例

在隔离库选两辆可公开车辆 X、Y。以下是输入和预期，尚未实跑。前三个会话仅同意本站分析。日期与分桶均用北京时间，在可控测试时钟内推进，不能把历史时间当作服务端刚收件的时间。

| 会话 | 输入 |
| --- | --- |
| A | 第一天 23:58 看目录，23:59 点 X，第二天 00:00 看 X 详情，00:01 点击联系 X。同一联系事件 ID 在批内重复一次，再将该批重新提交 |
| B | 第二天 09:00 从站外直达 Y 的详情，然后点击联系 Y |
| C | 第二天 10:00 看目录、点 X、联系 X、看 X 详情、联系 Y，依次发生 |
| 旧版 | 第二天 11:00 只看一次 X 详情，沿用旧版事件格式，无匿名会话 |

按 PV／详情浏览／点车／联系点击核对，第一天应为 **1／0／1／0**，第二天为 **5／4／1／4**。区间内可识别会话 3 个，有序目录漏斗应为 **2→2→2→1**，站外直达详情 1 个，能归因的详情联系人次按会话去重为 2／3。C 的倒序联系、异车联系保留在总点击数中。旧版 7／30 天响应继续通过旧版严格结构解析。

PV 和点击按发生的小时／日期展示。会话漏斗按入场日期归组，A 的完整漏斗归第一天；后台应标出最近仍在进行的会话。浏览器可能在同一批上报点车和详情，联调要覆盖同一收件时间下的操作顺序。短期去重清理后，7 天以前的趋势、漏斗仍可读取已形成的匿名聚合。

另在浏览器隔离并拦截 Pixel 网络，先设置测试同意状态，再打开详情并主动联系。仅统计、仅广告、两者同意、两者均撤回四种情况下，本站浏览／联系事件合计预期分别为 **2、0、2、0**，Pixel 的 PageView／ViewContent／Contact 合计分别为 **0、3、3、0**。拒绝和撤回后检查请求与待发送队列。联调不触达真实客户，不向正式广告账号写测试事件。

在 URL 查询串和来源页分别放入仅用于隔离测试的识别字符串，检查实际网络载荷，包括 SDK 自动附带的页面地址与来源地址；两个字符串均不能进入广告请求或经营报表。使用公开咨询编号作为 Meta 的车辆标识。对站内统计再核实未知国家、跨午夜和多日 IP 估算的显示。

## 验收与放行

1. 分别验证仅同意统计、仅同意广告、两者都同意和撤回。通过本地采集、存储、后台报表的整条链路核对去重与权限。统计写入失败时，查车、报价与联系正常可用。
2. 在约 50 万条数据的等配隔离环境分别跑冷缓存、热缓存、同步并行、缓存故障。20 并发常用目录／筛选 P95 ≤800 ms，错误率 <1%；列出 429、统计丢弃和数据库压力。50／100 并发用于标出容量拐点。俄语手机目录品牌检索可用时间三次中位数 ≤3 秒，上线后另记真实用户 P75 和样本量。
3. 核定准入是否够未来 24 小时；保留一个同步 worker、持久游标和磁盘 60% 告警／70% 暂停。核对下一轮实际定时 CSV、增量重放、最近一份自有数据的隔离恢复。有旧备份时按既有保留策略管理。
4. PM 验证 `127.0.0.1:3363` 上的官网和后台确实连到同版 API，再交用户本地验收。经用户验收、独审和 CI 后才合并 main、打 `v2.0.0`、平滑切换。兼容迁移及观测先行，统计、广告、公开索引分别控制。切换后验数据与缓存、再开放首批 SEO；有站长权限时提交地图。开放 48 小时后依据抓取、负载和同步时延决定是否扩大。

# FE-VEHICLE-PIXEL 后端单车推广开关

固定工作树 `codex/be-v2`，基线 `11fd1b1b9f0ed5bc07c3bd18b5189d6576583350`，与远端 `main` 一致。保留既有 v2 开发内容。本轮只改 API、共享契约和接口说明，使用隔离数据库和合成车辆。

## 实现与交接

- 管理员通过两类车的 `/pixel` GET／PUT 读取和保存独立开关版本。默认关闭，重复同值保存直接返回当前状态。并发提交试图覆盖现值时，旧版本返回 409。实际变化在同一事务记录员工、车辆、请求 ID、开关差异和版本。三方审计使用 `audit_events` 的 `external.pixel.update`，变更记录的 `listingId` 路径保存公开身份。
- `0043_vehicle_pixel` 分别引用人工车辆和稳定的三方挂牌 UUID。管理变更独立于草稿、发布、图片和翻译。三方增量同步及撤回均保留人工设置。实际变更推进共享公共目录版本，筛选版本维持独立。沿用全局版本会使列表缓存重新验证，旧分页游标可能返回 409。
- 公开详情、SSR 别名与现有详情恢复使用 `view=localized&projection=detail-inline-v1&pixelView=eligible`。新请求收到明确布尔，旧请求保留原数据形状。目录、首页、分段、私有预览均不提供开关。管理契约和缓存规则已发送 FE、AD、OPS 和 PM。[接口详情](../../开发/车辆接口.md#26-fe-vehicle-pixel-单车开关)

## 验证与边界

- 独立 PostgreSQL 18.6 的定向测试 4 项通过。Fastify 注入验证管理权限、Origin、默认关闭、并发冲突、幂等、审计失败回滚、公开接口和 SSR 各语言读写、旧投影兼容和三方合成增量。已开启的三方挂牌隐藏后详情为 404。自录车进回收站后开关不可读写，恢复草稿保留已有设置且详情仍为 404。既有详情、美元和缓存集成 12 项，以及缓存单测 23 项通过。共享契约 99 项、API 类型检查／构建／OpenAPI、BE 树的后台构建通过。独立审查未发现 P0／P1 阻断。
- BE 树的旧官网副本类型检查仅在 `apps/web/tests/site-analytics.spec.ts:57` 失败，旧测试直接从 v2 统计事件联合类型读取 `vehicleId`。FE 固定树已对该测试加属性判断，最终组合以 PM 核对为准。
- PM 同版验收检查后台实际开关、已打开详情恢复以及三语 SSR／RSC 开启和关闭。OPS 候选已将第三方设置及其挂牌身份纳入第一方备份路径，BE 未执行实际备份恢复。配对 API 和官网切换，启用 Pixel 的新官网遇到旧 API 会因新增参数在旧接口返回 400，官网将详情按 404 处理。初交付时样本库仍在 0042。

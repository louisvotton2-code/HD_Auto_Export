## 浏览数据缓存

`PUBLIC_BROWSE_CACHE_ENABLED=true` 选择已有有界公开缓存的浏览模式，复用 L1、Redis 槽位、同键单航班及回源限额。入围为无认证、无会话或条件控制的公开 GET，包含首页精选、偏移分页、搜索和筛选。受信 SSR 私有别名显式协商 `browse-600-v1`。旧 SSR 客户端、版本绑定游标、详情和员工接口使用原规则。线上仍保留正式发布门禁及现行 gzip。

首次生成的 UTC 时间加 600 秒是上限，媒体或 FX 更早到期时采用更早值。冷热、跨实例 Redis 和服务端复用共同保留同一绝对到期点。浏览数据入口只读 0052 增加的独立紧急代数。常规同步、改价、供应商主动撤回和普通库存变化不推进旧浏览缓存，详情仍读实时目录版本。员工明确隐藏三方挂牌或归档、删除已公开自录车时同事务换代。业务回滚不推进代数。旧回源若在完成前发现紧急换代会重试或失败关闭。

API 控制读和数据凭据见[车辆接口](../../开发/车辆接口.md#browse-600-匿名浏览)。上层热缓存不能只验证宿主机文件。当前 OPS 草案在热 HTML 命中时只验证该文件，FE 仅在冷渲染时核对数据库代号。直到命中路径使用权威 BE 代号或完成等价的保存前屏障前，网关额外的整页模式需保持旁路。网页侧仍可通过已协商的 BE 数据缓存获得收益。

## 紧急下架屏障增量

OPS 真实隔离复现中，后台归档返回 200，三语详情首次读取已为 404，三语热首页仍保留旧车。原热 HTML 仅验证宿主活动标记。归档事务同次推进的是数据库紧急代号。

BE 接入 OPS 同一个只读运营文件。公开和受信浏览查询在暂停、损坏或缺失时走实时版本路径，权威控制返回 503。活动标记参与 BE 浏览代号和缓存键，更换时无法重用旧内存／Redis 条目，进行中的回填或查缓存会重新核对标记。数据库紧急代号、已有管理写事务、公开详情及默认无文件配置兼容，沿用原限流。网关须同时按请求核验数据库紧急代号，完整回填结束再验。正常热命中因此读取一行紧急代号，不读取全站目录版本。

本地 PostgreSQL 18.6 与 Fastify 联调 22 项通过，覆盖三语公开与受信别名、文件暂停到恢复、回滚及 API 重启。缓存单测 34 项通过，含进行中的冷回填、Redis 命中在暂停后被拦下。OPS 网关增量仍须按真实同版验收后启用。

## Redis 跨实例截止时间

采用 OPS 隔离环境已验证的原补丁。Redis 传输层将写入上限从 300 秒调整为 600 秒，使 Browse 和受信首页协议各自计算的合法最长时限可存入共享缓存。各协议原有期限、媒体和汇率硬截止、固定键槽、ACL 与连接数约束继续生效。读取 Redis 不会重写条目，本地缓存继承原始生成时间和绝对截止。

核对 OPS 真实 Redis 7.4 与两个 Fastify 实例的运行收据。普通数据库更新后，另一个空本地缓存的实例取得原快照。两个实例都返回北京时间 20:35:37.524 生成、20:45:37.524 截止。该组合中的 Redis 传输层、边界测试和缓存读取实现与本增量逐字节一致。

本轮独立使用真实 Redis 7.4.12 和三个新 Node 进程复验。应用时钟推进至第 597 秒时，第二个进程复用原始时间和内容，Redis 的 `PEXPIRETIME` 不变，剩余 TTL 从 599,876 下降到 599,498 毫秒。应用时钟超过原截止 1 毫秒后，第三个进程拒绝 Redis 中仍存的旧条目，只回源一次。Redis 自身时钟正常运行。运输层及缓存边界 39 项回归、API 类型和构建通过，独立复核无剩余 P0／P1。

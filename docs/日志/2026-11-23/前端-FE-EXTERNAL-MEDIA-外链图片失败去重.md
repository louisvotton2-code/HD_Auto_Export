# 外链图片失败去重与详情图库焦点

v2.0.17 门禁候选 `17983f3` 的首败与重试均出现同一外链图片、同一 revision 上报两次。两份 trace 都记录到目录页 POST、详情真实 document GET、详情页再次 POST。两个 POST 都返回 202。隔离构建按原用例复现 2 次上报。进入实时详情会重新载入模块，目录页留下的内存集合随旧文档销毁。

官网按图片 ID 和 revision 在同源标签页的会话存储记录失败尝试。最多 128 条，自首次尝试起 10 分钟，后续重复失败不延长有效期。存储不可用时保留当前文档内存去重。记录先于请求写入，短请求可在文档跳转时继续投递，网络失败后没有自动重试。真实详情仍从最新数据读取，图片本地占位仍立即展示，图片新版本允许独立上报。

相邻图库检查发现另一处同导航回归。详情重查卸载旧图库，打开过的原生弹窗失去焦点恢复目标。原候选独立构建连续两次复现。刷新开始时记住该次导航是否关闭了当前图库。仅在同一次刷新收到空图库、页面仍未获得其他焦点时，把焦点交还给新图库占位区域。未核实或已撤回的详情保持原有屏蔽。

最终官网类型检查、模块边界、1,314 项单测和 Next standalone 构建通过。隔离 Chrome 将 `external-catalog.spec.ts` 与 `catalog-navigation.spec.ts` 真实导航连跑两轮，32/32 通过。同图同版本的上游 POST 仍严格断言为 1，且确认详情加载新文档。新测试核对两个有效 revision 各被隔离 API 接收一次。图库空态、键盘焦点、滚动恢复、筛选分页返回和撤车后详情不可见均通过。

最终候选的全量发布门禁由 PM 在同一整合 SHA 上复跑。原门禁、隔离复现与定向测试的本机收据存于私有目录。

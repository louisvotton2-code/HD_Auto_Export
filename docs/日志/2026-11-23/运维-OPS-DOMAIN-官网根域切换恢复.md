# OPS-DOMAIN 官网根域切换恢复

## 故障与公网恢复

2026-11-23，用户已将 `hongdingauto.com` 与 `www.hongdingauto.com` 指到生产源站，`cars.hongdingauto.com` 已 CNAME 至 `okkishop.site`。切换时新站 Nginx 默认拒绝未配置的 SNI，旧证书仅覆盖 cars 和 admin，因此根域与 www 在开始渲染前就出现 TLS 握手失败。

以线上 v2.0.16 `2ce683ec69c52a6bb54190e52beb2ffbcf870476` 为基线，在现有 HTTPS 入口增加根域和 www 的 HTTP-01 验证。双域验证通过并签发独立 `hd-auto-apex` 证书。本机网关配置先备份再校验重载，13:27:49 完成入口恢复。公网 TLS 验证正常，根域俄语首页、中文目录、车辆 API 均为 200，www 以 302 保留路径和查询串跳根域。后台匿名请求为 401。未改 DNS，数据库与进程沿用原版本。紧急恢复阶段临时直接出 Web，并在根域禁止抓取，等待根域专用构建的 canonical 与站点地图。

旧站 cars 已通过两家公共 DNS 核对 CNAME。从生产网络对 OKKI 两个实际地址直连并使用 cars 的 SNI，两次均在 TLS 握手阶段失败。已提示用户在 OKKI 原站后台绑定 `cars.hongdingauto.com` 并启用该域名 HTTPS。绑定及证书签发以旧平台后台和再次公网验证为准。

## 统计与续期

13:34:48 验证新根域两个现有统计入口。网关先校验固定的根域 Host、Origin、路径、POST 和浏览器同源标记，再仅对这两条请求使用当前 API 允许的逻辑来源。原 Cookie、鉴权、来源和私有标头清空规则保留。各发空 JSON，合法同源到达 API 并被必填字段校验拒绝为 400，null Origin 和跨站为 403，无真实事件或联系统计写入。下次签版用 API 显式允许新根域，届时移除临时映射。

原 cars/admin 共用证书在 cars 指向旧平台后无法依靠原 HTTP 验证续完整两域。另为 admin 签发专用证书。根域／www 和 admin 的新部署钩子只消费各自的 Certbot lineage，并使用各自的数据盘证书目录。旧证书作为临时回退材料保留。

私有收据位于主目录 `docs/private/ops-v2/domain-20261123/`。

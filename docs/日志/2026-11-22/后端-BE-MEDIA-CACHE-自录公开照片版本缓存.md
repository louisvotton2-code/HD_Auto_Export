# BE-MEDIA-CACHE 自录公开照片版本缓存

从 v2.0.8 开工，冻结前快进到仅包含官网 iPhone 修复的主线 `a935ea9f13aee23699d20672e51aa227f46cf7cb`。固定 BE 工作树 `codex/be-public-media-immutable`。已经公开并下载的图片在下架后可继续复用，API 收到新请求时仍校验当前发布。

手工自录发布图的 `images[].url` 可包含 `UUID_43位base64url版本`，媒体 ID 和 DTO 其余字段沿用现有契约。版本绑定同一生成配方、显示原图及两种派生图的三个真实 SHA-256。原图、thumb 和 card 使用同一路径段，尺寸仍由既有 `variant` 参数区分。列表、首页、详情和相册在发布读取时批量取数据库摘要。新上传完成时准备摘要，0049 添加摘要侧表和历史批量登记入口。未登记、员工预览及供应商外链使用原协议。

API 为带版本且验证通过的 200、HEAD 和 304 提供一年强缓存。重新发 HTTP 请求时仍校验当前引用和实际文件。完整 200 直接发送经过验证的字节，每进程最多 12 个进行中的验证与发送。可走 Nginx 的忙碌请求临时 307 到同尺寸裸 UUID，回退响应继续 `no-store`，原有内部跳转只用于裸地址或员工预览。其余版本图饱和路径返回可重试 503。缺文件、字节变更、未知版本或撤权走 `no-store` 错误。

Node 24.19.0 的文件与媒体路由定向测试 57 项通过，隔离 PostgreSQL 18.6 的发布、历史补录、尺寸与版本错误、撤权和服务准备检查共 16 项通过。对照补录只推进目录版本，保留筛选版本。变动后的旧地址拒绝，新地址可交付已验证字节。相关类型检查、OpenAPI 和构建通过。FE、OPS、AD 已收到接口格式。生产组合、浏览器复访、初次冷流量及历史照片补录覆盖率由同版验收确认。本轮为本地候选。

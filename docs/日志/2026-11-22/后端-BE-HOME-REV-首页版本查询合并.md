# BE-HOME-REV 首页版本查询合并

生产 v2.0.14 在 10 并发完成 40/40，没有复现目录版本推进引起的 503。20 并发的前两轮 40/40，第三轮 `/zh/` 返回带 `Retry-After: 28` 的 429 后停止。同期 API 的 27 条 429 全落在已独立限流的 `/internal/public-catalog/version`。源站日志确认后端版本配额拥挤，公开 JSON 独立额度没有混用。

- 首页整页缓存预检把同一匿名访客的两次版本读取合成一次。API 在一条 SQL 中读取目录版本、筛选版本和同一份有效汇率，各自返回原有版本标识。受信访问、公开限流、回源并发、每访客版本读取上限、实时快照和缓存证明边界继续执行。
- 首页动态渲染内的 `overview` 与 `home-models` 共享当前页面的首次筛选版本读取。需要重试时仍读取当前版本。首页无冲突时，整页缓存命中从两次检查降至一次，预检加动态渲染从五次降至三次。现有数据库结构无需修改。
- v2.0.14 20 并发的成功新连接从请求发起到 TLS 握手完成耗时 855–890 ms，其中从 TCP 建连完成到 TLS 握手完成耗时 415–444 ms。连接建立阶段已超过公网总耗时 P95 ≤800 ms 的目标。优化减少源站重复读取，公网延迟仍需按新旧连接分层报告，并保留原整体验收口径。

定向验证覆盖 53 项 API 测试（含隔离 PostgreSQL）、99 项公共契约和 89 项官网测试。真实查库验证无关目录推进只更改目录版本，汇率变化推进行为同时影响两个范围。旧协议、权限、限流、下架和跨请求不复用版本均纳入验证。

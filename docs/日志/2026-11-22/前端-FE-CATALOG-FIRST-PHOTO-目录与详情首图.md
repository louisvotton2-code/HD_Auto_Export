# FE-CATALOG-FIRST-PHOTO 目录与详情首图

固定 FE 分支 `codex/fe-catalog-photo-performance`，PM 集成基线 `154cb69397bd8c005e93f04d757ae01df8d4020f`。生产现象取自 OPS 的 v2.0.1 中文桌面和俄文手机 Chrome 各一条目录、详情旅程。每端样本量为 1，无可用 P95。生产复测由 OPS 执行。

## 目录

- 中文目录 HTML 首字节 1.455 秒，FCP 3.084 秒。成为 LCP 的 44,120 B `card` 请求到 3.061 秒才发出，图片在 4.484 秒绘制，页面到 5.330 秒才完成客户端接管。SSR 已给出卡片标记，但原版所有图都是 `loading=lazy` 并让浏览器按布局计算 `sizes=auto`，所以图片发现挨着首次布局。同一图在俄语手机样本传输了 203,736 B。旧瀑布图省略了媒体查询参数，仅凭该条不能确认变体。字节差和当前 DPR 计算均支持手机选中了原图的判断。
- 仅优先加载第一张存在的目录封面。它使用明确的响应式尺寸及 eager/high，React 从同一组属性在 SSR head 自动预加载。其他封面保留懒加载，已知尺寸的大本地图优先限制到 API 的最长边 800px 变体。小原图照常使用。外部、带签名或缺尺寸的资源保留原有地址。变体故障时最多回原图一次。合成的 390px／DPR 3 Chrome 测试验证 head 中有且只有一条对应预加载、首图只请求一次 `card`、其他图不提升为高优先级。[目录列表](../../../apps/web/src/modules/vehicles/ui/public-vehicle-list.tsx) · [卡片选图](../../../apps/web/src/modules/vehicles/ui/vehicle-photo.tsx)

## 详情

- 中俄详情首图在 HTML 首字节后约 17／33 毫秒已经请求，没发现需要另加预加载的证据。两端下载同一 131,724 B 原图，LCP 分别为 1.836／1.288 秒。公开内嵌相册现在复用现有 `card`，限制大图展示体积，短边很窄的竖图和原本已小的图片沿用原图。高像素密度设备或部分宽平板在内嵌相册可能看见较低清晰度。点开大图、使用原图链接仍获得原图，员工受保护预览继续使用原图及实际图片解码握手。[公开入口](../../../apps/web/src/modules/vehicles/ui/public-vehicle-gallery.tsx) · [相册实现](../../../apps/web/src/modules/vehicles/ui/vehicle-gallery.tsx)
- 验证公开详情只预加载一次首屏 `card`，缩略图按独立 `thumb` 变体加载。大图窗口打开后翻页只加载目标原图，遮住的内嵌相册等窗口关闭再跟随，即使相册版本已替换全部照片。内嵌派生图出错只回原图一次，大图原图失败不会覆盖已加载成功的内嵌图。API 在未预生成派生图且处理繁忙时仍可能返回授权原图。实际生产占用需同时看变体、响应体积和缓存头。[图片交付](../../../apps/api/src/app.ts) · [浏览器回归](../../../apps/web/tests/responsive-public-media.spec.ts)

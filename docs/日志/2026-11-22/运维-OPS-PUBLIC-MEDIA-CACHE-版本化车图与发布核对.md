# 版本化车图与发布核对

固定 OPS 工作树 `codex/ops-v2-readiness` 已快进到主线 `a935ea9`。本轮对真实 Nginx 配置做隔离回归，供组合版本验收。

## 网关契约

BE 最终约定为 `/api/v1/media/{uuid}_{43位Base64url版本}`，原图省略尺寸，缩略图和卡片图使用 `?variant=thumb` 或 `?variant=card`。一个版本对应该图三种表示的字节。API 核对公开权限、登记摘要及同一文件句柄读出的字节，然后直接返回图片和唯一的 `Cache-Control: public, max-age=31536000, immutable` 与 ETag。条件请求可以返回相同缓存头的 `304`。浏览器已缓存的公开字节可按一年缓存策略复用，源站收到新请求时仍核对公开权限。

`deploy/runtime/nginx-domains.conf` 的既有单段媒体路由能在两种尾斜杠形态下保留版本和尺寸。`nginx-domains/api-proxy.conf` 传递 API 的缓存头和验证器。版本化响应经过普通 API 转发；旧 UUID 和私有预览沿用各自现有的内部文件映射。旧版衍生图缺失时授权原图使用 `no-store`，版本化路径的失败响应也保留 API 的 `no-store`。现有 HSTS、文件路径拒绝和媒体规约继续使用。

隔离测试使用实际 Nginx 与本机 Unix TLS 套接字，对模板和渲染后的两个域名生产配置运行。新媒体测试覆盖三种尺寸、带或省略尾斜杠、直接 `GET`、`HEAD`、条件 `GET` 和条件 `HEAD`，同时比较唯一缓存头、ETag、正文、长度及 HSTS。移开加速映射的测试文件目录后，新版模拟 API 仍可直接返回。另覆盖旧裸 UUID、旧衍生图回退、未知版本、撤回、版本化表示失败、私图和内部分发地址的匿名直访 404。模拟 API 夹具用于验证网关转发，正式 BE 摘要核对属于组合验收。

`test_nginx_cache_headers.py` 的 25 项全部通过，`test_routine_backup.py` 的 23 项中 22 项通过、1 项在非 root 测试环境跳过。独立只读复核确认 Nginx 运行规则只有注释变化。

## 前端指纹与备份组合门禁

前端候选的 `?site-asset` 静态导入走构建产物。已在生产渲染配置上用 `/_next/static/media/` 夹具验证字体、国旗、图标和新旧 Logo 的 MIME、长缓存及共享目录直出。真实产物须从 `standalone` 中核对路径并汇入已有 `immutable-assets.py`，沿用同 URL 内容冲突拒绝和旧文件合并。正式域车图直接到 API；本地 Next 代理是 FE 单独验证的转发路径。

当前首方逻辑备份按表显式排除供应商和临时统计记录。`0049` 的 `media_content_versions` 外键指向 `media_assets`，未列入排除表，现有首方独立指纹列表未包含这张新表。媒体归档只保留原图。

用真实 `routine-backup.py` 打包本机一张合成图片，并从归档按原权限恢复后调用 BE 工作树的真实存储实现。原图能按登记摘要读取。重建之前，`thumb` 和 `card` 均返回 `MEDIA_NOT_FOUND`。执行既有生成和摘要流程后，这个合成样本的三种摘要与原登记逐一一致，三种版本读取均成功。证据在 `docs/private/ops-public-media-cache/originals-only-restore.json`。这次验证覆盖媒体文件归档与恢复，组合验收仍须在隔离恢复的数据库中对账登记行、跑有界重建或校验，并验证官网实际返回可用的 URL。若重建字节不同，由 BE 换发内容对应的新版本。

旧 API 的媒体路径只接受裸 UUID。完整回退时，已经打开的新页面里尚未缓存的版本化图片有可能暂时加载失败。回退验收应覆盖现用和存量页面、刷新与旧裸 UUID。保留指纹构建资源，并保持版本化 URL 与实际内容绑定。正式发布前还需核对已签组合版的迁移账本、可续跑的有界登记和同版官网、API、备份与恢复。生产按组合版本另行核准。

## 并发回退与浏览器缓存

隔离 Nginx 回归增至 26 项，全部通过。新增用例覆盖模板及生产渲染配置下的 `GET`、`HEAD` 和三种表示。过载时完整透传 `307 no-store`，Location 保留同一裸 UUID 及尺寸参数。裸链实际走 `X-Accel-Redirect`，继续返回 `private, no-cache` 和旧 ETag。常规版本请求继续返回原一年缓存头及 ETag。

用 BE 候选真实 Fastify 路由、文件读取和摘要、生成的 Nginx 配置及 Chrome 157 走本机 HTTPS/HTTP2。使用合成 WebP 与本地登记查询夹具。冷访新开浏览器上下文，复访保持同一上下文并经空白页正常导航。用浏览器资源传输数据和 Nginx 接收到的请求交叉核对。饱和档通过受控等待占满 12 个 API 响应槽，四个拒绝产生后释放等待。

| 场景 | 图片全部解码 | 实际媒体网络请求 | 无网络请求的图片 |
| --- | --- | --- | --- |
| 常规 12 张冷访 | 12/12 | 12，全部版本 URL 200 | 0/12 |
| 常规同档复访 | 12/12 | 0 | 12/12 |
| 强制饱和 16 张冷访 | 16/16 | 20，包括 12 个版本 URL 200、4 个 `307` 和随后的 4 个裸链 200 | 0/16 |
| 同 16 张首次复访 | 16/16 | 4，原先回退的版本 URL 在释放后全部 200 | 12/16 |
| 同 16 张再访 | 16/16 | 0 | 16/16 |

四个实际 `307` 的 Location 均保持原媒体身份和 `variant=card`，缓存头均为 `no-store`，随后裸链均为 `private, no-cache`。独立的非 Nginx 投递实例在占满 12 个槽时实测 `503 no-store`，释放后恢复一年缓存的 200。证据为 `docs/private/ops-public-media-cache/capacity-chrome.json`，内含所测 BE 源码摘要。结果适用于隔离样本和指定并发，组合版验收沿用同一口径。

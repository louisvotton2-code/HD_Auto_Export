# BE-CATALOG-REUSE 目录同请求版本复用

v2.0.15 减少了首页版本请求。20 并发前两波的内部版本查询从 56 次降到 41 次，第三波仍触及独立的每访客 120 次版本配额。生产固定窗口记录了 124–129 次内部版本请求。此轮复用已发布双范围接口，处理 `/cars/` 同一次服务端渲染对列表、总览及细分筛选的重复首读。

- 普通文档的列表与筛选共用首次同一目录、筛选版本和汇率。多个筛选消费投影校验各自实际响应。导航只读取列表时继续请求单范围。元信息和页面渲染共享当前文档的读取上下文，新的文档继续执行独立检查。
- 版本冲突重新取得当时的版本。配对响应校验同一美元汇率与取样时间。旧 API 在返回 400 时才回退到分别读取两个范围，共用原截止时间。目录按各自结果展示列表和筛选，整页缓存预检仍须两份证据。429 保留 `Retry-After`，服务失败按原方式降级。原公开 API、配额、缓存期限和下架校验保留。
- 按 v2.0.15 固定窗口的真实路由组成进行本机 Fastify 回放。合成访客的首次读取及额外模拟访问从 129 次降至 100 次，429 从 9 次降至 0。使用 mock 数据库，生产同口径结果以正式报告为准。

隔离浏览器对照中，普通、品牌、车型目录的发布版分别读 2、3、4 次版本，候选均只读一次。延后筛选导航保持单次目录版本读取。候选 Chrome 5 项和官网定向 92 项通过，包括旧端 400 后筛选检查延迟返回 503 时仍先发出车卡源查询，以及真实撤回详情 404。

# BE-CATALOG-LATE 列表撤回与内嵌详情复核

基线为 v2.0.13 `446b6170b436a270db78c6a24535d6fcb31f352a`。原 OPS 在该版本的受审树上用隔离数据库交叉验证，复现车辆在第二次列表快照读期间归档后仍出现在响应中。公开和受信 SSR 的内嵌详情也仍会因反复目录推进返回 503。v2.0.13 停在切流前，既有标签保留。

- 无游标列表重读后若目录再推进，在原回源额度和截止时间内复核最多 48 个已返回 ID。人工车和供应商车复用原列表可见性、搜索条件、价格及媒体投影。命中撤回、售出、换图或其他卡片变化即拒绝该次旧页，复核只读取本页车辆，不再执行总量或整页扫描。仍相同的列表只供本次使用，精确数量继续对应 `dataAsOf` 表示的列表读快照。
- 官网的同一内嵌详情请求遇到单纯目录推进后，在同一个最新只读快照复核真实内嵌投影。Pixel、SEO、配置、报告、图片、可见性和汇率参与校验。确认内容一致才按核验版本复用。目标内容改变沿用有界重读，已撤回详情返回 404。
- 官网内部详情显式协商一次性渲染。API 确认内嵌投影后，即使目录版本比官网的预读更新，只要汇率相同且内容有效即可渲染。跨版本渲染不生成共享 DTO 或整页缓存。
- 需要晚校验时，公开项目的可见性以最后一次核验的数据库快照为准。该快照之前提交的撤回不得出现在响应中。快照之后发生的事务由下一次读取反映。一次性列表的统计时间仍对应实际读取整页的快照。

定向覆盖 31 项缓存用例、42 项官网读取与内部连接用例，以及 PostgreSQL 中的第二快照归档、供应商投影和内嵌详情的 Pixel、换版、撤回。无需迁移。候选需通过原 OPS 隔离反例、独立审查、本地仓库门禁及 GitHub 必需检查，再由 OPS 执行同域名、同脚本和原资源保护下的生产复测。

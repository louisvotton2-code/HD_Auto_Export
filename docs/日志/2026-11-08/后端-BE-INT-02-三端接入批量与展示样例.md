## 已实现的契约与服务

- [车辆接口第9节](../../开发/车辆接口.md#9-be-int-02-三端接入增量)与 contracts 先交付，随后服务落码。新增 `POST /api/v1/admin/vehicles/bulk`，每批1–50个明确ID＋expectedVersion，允许 availability 或 archive。Cookie、可信Origin、幂等键必填；UUID大小写重复整批拒绝。
- 批量在同一事务内按规范化ID锁现存行，按输入顺序返回紧凑结果。不存在、版本冲突和演示库存限制逐条失败，不改失败/未选记录；SQL或审计等未知故障整批回滚。成功行的更新、审计和幂等结果同时提交。返回HTTP200仍须检查每行及汇总。
- 幂等固定员工＋`vehicle.bulk`＋key范围，整个请求含operation/顺序/版本参与hash，24小时精确重放不重复执行；同key异请求409。原结果不代表最新库存，失败项必须刷新并确认后使用新key，不能自动覆盖新版本。
- 新增 `GET /api/v1/admin/vehicle-filters?make=...`，含所有当前草稿（draft/published/archived、manual/demo）。品牌/动力为全库计数，make只筛车型；车型按品牌＋车型ID区分，显示最新修改记录的名称。只投影选项字段，不含内部资料，与公开已发布字典分离。
- 新增 `source.kind=demo`：创建后来源类型不可切换；未知库存、空核验时间、待询价；制造日期/首次登记/里程/所在地/VIN不得伪造。型号层参数可保留经核验的公开规格。单条和批量库存操作均拒绝demo，下架允许。
- demo仍需品牌/车型、封面与合法图片引用、当前原文版本的非空三语，允许pending/approved但不允许stale；公开所有文本reviewed=false，kind保留实际原文/机器来源。真实manual仍要求库存、所在地及三语approved，不因演示例外放宽。原文标记须匹配语言及原文字串，不能借pending例外伪装原文。
- 公开目录/数量/字典、首页配置/读取同步识别已发布demo；详情及媒体继续基于真实发布状态，下架立即撤销。首页沿用原GET/PUT端点和版本，不另造配置接口。
- 官网SSR只用既有公开HTTP，无员工Cookie/Authorization；相对图片路径经公开媒体代理或明确API origin解析，继承no-store。CORS与可信管理写入Origin未扩大，禁止用官网管理员代理或长期图片缓存绕过权限。

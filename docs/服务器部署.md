# HD Auto Export：纯静态构建与 Ubuntu 22 部署

最后更新：2026-10-24。适用本项目 P1.7 起的 Next 静态导出，服务器为 Ubuntu 22.04，可能已经安装 s-ui／Sing-box／Docker。本文为通用安装指南；P1.8 已按用户授权实际部署到 VPS 的空闲 TCP 80，s-ui 保留 TCP 443，详见 [实际 IP 部署记录](./VPS-IP部署记录.md)。不要在已部署服务器上重复首次安装步骤；新服务器的监听端口、安装方式和证书管理仍以第 2 节检查为准。

**可以与 VPN 共用这台 VPS，前提是网站使用的 TCP 端口没有被现有服务占用。** 静态文件由 Nginx 直接提供，计算在访问者浏览器完成，服务器不需要 Node、pnpm、PM2、网站 systemd 进程、数据库或反向代理。Node 只用于你本地开发电脑上的构建。[Next 静态导出文档](https://nextjs.org/docs/app/guides/static-exports)

这里的共用不涉及更换 VPN 协议、修改 VPN 入站、迁移 s-ui 面板或停止现有服务。s-ui 支持多种协议，面板、订阅、VPN 入站还可能分别监听不同端口；不能根据它的默认面板端口推断你的 80／443 是否空闲。[s-ui 项目说明](https://github.com/alireza0/s-ui)

## 1. 先确定选择哪条部署路径

| 服务器实际情况                                      | 本指南的路径                                                                   | 网站访问地址                       |
| --------------------------------------------------- | ------------------------------------------------------------------------------ | ---------------------------------- |
| TCP 80、443 都空闲                                  | A：标准 Nginx + HTTPS，推荐                                                    | `https://auto.example.com/`        |
| 已有宿主机 Nginx 占用 80／443                       | 检查现有站点，只增加独立域名站点；不要重装或覆盖主配置                         | 通常可用标准 HTTPS，取决于现有配置 |
| TCP 80 或 443 由 s-ui／Sing-box／其他进程或容器占用 | B：已确认空闲的 8088 试跑，再用 8443 HTTPS                                     | `https://auto.example.com:8443/`   |
| 只有 UDP 443 被 VPN 占用，TCP 443 空闲              | TCP 443 仍可给 HTTPS；80 也空闲则可走 A                                        | `https://auto.example.com/`        |
| 网站必须用标准 443，但 TCP 443 已被 VPN 占用        | 增加独立公网 IP 并按 IP 绑定，或使用另一台 VPS；也可后续按真实协议专门设计入口 | 另行设计后使用标准地址             |

**同一个 IP 换一个域名，并不能让两个独立进程同时绑定相同的 TCP 443。** SNI 分流也不是所有 VPN 协议都适用，不要直接照搬反向代理教程去替换现有入口。本模板只使用 TCP，不启用 QUIC／HTTP/3，不占 UDP 443。

下文占位值需要替换：

- `SERVER_IP`：VPS 公网 IPv4。
- `SSH_PORT`：你当前 SSH 的实际端口，不一定是 22。
- `USER`：可 SSH 登录、能使用 sudo 的用户名。
- `auto.example.com`：你拥有的实际域名；需要 A 记录指向 VPS。没有域名可先用 `http://SERVER_IP:8088/` 试跑。
- `you@example.com`：接收证书通知的真实邮箱。
- 8088／8443：仅为示例，必须先确认空闲；有冲突则选择其他端口，同步修改配置、访问地址、防火墙和构建域名。

域名先只设置 DNS 解析，不急于启用 CDN 代理。只有服务器 IPv6 确实可用、监听与防火墙均已配置时才增加 AAAA。本指南模板初始仅监听 IPv4。

## 2. 在服务器上做只读检查

保留当前 SSH 连接，新开一个终端登录，确认不会失去管理通道：

```sh
ssh -p SSH_PORT USER@SERVER_IP
lsb_release -ds
sudo ss -lntup
sudo ss -lntp '( sport = :80 or sport = :443 or sport = :8088 or sport = :8443 )'
sudo ss -lnup '( sport = :80 or sport = :443 or sport = :8088 or sport = :8443 )'
sudo sshd -T | awk '$1 == "port" { print }'
sudo systemctl is-active s-ui sing-box nginx docker
sudo ufw status verbose
```

`ss -lntp` 是 TCP，`ss -lnup` 是 UDP；查看本地地址、端口和进程名称。`0.0.0.0:443` 或 `*:443` 通常覆盖全部 IPv4 地址；`[::]:443` 还可能覆盖 IPv4，不能看见 IPv6 就认定 IPv4 空闲。某个 unit 显示 `inactive`／`unknown` 不一定代表没安装，实际可能使用其他服务名或容器。

如果装有 Docker，再查看容器发布的端口；容器映射不一定全部显示为 `ss` 中的独立 docker-proxy 进程：

```sh
if command -v docker >/dev/null 2>&1; then
  sudo docker ps --format 'table {{.Names}}\t{{.Ports}}'
fi
if command -v nginx >/dev/null 2>&1; then
  sudo nginx -t
  sudo nginx -T 2>/dev/null | awk '/listen |server_name / { print }'
fi
sudo systemctl show s-ui sing-box -p FragmentPath -p WorkingDirectory
```

还要检查 VPS 控制台的安全组／云防火墙；UFW 不是唯一一层。记录现有 SSH、面板、订阅和 VPN 的 TCP／UDP 端口，保留 s-ui 自带备份／导出和证书的安全副本。实际数据目录取决于安装方式，不套用网上目录，也不输出数据库、私钥、完整配置到聊天／公开日志。

**接下来不执行 `ufw reset`、`ufw enable`、停止 s-ui／Sing-box、清理 Docker 或改 VPN 入站。** 80／443 被非 Nginx 服务占用时选 B 即可继续，不需要先腾出端口。

## 3. 在本地电脑构建静态成品

以下在 Mac 项目目录执行，不是在 VPS 上执行。使用 Node.js 24 LTS 与项目锁定的 pnpm 11.25.0；已有环境不重复安装。项目命令与依赖见 [README](../README.md) 和 [开发进度](./开发进度.md)。

```sh
cd HD_Auto_Export
node --version
pnpm --version
pnpm install --frozen-lockfile
if [ ! -e .env.production ]; then
  cp .env.example .env.production
fi
```

命令只在 `.env.production` 不存在时创建；已有文件保留并编辑：

```dotenv
NEXT_PUBLIC_SITE_URL=https://auto.example.com
SITE_INDEXABLE=false
```

B 路径最终用 8443 时，origin 应为 `https://auto.example.com:8443`。仅用 IP 试跑可填 `http://SERVER_IP:8088` 且保持 `SITE_INDEXABLE=false`；切换正式域名和 HTTPS 后再重建。

只写 origin，不带 `/zh`、其他路径、查询参数或账号密码。确认正式开放搜索引擎后改 `SITE_INDEXABLE=true` 并重建。不要让 `.env.local`／`.env.production.local` 覆盖本次部署值。`out/` 中的内容都是公开文件，不在客户端环境变量中放私钥或访问令牌。

```sh
pnpm check
pnpm build
pnpm preview
```

`pnpm build` 生成整个 `out/`，并在构建时获取市场参考汇率快照。汇率数据日期在页面显示，服务器不后台更新汇率。更新快照需要本地重新构建并上传，用户手工调整汇率的能力保留。访问日期由浏览器初始化，清关年份的参考规则限制不会因静态部署自动扩展。

`pnpm preview` 启动本地静态预览（默认 3100），只在开发电脑验收，**不用在 VPS 运行**。确认七国、三语、动力切换、公式／说明、印章／水印、双币种与复制正常后按 Ctrl+C 停止。构建报错应先修复，不上传残缺目录。

## 4. 安装 Nginx：先避免自动抢占 80

Ubuntu 的 `apt install nginx` 通常自动启动 Nginx，默认站点监听 80。因此只有确认 TCP 80 空闲且尚未安装 Nginx 时，才直接安装：[Ubuntu 安装说明](https://ubuntu.com/tutorials/install-and-configure-nginx)

```sh
sudo apt update
sudo NEEDRESTART_MODE=l apt install nginx rsync
```

`NEEDRESTART_MODE=l` 让 needrestart 只列出可能需重启的服务，避免安装顺带自动重启现有服务。不要顺手执行全系统 `apt upgrade`。

如果 80 被 VPN 占用且尚未安装 Nginx，先在 Mac 用 scp 上传安装脚本（这一步不要求 VPS 已有 rsync）：

```sh
scp -P SSH_PORT deploy/install-nginx-without-start.sh USER@SERVER_IP:~/hd-auto-install-nginx.sh
```

在服务器执行：

```sh
sudo sh "$HOME/hd-auto-install-nginx.sh"
```

脚本仅用于首次安装：临时建立 `policy-rc.d` 禁止包安装脚本自动启动服务，安装 nginx／rsync 后移除自己创建的策略，并让新 Nginx 暂不开机启动。发现已有 Nginx、已有配置或任何已有 `policy-rc.d` 时会退出，**不覆盖它们**。已有策略时由服务器管理员在原策略内确认如何禁止安装时启动 Nginx，不能直接删除原文件。[Debian 服务启动策略](https://manpages.debian.org/bookworm/init-system-helpers/invoke-rc.d.8.en.html)

正常退出或安装失败时都会尝试清除本脚本的临时策略。若 SSH 异常断开、机器掉电等导致残留，先查看：

```sh
sudo sed -n '1,3p' /usr/sbin/policy-rc.d
```

**仅当它恰好是本脚本创建的以下三行**，才移除：

```text
#!/bin/sh
# hd-auto temporary no-autostart policy
exit 101
```

```sh
sudo rm /usr/sbin/policy-rc.d
```

有未完成包配置时，先配置下文的空闲端口站点、取消新装的默认 80 站点，再执行 `sudo dpkg --configure -a`，避免修复安装时又启动默认监听。

如果原先已有 Nginx，跳过 Nginx 安装，保留原有虚拟主机及启动方式，只增加本站独立配置。需要上传时可先检查 `command -v rsync`，确实缺少则仅执行 `sudo NEEDRESTART_MODE=l apt install rsync`。Nginx 若在 Docker 内，宿主机 `/etc/nginx` 不是它的生效配置，需按容器挂载位置配置；也可走 B 在宿主机空闲端口增加 Nginx，不重建现有容器。

## 5. 上传 out，建立可回滚目录

在服务器为当前 SSH 用户建立上传目录，站点最终仅供 Nginx 读取：

```sh
mkdir -p "$HOME/hd-auto-incoming"
sudo install -d -m 755 /srv/hd-auto /srv/hd-auto/releases
```

在 Mac 项目目录执行（`out/` 后的斜线表示上传目录内容）：

```sh
rsync -av --delete -e 'ssh -p SSH_PORT' out/ USER@SERVER_IP:~/hd-auto-incoming/
rsync -av -e 'ssh -p SSH_PORT' deploy/ USER@SERVER_IP:~/hd-auto-deploy/
```

`--delete` **只作用于本站专用 incoming 目录**，不指向 `/etc`、其他网站、s-ui 或当前在线版本。本地无 rsync 时可用 SFTP 上传整个 `out/` 内容到此目录，不能漏 `_next`、Logo、字体、导出的 `.txt` 等文件。

回到服务器，确认成品存在：

```sh
test -f "$HOME/hd-auto-incoming/zh/calculator/russia/index.html"
test -f "$HOME/hd-auto-incoming/404.html"
test -d "$HOME/hd-auto-incoming/_next/static"
```

任意检查失败先核对上传，不继续发布。然后：

```sh
hd_release=$(date -u +%Y%m%d%H%M%S)
sudo install -d -m 755 "/srv/hd-auto/releases/$hd_release"
sudo rsync -a "$HOME/hd-auto-incoming/" "/srv/hd-auto/releases/$hd_release/"
```

为避免更新时已打开页面找不到尚未加载的旧哈希资源，将上一版的哈希静态文件补进新版本，只补缺少的文件：

```sh
if [ -d /srv/hd-auto/current/_next/static ]; then
  sudo rsync -a --ignore-existing /srv/hd-auto/current/_next/static/ "/srv/hd-auto/releases/$hd_release/_next/static/"
fi
sudo chown -R root:root "/srv/hd-auto/releases/$hd_release"
sudo find "/srv/hd-auto/releases/$hd_release" -type d -exec chmod 755 {} +
sudo find "/srv/hd-auto/releases/$hd_release" -type f -exec chmod 644 {} +
```

不把源码、`.env.production`、数据库或证书放进 release。首次发布／后续更新均使用符号链接替换：

```sh
readlink -f /srv/hd-auto/current
sudo ln -s "/srv/hd-auto/releases/$hd_release" /srv/hd-auto/current-next
sudo mv -Tf /srv/hd-auto/current-next /srv/hd-auto/current
```

首次无 `current` 时第一行无输出正常；以后记下旧路径用于回滚。`current-next` 如因中断已存在，先用 `readlink` 确认它是本站临时链接，再只移除该链接重试，不对未知目录递归删除。Nginx 读取 `current`，纯内容更新不需重启 Nginx。

## 6. 配置 Nginx：A 和 B 二选一

首次修改前备份 Nginx，备份可能含敏感站点配置，只保存在 root 可读目录：

```sh
hd_nginx_backup="/root/hd-auto-nginx-before-$(date -u +%Y%m%d%H%M%S).tar.gz"
sudo tar -czf "$hd_nginx_backup" /etc/nginx
sudo chmod 600 "$hd_nginx_backup"
sudo install -d /etc/nginx/snippets
sudo cp "$HOME/hd-auto-deploy/hd-auto-static.conf" /etc/nginx/snippets/hd-auto-static.conf
```

复制前确认 `/etc/nginx/sites-available/hd-auto` 不是其他站点；已有本站配置先单独备份。

### A：80／443 空闲，或由现有 Nginx 统一管理

```sh
sudo cp "$HOME/hd-auto-deploy/nginx.conf" /etc/nginx/sites-available/hd-auto
sudo nano /etc/nginx/sites-available/hd-auto
```

把 `auto.example.com` 全部替换为真实域名。仅首次启用时建链接：

```sh
sudo ln -s /etc/nginx/sites-available/hd-auto /etc/nginx/sites-enabled/hd-auto
sudo install -d -m 755 /var/www/hd-auto-acme/.well-known/acme-challenge
sudo nginx -t
```

Nginx 已运行时执行 `sudo systemctl reload nginx`；刚安装尚未启动时执行 `sudo systemctl enable --now nginx`。语法失败先修复，不重载。已有 Nginx 的域名和监听冲突需要先处理本站配置，不能覆盖原站点。

### B：80／443 被 VPN 或其他独立进程占用

确认 TCP 8088 空闲后：

```sh
sudo cp "$HOME/hd-auto-deploy/nginx-alt-http.conf" /etc/nginx/sites-available/hd-auto
sudo nano /etc/nginx/sites-available/hd-auto
```

替换域名／端口。无域名时，单一新站点也可先通过 `http://SERVER_IP:8088/zh/calculator/russia/` 访问。已有宿主机 Nginx 时保留所有其他站点。

**仅在本轮刚首次安装 Nginx、确认它带来的 Ubuntu 默认站点监听冲突的 80 时**，检查：

```sh
ls -l /etc/nginx/sites-enabled/default
```

只有该链接指向此次新装的 `/etc/nginx/sites-available/default`，且不是原有业务站点时，取消该启用链接，保留配置文件：

```sh
sudo unlink /etc/nginx/sites-enabled/default
```

然后只启用备用站点：

```sh
sudo ln -s /etc/nginx/sites-available/hd-auto /etc/nginx/sites-enabled/hd-auto
sudo nginx -t
sudo nginx -T 2>/dev/null | awk '/listen |server_name / { print }'
```

确认新装的 Nginx 最终只监听选定空闲端口，没有其他 include 再监听 80／443。`nginx -t` 检查语法和文件引用，不保证端口可绑定，仍需结合 `ss`。

已运行则 `sudo systemctl reload nginx`，刚安装未运行则 `sudo systemctl enable --now nginx`。若出现 `address already in use`，重新查进程／容器，换空闲端口，不停止 VPN。8088 HTTP 只用于试跑，公网浏览器剪贴板可能受限，正式继续第 8 节配置 HTTPS。

### 公共静态处理

完整配置见 [deploy/hd-auto-static.conf](../deploy/hd-auto-static.conf)，核心是：

```nginx
root /srv/hd-auto/current;
index index.html;
location / {
    try_files $uri $uri/ =404;
}
```

模板还包含独立日志、真实 404、缓存策略和旧 API 明确 404。`trailingSlash` 导出为各路由的 `index.html`，不要改成所有地址返回 `/index.html` 的 SPA 回退，否则未知页面错误变成 200。HTML、导出的 RSC `.txt` 与非哈希资源重新验证，只有 `/_next/static/` 的哈希资源长期 immutable。[Nginx try_files](https://nginx.org/en/docs/http/ngx_http_core_module.html#try_files)、[响应头说明](https://nginx.org/en/docs/http/ngx_http_headers_module.html)

## 7. 增量开放新站端口并试跑

在 VPS 控制台安全组和现有防火墙放行选定 **TCP** 端口。UFW 已 active 时才增量加规则；不直接复制两组：

```sh
# 路径 A，UFW 已启用时：
sudo ufw allow 80/tcp comment 'HD Auto HTTP ACME'
sudo ufw allow 443/tcp comment 'HD Auto HTTPS'
```

```sh
# 路径 B，UFW 已启用且端口已确认空闲时：
sudo ufw allow 8088/tcp comment 'HD Auto trial'
sudo ufw allow 8443/tcp comment 'HD Auto HTTPS alternate'
```

UFW inactive 时不为本次网站执行 `ufw enable`；现有 nftables／iptables 和云安全组保持原管理方式。不重置、替换整套规则或遗漏现有 SSH／VPN 端口；网站无需新增 UDP 放行。

在服务器验证，A 用 80，B 换成 8088：

```sh
curl -I -H 'Host: auto.example.com' http://127.0.0.1:80/zh/calculator/russia/
curl -I -H 'Host: auto.example.com' http://127.0.0.1:80/brand/hd-auto-logo.webp
curl -I -H 'Host: auto.example.com' http://127.0.0.1:80/this-page-does-not-exist/
curl -i -X POST -H 'Host: auto.example.com' http://127.0.0.1:80/api/v1/calculations
```

前两项应 200，后两项 404。静态站不提供 `/api/health`、HTTP 计算接口和 `/_next/image`；公共计算函数仍在源码中，未来车辆模块可直接调用。

在电脑浏览器打开公网地址，同时确认 VPN、面板和订阅仍正常。本地通而公网不通时先查安全组、UFW、DNS／AAAA 和端口，不改 VPN 排障。

## 8. HTTPS：标准 443 和备用 8443

证书属于**域名**而非端口，有效域名证书可用于 443 或 8443。沿用已有证书原续期管理，不能复制面板证书后忘记续期。已有 Certbot／acme.sh／面板时先核对，不安装第二套去接管同一证书。如果已有 Certbot，先运行 `sudo certbot certificates`；下文 `--cert-name` 必须选本站未被其他用途占用的名称。若换了名称，两份 HTTPS 模板的证书目录也要使用实际输出路径。

### A：80 可达，用 webroot 自动签发／续期

确认域名正确解析、80 上本站可公网访问。安装 Certbot，不需要 Nginx 插件：

```sh
sudo NEEDRESTART_MODE=l apt install certbot
sudo certbot certonly --webroot \
  -w /var/www/hd-auto-acme \
  --cert-name auto.example.com \
  -d auto.example.com \
  --email you@example.com --agree-tos
sudo certbot certificates
```

核对输出的真实证书路径，再替换 HTTPS 模板中的域名、跳转地址和两条证书路径。本流程使用本站独立证书名称，不能覆盖现有 VPN 的证书条目。

```sh
sudo cp /etc/nginx/sites-available/hd-auto /etc/nginx/sites-available/hd-auto.before-https
sudo cp "$HOME/hd-auto-deploy/nginx-https.conf" /etc/nginx/sites-available/hd-auto
sudo nano /etc/nginx/sites-available/hd-auto
sudo nginx -t
sudo systemctl reload nginx
```

签发前不启用引用不存在证书的配置。模板只对本站跳 HTTPS 并保留 ACME 文件路径，不用 `certbot --standalone` 抢端口。HTTP-01 固定验证公网 80，不能换 8088。[Let’s Encrypt 验证方式](https://letsencrypt.org/docs/challenge-types/)

如果 443 空闲但 80 被 VPN 占用，可按 B 的 DNS-01 取得证书，单独建立 `listen 443 ssl` 站点，不复制 A 中监听 80 的块。反过来，80 空闲但 443 占用时仍可用 webroot 签证书，HTTPS 用 8443。

### B：80／443 不动，DNS-01 签发后用 8443

确认 TCP 8443 空闲且已放行。DNS-01 通过域名 TXT 记录验证，不要求网站占用 80／443。

DNS 服务商未知时，可先手动签发验证流程：

```sh
sudo NEEDRESTART_MODE=l apt install certbot
sudo certbot certonly --manual --preferred-challenges dns \
  --cert-name auto.example.com \
  -d auto.example.com \
  --email you@example.com --agree-tos
```

按提示，在**实际管理域名 DNS 的服务商**添加 `_acme-challenge.auto.example.com` 的 TXT 值，等权威 DNS 生效后再按回车。不能复用示例 token，也不覆盖其他仍在使用的 ACME 记录。

**纯手动 DNS 不会自动续期。** 正式使用前建议改成该 DNS 服务商的 Certbot DNS 插件，用最小权限 API 凭据自动更新 TXT；服务商未确认时不能套 Cloudflare 等其他命令。凭据只保存服务器受限文件，不进入 `out/` 或 Git。暂用手动方式则到期前重复同一签发命令、重载 Nginx，不能把定时 `certbot renew` 当成自动续期已实现。[Certbot DNS 插件和手动续期](https://eff-certbot.readthedocs.io/en/stable/using.html#manual)

签发成功后，替换备用 HTTPS 模板中的域名／证书路径：

```sh
sudo certbot certificates
sudo cp /etc/nginx/sites-available/hd-auto /etc/nginx/sites-available/hd-auto.before-https
sudo cp "$HOME/hd-auto-deploy/nginx-alt-https.conf" /etc/nginx/sites-available/hd-auto
sudo nano /etc/nginx/sites-available/hd-auto
sudo nginx -t
sudo systemctl reload nginx
```

访问 `https://auto.example.com:8443/zh/calculator/russia/`，端口不可省略。配置替换 8088 试跑站点，不影响 80／443。用 IP 访问会与域名证书不匹配，正式需用域名。

### 自动续期后重载 Nginx

webroot 或 DNS API 自动方式可增加 deploy hook，证书实际续期成功后检查并重载：

```sh
sudo install -d -m 755 /etc/letsencrypt/renewal-hooks/deploy
sudo nano /etc/letsencrypt/renewal-hooks/deploy/hd-auto-reload-nginx.sh
```

写入以下内容；不要覆盖已有同名文件，已有合适重载 hook 时复用：

```sh
#!/bin/sh
set -eu
/usr/sbin/nginx -t
/usr/bin/systemctl reload nginx
```

```sh
sudo chmod 755 /etc/letsencrypt/renewal-hooks/deploy/hd-auto-reload-nginx.sh
sudo certbot renew --cert-name auto.example.com --dry-run
sudo systemctl list-timers --all | awk '/certbot/ { print }'
```

确认已有 apt Certbot 定时任务；若 apt 安装的 `certbot.timer` 存在但未启用，再 `sudo systemctl enable --now certbot.timer`，不另加重复 cron。`--dry-run` 检验自动验证流程，默认不一定运行 deploy hook，首次可单独执行这个 hook 检查重载。手动 DNS 不适用自动验收，需先接好认证插件／hook。[Certbot 续期与 deploy hook](https://eff-certbot.readthedocs.io/en/stable/using.html#renewing-certificates)

# 员工管理后台任务书

2026-11-08｜工作流 AD｜状态：AD-00 待开始；后台业务等待 BE 契约与服务。

先按 [接手导航](../README.md) 完成公共入门，再读 [车辆接口](../开发/车辆接口.md)。管理后台是员工操作界面；持久化、鉴权与发布服务由后端负责，不另外搭建一套后端。

## 范围和路径

在独立 `apps/admin/`（`@hd/admin`）建立 React/Vite 应用，拥有自己的路由、布局、依赖与构建／测试配置；不挂载在官网 Next 路由或 layout 下，也不复制官网大首页。当前只有 package 预留，没有可启动的后台工程。

后台通过 HTTP 消费 `apps/api`，安全共享类型与 schema 来自 `@hd/contracts`；不 import 官网或 API 的源码。员工后台默认中文，语义 key 与内容三语发布状态分开；不得因后台界面是中文就误报车辆三语内容就绪。

第一期只做车辆管理与首页车源配置，不做 CRM、聊天、订单、支付、复杂 BI、AI 或爬虫。登录复用 BE 选定的鉴权能力；隐藏按钮不等于完成权限控制。

## AD-00：独立后台工程（G0 工程基础）

1. 建立 React/Vite、TypeScript、独立路由和简洁布局，声明本应用依赖，提供独立启动、构建和适用的检查命令。根脚本、统一锁文件和 CI 改动交给工程集成人。
2. 与 BE／OPS 明确开发代理、部署入口／base path、API 地址和登录会话约定；后台路径由部署方案确定，不沿用旧 `/zh/admin/` 作为官网子路由。浏览器不得包含服务密钥。
3. 先提供基本应用壳及 API 客户端位置。契约尚未落码时只完成工程基础；使用 fixtures 必须遵循后续统一契约并标记待联调，不能声称已登录或持久化。
4. 交付可复现工程与实际检查记录，由独立 review 核对依赖边界。工程可运行后再实施 AD-01。

## AD-01：最小操作闭环（G1）

依赖：AD-00、员工身份、草稿／发布／媒体契约和可运行的 BE 环境。可以先用同契约 fixtures 实现界面，注明尚未联调；自测后先交独立审查。

| 页面 | 必需行为 |
| --- | --- |
| 登录 | 真实登录、错误提示、退出、会话过期回登录；不开放公众注册 |
| 车辆列表 | 显示稳定车号、品牌车型、草稿／发布、库存状态、最近修改与核验；新建／编辑入口 |
| 车辆编辑 | 分组录入基础事实、公开价格、内部信息、图片和三语内容；保存草稿与发布分开的按钮 |
| 图片管理 | 多图上传状态、失败重试、排序、封面、删除限制；未完成图片不能假装可发布 |
| 发布检查 | 展示缺项、真实来源／价格范围、图片与语言准备情况；发布成功后给正式官网预览入口 |
| 首页配置 | 两个现有车轨区块的标题、车辆选择和排序；不能选择草稿或已售车 |

日期输入区分年款、生产日期和首次登记，允许按真实精度保存。展示价格默认 USD 录入但必须明确币种；内部成本不出现在官网预览。缺报价可选待询价，不能自动填 0。

验收：员工可用界面完成一辆车全链路；刷新后数据库数据仍在；草稿预览不会公开泄漏；保存没有隐式发布；官网预览与实际 public DTO 一致。

## AD-02：可运营完善（G2）

- 编辑已发布车辆时清楚标注“未发布修改”，并区分当前公开版本；提供预览和再次发布，不让员工以为保存就是上线。
- 在售／预订／已售／待核验与发布状态分别展示；售出／下架有明确影响说明，成功后官网同步，失败不能提前显示完成。
- 版本冲突 409 时保留本地输入，提示重新载入并比较，不能自动覆盖他人改动。重复点击、断网重试避免重复创建。
- 表单字段错误定位、未保存离开提示、长文本／俄文／移动端基本操作可用。
- 图片权限／超限／格式／上传失败可理解；已发布图不能直接硬删，显示原因。
- 提供基础操作记录查看，至少能解释最近谁发布／下架。帐号管理大页面不是首期必需，由管理员受控初始化即可。
- 协助用户录入并核对首批 10–20 辆真实车；需要用户提供车辆事实和有权使用的图片，开发方不虚构库存。

## 职责与本轮范围

AD 负责独立 `apps/admin` React/Vite 应用的员工界面、路由、表单、交互及应用检查。API 的持久化、权限、发布和审计由 BE 实现，AD 通过 HTTP 消费，不搭建第二套后端、不跨应用导入内部源码。

本次用户要求分步建设，并将客户资料／标注及员工 AI 对话纳入未来后台。先实现车辆基础与运营闭环，后续客户工作台和 AI 按各自契约推进。旧路线图“不另建 CRM”的表述不再作为排除本次规划的依据；PM 需同步范围，具体设计见后台架构。后台默认中文，车辆三语内容有独立版本与审核状态。

代码核对结果：BE-01/02 已有本地服务和契约；不能继续把后台任务写成“等待接口从零建立”。真实 FE/AD 联调、生产部署和内容验收仍分别登记。

## AD-00：独立后台工程

建立 React/Vite、TypeScript、React Router、应用布局和共享 HTTP 层；声明独立依赖，提供启动、构建和检查。使用 `/admin/` base、3318 开发端口和 `/api` 同源代理；部署深链接回退、会话和代理由 OPS 联合验证。根脚本与统一锁文件由当轮集成人串行更新。

验收为可复现运行与构建、路径刷新有效、浏览器无密钥和跨应用源码依赖。测试样例不能作为真实会话或持久化证明。

## AD-01a：登录与草稿管理

| 页面／交互 | 必需行为 |
| --- | --- |
| 登录／退出 | 真实员工登录，错误可理解，401 要求重新登录，不开放公众注册；同账号恢复和换账号隔离遵循架构 |
| 车辆列表 | 稳定车号、品牌车型、发布与库存状态分别显示，修改／核验时间、分页、筛选与新建／编辑入口 |
| 新建／编辑 | 基础事实、公开价格、内部资料和原文标题；保留未编辑字段；保存草稿与发布语义分开 |
| 失败恢复 | 创建幂等重试；保存带版本；409 保留输入并比较当前版本；未保存离开提示；服务错误不能伪装空数据 |

AD-01a 切片保留未编辑图片、三语审核和发布数据；AD-01b 在其上补齐可操作界面。日期按真实精度保存，缺制造日期／里程为 null；待询价没有金额，不自动填 0；金额与币种独立明确。内部信息不得出现在公开预览。

验收：在隔离本地 API／数据库完成登录→新建→编辑→刷新仍存在→退出；补查未登录、无权限、断网与冲突。若仅采用契约 fixtures 或请求拦截验证界面，日志必须标明尚未完成真实 API 联调。

## AD-01b：图片、审核与发布闭环

依赖 AD-00／01a 及现有媒体／发布服务。本轮用户明确先完成后台并核验公开接口，不接官网；正式官网联调单独留给 FE-01。首页配置界面不在本轮单车闭环范围。

| 页面／交互 | 必需行为 |
| --- | --- |
| 图片 | 申请上传→二进制→完成→绑定草稿；状态、失败恢复、排序与封面；显示来源／许可和删除限制 |
| 三语 | 原文与中英俄译文、来源及审核状态；原文改变后复核，不把自动译文标成人工已审核 |
| 发布检查 | 定位服务端缺项；保存与发布分开；明确当前线上版本与未发布修改；成功后提供正式官网入口 |
| 库存与下架 | 库存核验与发布状态分开；已售／下架影响说明；成功后公开视图即时变化 |
| 首页配置 | 两组标题、可展示车辆选择与顺序；版本冲突可恢复，不能选择草稿或已售车 |

验收：员工从界面完成单车录入、图片、三语、核验、发布、公开读取、再编辑不隐式发布、已售和下架全链路；草稿与内部资料不公开。联系草稿由 FE 验证，开发测试不向真实客户发消息。

## AD-02：可运营完善

在已完成的版本／幂等保护上完善对比、上传恢复、错误定位、操作记录及手机／长文本体验。审计查询若尚无接口，先向 BE 提出最小可检查契约，不用 UI 编造“最近操作人”。管理员账号首期仍使用受控工具，无需先开发大页面。

协助用户录入并核对首批 10–20 辆真实车；真实事实和有权使用的图片由用户提供。使用合成数据开发不阻塞，真实内容验收另记。

## 后续客户与 AI 任务

AD-CRM-01 管理客户资料、标签／标注、跟进和车辆关联；AD-AI-01 在后台提供员工只读查车对话；AD-AI-02 视实际需求接入客户辅助与草稿建议。实体关系、数据范围、模型工具权限与验收标准见[后台架构的阶段章节](../开发/后台架构.md#6-分阶段实施与协作)，不在本任务书重复维护协议。

客户与 AI 都需新增 BE 契约：客户身份／负责人／数据范围不能只靠前端过滤；首版 AI 仅能读取公开车源，客户数据不默认加入对话。两者的独立能力可在依赖就绪后并行；没有接口时先完成具体契约协作清单，不假设已经持久化或调用模型。

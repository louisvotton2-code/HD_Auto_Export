## 职责

在 `apps/api/`（`@hd/api`）建立独立 TypeScript API，维护车辆业务、员工鉴权、媒体与 PostgreSQL 迁移；在 `packages/contracts/`（`@hd/contracts`）维护公共 DTO、运行时 schema 和 fixtures。本轮选定 Node.js 24.19.0、Fastify 5、PostgreSQL 18、Drizzle、Better Auth 和 Zod 4；版本与理由见后端架构，精确依赖由清单和锁文件固定，实际兼容性须由 BE-01 验证。

官网与后台通过 HTTP 消费 API，不导入 API 业务代码；不得在官网另建一套库存后端。各应用独立声明依赖，API 自己的构建／测试配置由 BE 负责；共享锁文件、workspace、根脚本和 CI 由当轮工程集成人统一修改。基础共享包不得带数据库、密钥、网络副作用或 React。

- 维护后端架构说明和仓库内后端工作入口，链接现有接口、角色任务与验证流程，不复制第二套契约。
- 明确本轮 BE-01/02 和后续运营、来源、翻译、AI 阶段；技术选定、代码实现、自测、独立审查、消费者联调和生产部署分别记录。

完成证据：规范元数据与链接可用；架构和实际实现无冲突；独立审查与对应日志已登记。

## G0 / BE-01：公共契约、独立 API、鉴权与数据库

1. 核对迁移后的共同基线和既有改动；当前官网已在 `apps/web/`，不能从旧 HEAD 建立第二套单 Next 后端。先与集成人确认可复现版本，保护其他角色文件。
2. 先把车辆契约草案落实到 `packages/contracts/` 的浏览器安全 DTO、运行时校验 schema、固定样例及明确公共出口，按约定生成 OpenAPI 等可检查资料。由 FE／AD 核对消费方式；不复制三套手写类型。声明版本与兼容性，破坏变更同步所有消费者。
3. 在 `apps/api/` 建立可独立安装依赖、启动、构建与测试的服务工程，落实公开／管理员接口边界、配置校验、健康端点、错误格式和日志。共享根脚本与 CI 通过集成人接入，不修改官网 Next 运行模式。
4. 建 PostgreSQL 隔离的本地开发实例、迁移与测试库；核验并锁定数据库和工具版本，避免 `latest`。明确连接池预算、初始化和迁移命令；服务构建不要求生产数据库在线。库和真实环境文件不提交。
5. 员工登录无开放注册，采用成熟鉴权方案；验证管理员初始化、编辑员权限、禁用后会话失效、Cookie／CSRF／Origin 校验、登录限流与管理 no-store。BE 维护身份与权限真相，AD 仅消费接口。
6. 联同 AD／FE／OPS 确认本地端口、公开 API 前缀、登录回调、同源代理或受限 CORS、Cookie 域与路径、服务端 API 地址及无密钥环境示例。独立部署不能依赖开发机恰好同源；SSR 只拿公开白名单 DTO。
7. 提供服务和契约检查命令、隔离 fixtures、运行文档及实际测试证据；将客户端误引数据库／密钥、跨应用源码导入纳入边界检查。与独立审查者验证后再进入消费者联调。

BE-01 完成证据：API 生产成品可独立启动；契约可被两端安全消费；测试库迁移及身份／权限检查通过；端口、代理和接口样例清楚。官网运行时由 FE-01 完成，后台工程由 AD-00 完成；工程目录迁移本身不代表整个 G0 完成。

## BE-02：一辆车闭环（G1）

- 实现草稿、不可变发布版本、库存状态、稳定车号、媒体记录、审计和首页分组的最小持久化；已发布车编辑保留旧公开快照，发布与下架事务及版本冲突行为按契约执行。
- 提供所需 public/admin 接口和员工身份接口，公开 DTO 白名单过滤成本／内部资料；服务端验证是最终规则。
- 本地媒体适配器用于开发；接口保持可切换到对象存储。上传内容校验和私有草稿预览不可因本地阶段省略。
- 与 AD／FE 完成一辆真实测试车闭环：创建草稿不可公开→图片准备好→发布→无需重建的新详情→首页→咨询草稿→库存更新／下架。
- G1 公开精选数据可先 no-store，保证可见性语义后再优化缓存。

验收：未登录／越权请求被拒绝；公开 JSON、SSR HTML/RSC 均无内部成本；发布失败不半上线；新车可访问；草稿／下架返回 404；冲突 409 不覆盖；金额／日期不补假数据。

## BE-03：运营完整性（G2）

- 扩充 BE-02 已建立的发布、库存、审计和首页排序能力，验证多人运营与失败恢复；不把编辑保留旧快照、并发版本和下架一致性推迟到生产阶段。
- 接入生产对象存储适配器，处理文件完成校验、访问权限、临时对象清理、原图与展示图、已引用图片保护。
- 按查询建立必要索引和连接池预算；增加精选缓存时同步失效，测试停售／下架不会短期继续作为可售车曝光。
- 提供 liveness（进程存活）与 readiness（必要依赖可用）端点，返回不含敏感信息；第三方非核心依赖故障不使精选站点整体判死。
- 与 OPS 验证迁移、数据库与图片恢复、备份读取权限及应用回滚兼容性；不用生产数据跑破坏性测试。

## BE-04：一家第三方（G3）

先完成供应商样本验证和计费／许可决策，再以适配器接入；禁止同时把三家都做进首期。密钥仅服务端，公共 API 不成为任意 URL 透传代理。

1. 来源三元组映射与公开稳定 ID；列表／详情／筛选字典映射到公共契约；保存必要原始证据的范围按许可。
2. 查询缓存键规范化，分页与排序语义正确；并发相同查询合并、超时、有限重试、限流和配额预算。
3. 分别计请求数、返回记录数、详情调用数，按实际套餐计算；列表不逐车补请求完整详情。
4. 处理上游限流／断开／撤车／图片失效／订阅到期；不可用不是空列表，过期缓存只在允许范围显示。
5. 外部记录不得覆盖人工精选事实；若人工精选引用外部挂牌，记录关联和许可条件，不能手工复制后消除删除义务。
6. 不把返回的 `firstRegistration` 作为制造日期，不把供应商出口标志作为已审核资格。

来源层与人工事实隔离、同步缺失处理、保留和删除传播见[后端架构](../开发/后端架构.md#4-后续来源接入与自动翻译)。这部分是后续计划，测试 fixtures 不能作为真实接入成功证据。

## BE-INGEST-01：自采集与标准化入库（后续）

- 依赖 BE-04 建立的来源边界，先确定一个允许使用的来源及抓取范围；不建设任意网站通用采集平台。
- 采集、文件导入和供应商 API 复用来源身份、校验、幂等入库与异常处理；保留必要的来源证据与解析版本，不覆盖人工精选事实。
- 验证重复抓取、解析失败、不完整同步、明确撤车、限流、任务重跑及保留期删除；来源条件只阻塞实际适配器，不阻塞本地基础建设。

## BE-I18N-01：入库后自动翻译（后续）

- 原文入库后由 worker 翻译展示文本，按原文 hash、目标语言和翻译配置版本避免重复；写回核对原文及人工编辑版本，过时任务不能覆盖新内容。
- 人工精选的三语内容仍由员工审核后发布；外部市场车源可自动展示机器译文并明确标记，失败和缺失不可伪装成已翻译。
- 目标语言必需标题未就绪时不进入该语言目录，描述可省略并提示；列表、数量和筛选条件一致。公开事实与译文版本对应，数值更新且文字未变时不重译，已售下架不等待翻译。
- 验证重试、原文变化、人工修改、源数据删除及衍生译文清理。任务队列采用 pg-boss，执行本任务时核验并锁定版本；翻译供应商届时验证，当前不调用翻译服务。

## BE-AI-01：公开数据只读工具（后续）

- 复用公开查询提供查车、公开详情、来源时间与缺项；无论调用者是否为员工，结果都限于公开 DTO。
- 首交付提供 HTTP 接口和 OpenAPI 通用工具定义，MCP 留待实际消费者需要时适配。
- 不向模型提供数据库连接或任意 SQL；不开放草稿、内部成本、员工资料、发布和真实消息能力。工具入口与现有公共契约保持一致。
- 验证参数限制、字段白名单、下架后不可读、来源内容不能改变工具权限，以及查询日志和调用预算。测算、报价和对客 AI 另按对应阶段执行。

## 验证与交付

选择能发现真实错误的服务测试：身份和角色、内部字段泄漏、并发版本、发布事务、日期／金额／缺失值、分页边界、缓存失效、上游异常；同时参与 G1 实际浏览器联调。契约变动按消费者扩大回归；未触及的官网样式不为凑数量全测。计算核心仍位于官网，有真实第二消费者且另分配提取任务时才移入共享包。

把 migrations、schema/OpenAPI、无密钥环境示例、样例、运行命令和测试证据交接；真实 `.env`、密钥、数据库和日志留在私有环境。未购买／未实测的外部接口不得写“接入成功”。自测后按 [测试与审查](测试与审查.md) 交独立 review、QA 集成及 PM 证据核验；作者自评不能替代审查。

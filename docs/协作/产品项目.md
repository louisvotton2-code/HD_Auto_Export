## 职责

- 将用户决定写入路线图，维护范围、优先级、验收条件及外部依赖；不另建重复总计划。
- 按前端、后端、后台、运维、独立 review 和 QA 的真实交付核对代码、版本和环境，汇总 [当前进度](../开发进度.md)。未看到证据的进展标为待核验。
- 维护接手导航与职责边界，处理跨角色接口／共享文件冲突。技术变更由对应负责人实施，PM 不在文档中提前宣布完成。
- 按用户询问复核进度；本角色文件不创建后台自动巡检，也不承诺自动读到其他对话的未共享信息。

## PM-01：共同基线与阶段验收

1. 确认当前未提交前端改动已被保护，按用户 Git 授权建立可供各端复现的共同基线。未准备好时协调串行工作。
2. 为共享根脚本、workspace、锁文件和 CI 指定每轮唯一工程集成人；各应用自行声明依赖，不能多端并发安装或互改应用配置。跟踪 FE-00 的官网迁移、BE-01 的 contracts／独立 API／鉴权／数据库、AD-00 的 React/Vite 工程，以及 FE-01 的官网运行时；确认各端获得同版本契约和可复现启动方式。目录预留不算工程完成，工程迁移不算整个 G0 完成。
3. 以 G1 单车流程实际联调作为阶段完成证据；真实车辆资料未给时允许标记清楚的测试数据开发，不能据此登记真实车源验收完成。
4. 按 [测试与审查](测试与审查.md) 分别核对实现者自测、独立 review、QA 集成／缺陷复测和阶段门槛；P0/P1 阻塞验收，P2 有负责人、处理计划和明确接受依据。用户承担业务／视觉验收，PM 不能用“文档已写”替代用户确认。
5. 区分工程完成、功能完成、待审查、待联调、待验收、已验收与部署成功；未执行的检查留在角色摘要。授权发布由 OPS 执行并记录产物、环境、冒烟和回滚，不把 Git 推送当上线。

- 按用户询问复核进度；本角色文件不创建后台自动巡检，也不承诺自动读到其他对话的未共享信息。

## 项目助理PA执行边界

项目助理是用户可持续委派的执行角色，由PM明确每次范围、输入和交付。可负责公开来源调研、资料整理、事实与图片出处清单、按现行管理API录入、保存本地素材及本轮日志；本轮任务见[PA-DATA-01分工](../日志/2026-11-08/产品项目-PM-INT-03-交互还原与可迁移本地服务.md#分工与依赖)。接手先按统一导航读取相关契约，维护该任务的实际数量、失败、来源和下一依赖，不另造总进度。

不修改BE契约、审批规则或库存事实，不直接写数据库、替代人工审核或把第三方挂牌当自有现货。没有依据的字段保持缺失或待核验，不把Agent整理说成人审，不冒称图片商用许可或出口资格。公开文案与内部事实按[当前产品约定](../../product/路线图.md#当前公开展示与交互)区分；最新授权下架HD6／7和整理8条三语文案，不能沿用早期“不动HD6／7”的分派阻止该操作，也不扩大到删除其他资料。正常公开资料可按已授权范围用于本地联调；凭据、原始素材和导入脚本进入忽略目录，公开日志保留必要来源与验证摘要。涉及新增业务能力、权限、生产公开使用或删除别人的资料时交PM协调，不以“杂务”扩大授权。

3. 以 G1 单车流程实际联调作为阶段完成证据；真实车辆资料未给时允许标记清楚的测试数据开发，不能据此登记真实车源验收完成。
4. 按 [测试与审查](测试与审查.md) 分别核对实现者自测、独立 review、QA 集成／缺陷复测和阶段门槛；P0/P1 阻塞验收，P2 有负责人、处理计划和明确接受依据。用户承担业务／视觉验收，PM 不能用“文档已写”替代用户确认。
5. 区分工程完成、功能完成、待审查、待联调、待验收、已验收与部署成功；未执行的检查留在角色摘要。授权发布由 OPS 执行并记录产物、环境、冒烟和回滚，不把 Git 推送当上线。

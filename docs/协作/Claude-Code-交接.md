# HD Auto Export 的 Claude Code 交接

## 从哪开始

打开 GitHub 工作分支 `codex/provider-operations` 对应的干净工作目录，从根目录启动 Claude Code。该分支基于已合入的 `main` 基线 `409529c`，包含三方车源管理、后台运营筛选与配件目录的新改动。要继续这些改动，后续任务以该分支为共同基线。工作分支进入 `main` 后，后续任务从更新后的 `main` 开始。

根目录 [CLAUDE.md](../../CLAUDE.md) 导入 [AGENTS.md](../../AGENTS.md)。用 `/memory` 检查加载情况，再看[接手导航](../README.md)和[开发进度](../开发进度.md)。仓库各角色的范围、命令和交接要求沿用现有文档。原 Codex 对话是历史背景，当前分支、角色摘要和开发日志提供可核对的工作依据。

## 谁负责什么

| 对话 | 工作范围 | 入口 |
| --- | --- | --- |
| PM | 明确目标和验收条件，确定共同基线，协调各端，验收、汇总和交付 | [产品项目](产品项目.md) |
| FE | 官网 `apps/web/` | [前端](前端.md) |
| BE | API、数据库、供应商与共享契约 `apps/api/`、`packages/contracts/` | [后端](后端.md) |
| AD | 员工后台 `apps/admin/`，按公共契约接 API | [后台](后台.md) |
| OPS | 部署、代理、备份和恢复 `deploy/` | [运维](运维.md) |
| QA／Review | 独立审查、验证最终差异和测试证据 | [测试与审查](测试与审查.md) |

先开一个 PM 会话。单端改动可以在对应会话执行。并行任务按角色各用独立分支和工作树，共享同一基线。PM 先明确接口和共享文件负责人，再汇总测试和审查结果。Claude Code 的独立子代理适合审查和短验证，长期角色可用各自会话继续。每次交接写角色、任务、基线、目录、验收条件和证据位置。

## 当前交付与环境

- 本机统一入口是 `http://127.0.0.1:3363`，官网、`/admin/` 和 API 同源。新电脑或云会话需要按[运维说明](运维.md)单独启动。当前本机验收库、密钥、运行配置与私有证据保留在本机，按需由 OPS 接手。
- 本机 ChinaCarAPI 账户状态由服务端按 `CHINACARAPI_ACCOUNT_KEY_FILE` 读取权限受限的密钥文件，通过 `/api/me` 探测。真实自动同步仍需独立接入。环境配置与凭据由 OPS 管理。
- 当前三方车源支持查询原链、筛选和人工修订。普通上游文字更新后保留符合展示条件的人工值，品牌或车型身份变化需复核。配件目录目前使用静态资料，按前端角色日志确认本次视觉和分页行为。
- 开工查工作树并执行 `pnpm hooks:check`，新 clone 安装 hooks。完成后先自测，再让独立 Reviewer 核对同一提交，PM 做联调。推送按[测试与审查](测试与审查.md#推送前检查)绑定基线和待推送 SHA。主分支走 PR 和 CI，生产发布由用户确认。

# 购车指南页面与后续维护

本轮从 2026-10-24 开始，本文更新于 2026-10-25（Asia/Shanghai）。阶段、实际检查结果及发布状态统一以[开发进度](./开发进度.md)为准；本文解释页面结构与维护入口，不替代验收记录。

## 用户要求与页面范围

用户提供的参考为 [K Motors / How to Buy](https://www.kmotors.shop/en/buy)，要求增加「如何购车」页面，将定金改为 **500 USD**，国际配送同时支持 **CIF 与 FOB**。

本页借鉴参考站的八步纵向购车流程，使用 HD Auto Export 品牌、黑金主题和中国出口背景，自写中英俄文案。没有复制参考站的韩国出口内容、退款保证、保险保证、支付渠道、检测认证或固定交付时效。当前页面提供流程说明与咨询入口；它不是订单系统，也不代表网站已提供在线车辆库存。

页面地址：`/zh/buy/`、`/en/buy/`、`/ru/buy/`。P1.12已合入main并发布，P1.13另补直达计算器导航及渐进动效（见[维护说明](./路由性能与动效.md)），当前可访问[中文购车指南](http://38.47.118.138/zh/buy/)。路由随站点构建导出真实 HTML，继续使用现有静态托管方案；不需要新增 Node 服务、数据库或运行时 API。本站当前是否已经发布这三个地址，查看[开发进度](./开发进度.md)和[实际部署记录](./VPS-IP部署记录.md)，不能根据本地页面存在推断已上线。

## 页面结构与八步流程

页面按以下顺序组织：品牌页眉 → 标题与咨询入口 → 八步／定金／交付方式摘要 → 八步纵向时间线 → CIF／FOB 对照 → 常见问题 → 咨询与计算器入口 → 公共页脚。

PC 和 H5 都保持八步顺序，使用有序列表、步骤编号及连接线；手机压缩步骤侧栏与间距，交付方式对照改为单列。定金步骤有独立的金色强调，不依靠第三方图片或脚本展示流程。

| 步骤              | 作用                                                     | 文案边界                                               |
| ----------------- | -------------------------------------------------------- | ------------------------------------------------------ |
| 1. 确定心仪车辆   | 收集车型、预算和目的地，讨论可选车辆与需要核对的进口要求 | 不链接到尚不存在的库存目录                             |
| 2. 确认定金       | 按双方确认的订单支付预订定金，计入车款                   | 不承诺无条件退款或固定保留时间                         |
| 3. 检查并确认车况 | 核对车辆信息、约定检查项目和可提供的照片／视频资料       | 检查范围与问题处理方式另行约定，不冒充检测认证         |
| 4. 支付剩余款项   | 确认车况与最终账单后，按订单／合同支付，抵扣已付定金     | 不指定未经确认的银行、SWIFT 或第三方支付渠道           |
| 5. 办理出口手续   | 协调中国出口准备，核对本单所需的出口与运输资料           | 所需文件按车辆、目的地和交付条款确认                   |
| 6. 安排国际运输   | 适合海运的订单选择 CIF 或 FOB，明确港口和费用分工        | 公路、铁路及多式联运单独确认适用条款和时间             |
| 7. 完成目的地清关 | 买方或其代理办理进口清关和当地缴费                       | 计算器仅作参考，不承诺进口资格、最终税单或完整落地成本 |
| 8. 提取车辆       | 清关放行后按约定交接车辆、钥匙和文件                     | 登记及上路要求按目的地实际规定确认                     |

这些步骤描述咨询后需要确认的业务过程，不会创建订单、收取定金、提交出口申报或发起物流查询。

## 定金数值与三语消息

运行时数值的唯一配置来源为 [config.ts](../src/modules/buying-guide/config.ts) 中的 `buyingGuideConfig.depositUsd`，当前为 `500`。摘要金额、正文和元信息从该配置取值，不在三份语言文案中分别维护金额数字。

[messages.ts](../src/modules/buying-guide/messages.ts) 导出 `getBuyingGuideMessages(locale)`，返回 `BuyingGuide` 命名空间。`zh`、`en`、`ru` 各有 **70 个字符串语义 key**，嵌套结构和 ICU 占位符一致。每种语言有以下 **5 个字符串使用 `{deposit}`**：

1. `metaDescription`。
2. `steps.deposit.title`。
3. `steps.deposit.body`。
4. `steps.balance.body`。
5. `faq.deposit.question`。

币种名称由各语言自行表达，数值由页面传入；`stepLabel` 使用 `{number}`。页面摘要的定金数字也直接读取配置。修改定金时先改 `depositUsd`，再检查三语页面、尾款抵扣说明、FAQ、meta description 与相关验收断言，避免将历史文档或测试中的 `500` 误认为另一个运行时配置来源。

中文使用「预订定金」，英文使用 reservation deposit，俄文使用 аванс。三语均表达计入车款、按订单／合同约定预留及取消／退还条件；语言切换不会改变金额、业务范围或适用交付条款。

## CIF 与 FOB 的说明依据

条款说明核对了 [ICC Incoterms® 2020 官方介绍](https://iccwbo.org/business-solutions/incoterms-rules/incoterms-2020/)和 [ICC Digital Library 海运及内河运输规则](https://library.iccwbo.org/content/tfb/BOOKS/BK_0049/BK_0049_05_RulesSea.htm)。页面仅提供简明分工，订单／合同仍需明确具体港口、所采用版本及费用范围。

| 内容                   | CIF                                    | FOB                                      |
| ---------------------- | -------------------------------------- | ---------------------------------------- |
| 交付及通常的风险转移点 | 装运港船上                             | 装运港买方指定的船上                     |
| 主要海运安排           | 卖方安排并支付至指定目的港的运费       | 买方安排并支付主运输段                   |
| 货运保险               | 卖方办理；订单核对保障、限额和除外责任 | 不默认包含卖方代办保险；买方安排所需保障 |
| 出口／进口             | 卖方负责出口，买方负责进口与当地税费   | 卖方负责出口，买方负责进口与当地税费     |

风险与运费支付范围分别说明：**CIF 的运费支付至目的港，不表示风险到港才转移**。CIF 保险也不描述为覆盖一切风险的保证，保险范围需要核对。上述原则来自 [ICC 海运规则](https://library.iccwbo.org/content/tfb/BOOKS/BK_0049/BK_0049_05_RulesSea.htm)，不是从竞品关于「全程保险」的表述推导。

CIF／FOB 属于海运与内河运输规则，本页以适合海运的订单说明选择。铁路、公路与多式联运应按实际交付安排另行确认条款，不将这两个缩写直接用于所有目的地、所有运输方式，也不把 CIF 报价命名为含进口税费的完整落地价。[ICC 2020 介绍](https://iccwbo.org/business-solutions/incoterms-rules/incoterms-2020/)

## FAQ 与咨询入口

四条 FAQ 分别说明目的地咨询、定金抵扣、清关与当地费用、运输保险。采用原生 `<details>`／`<summary>`，默认收起，支持单项独立开合，也允许同时展开多项；不需要为此增加客户端状态或交互依赖。正文、FAQ 及链接已由静态 HTML 输出，关闭 JavaScript 后仍能阅读和使用原生开合。

页面顶部和底部的咨询按钮读取 `siteConfig.contacts.whatsapp.href`，当前为用户确认号码的 [WhatsApp 咨询](https://wa.me/8618215932610)。它只是打开外部联系渠道，不会自动发送消息。页内「了解购车 8 步」跳到 `#buy-process`；底部计算器入口使用保留当前语言的 `/calculator` 链接。无 JavaScript 时，计算器静态入口保留到默认俄罗斯页的可点击链接。

共享导航的「如何购车」指向同语言 `/buy`，切换语言保持购车指南路径；计算器与购车指南分别标记当前导航。公共页脚复用现有电话、Facebook 和号码展示；Instagram／Telegram／微信在未提供确认用户名时不拼接假账号地址。公共号码复制仍遵循当前站点的 HTTPS 安全上下文限制，不因本页而引入 HTTP 兼容方案。

## 后续修改入口与边界

- 修改金额：`config.ts`；检查前述五处占位、摘要与验收断言。
- 修改流程、条款、FAQ 或 SEO 文案：`messages.ts`，三语保持同 key、同占位和同业务含义；不要将整个 `BuyingGuide` 再复制进基础 JSON。
- 调整步骤顺序或增加 FAQ：UI 中 `steps`／`questions` 列表与三语消息同步修改，核对有序列表及验收预期数量。
- 修改外观：优先改本模块 CSS Module；修改公共导航时才改共享样式，复查既有七国计算器 PC/H5。
- 修改咨询渠道：`shared/config/site.ts`，不能在新页面硬编码未经确认的用户名或付款地址。
- 修改路由或 SEO：同步页面装配、共享导航、语言链接、canonical／hreflang 及 sitemap；保留现有 noindex 开关和真实静态 404 行为。

当前没有新增车辆库存、在线定金支付、交易订单、登录、物流轨迹、报关提交、后台或真实运价服务。目的国列举用于咨询，不构成可进口资格或运输可达性保证；具体路线和条件仍须按订单确认。现有计算器仍是 2026 参考税费范围，不能因为本页描述完整购车流程就将其总额改称完整落地价。

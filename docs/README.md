# 接手导航

这是本仓库唯一的文档导航。**先确认现状，再选自己的职责；不用把全部文档读一遍。** 当前用户任务确定本轮范围，路线图不自动授权后续阶段。

## 新 Agent 从这里开始

Claude Code 从根目录 [CLAUDE.md](../CLAUDE.md) 加载公共入口，角色会话与接手步骤见 [Claude Code 交接](协作/Claude-Code-交接.md)。

1. 按 **根目录 [AGENTS.md](../AGENTS.md) → 本导航 → [当前进度](开发进度.md) → 自己的角色文件 → 本次相关契约** 阅读，确认实际能力、环境和阶段。用户须指定角色和本轮任务；目录或路线图存在不代表允许自主实现全部模块。
2. 加载 [hd-auto-development](../.agents/skills/hd-auto-development/SKILL.md)。支持 Skill 的工具可显式使用 `$hd-auto-development`；其他 Agent 直接读取同一文件即可，无需安装第二套规范。
3. 按下表只读自己的角色文件及任务所需资料，检查实际代码和已有改动，然后执行。身兼多职时按本轮涉及的职责补读，跨角色变更先协调文件归属。
4. 交付时更新本角色进度和本轮日志。总进度由产品／项目管理汇总，历史日志不反复复制。
5. 每轮确认 `pnpm hooks:check` 通过；新 clone 先 `pnpm hooks:install`。功能自测后主动安排独立 Agent review，按 [推送前检查](协作/测试与审查.md#推送前检查) 登记对应提交的实际证据。无需用户每轮重复提醒；正在运行的旧对话需先重新读取更新后的 AGENTS 和本导航。

**一个事实只设一个维护入口：** 当前状态在进度，业务决定在路线图，接口在车辆接口，操作步骤在角色任务，执行证据在日志。其他地方用链接，不重复写长篇。技术文档须区分“已实现”和“方案草案”；遇到与代码冲突先核对并记录，不能靠改文档把未实现能力写成完成。

## 本地开发与部署分工

**日常本地开发由 FE／AD／BE 自行启动和维护开发服务，不作为一次部署，不等待 OPS 打包。** 改源码后使用热更新／自动重启查看结果；仅应用启动参数或环境变量改变时重启受影响服务。

| 对象 | 日常负责人及方式 | 何时需要构建／OPS |
| --- | --- | --- |
| 官网 | FE：`pnpm dev:web`，Next 开发服务 | 提交范围检查或检查 SSR／缓存／生产产物差异时构建；普通页面修改不交 OPS |
| 后台 | AD：`pnpm dev:admin`，Vite 开发服务 | 提交范围检查及部署时构建；普通表单、表格调整直接热更新 |
| 后端 | BE：`pnpm dev:api`，监听源码并自动重启 | 新迁移由 BE 在自己的开发库验证；部署、共享数据环境迁移与 OPS 协调 |
| PostgreSQL／Redis／本机媒体 | 复用指定的本地实例和持久化目录；不随每次源码变化重建 | OPS 首次准备，配置／资源／恢复问题时参与；不得让多个端另建重复业务库 |
| 本地入口与部署 | 各端可分别使用开发端口，完成后列清实际访问地址 | 不以统一网关接线为开发前置；OPS 按需协助基础设施，真实发布仍由 OPS 执行 |

命令从仓库根运行。安装依赖仅在首次接手或依赖／锁文件变化时执行；`@hd/contracts` 首次及其源码变化后构建一次，由变更负责人通知消费者，不为每次页面改动重装全仓。已有本地环境不重复复制 `.env`、创建账号、初始化库或恢复数据。开发环境不连接生产数据库，也不默认启用三方同步或自动付费调用。

**最新决定：本地不再强制统一 3363，允许分端口以提高开发效率。** 当前脚本默认官网 `http://127.0.0.1:3317/zh/`、后台 `http://127.0.0.1:3318/admin/`、API `http://127.0.0.1:3320`；这些是默认配置，不表示服务此刻已启动。端口被占用时核对进程归属，必要时改用明确记录的空闲端口，不停掉其他任务的服务。原 3363 组合可保留给生产模式核验，不作为日常开发前置。

各端自行配置本机 API 地址／开发代理及明确的可信 Origin，跨端直接协调；不为统一地址再等待 OPS 构建或网关改造。代理须支持热更新，保留 Cookie、员工预览和媒体权限；不关闭鉴权、CSRF 或任意放开跨域。开发应用只监听回环地址或受控私网，数据库与缓存不公开暴露。

交付时给用户一份简短地址清单：官网 URL、后台 URL、API 端口／用途，注明实际运行分支或版本、哪些服务已启动。临时测试结束释放自己创建的资源；用户正在查看的预览保持可用，替代确认后再清理自己的旧进程。不要把历史地址或仅写在配置中的端口当作可用服务。

**落地状态：三端开发命令已存在；本次只更新规则，没有启动、停止或切换任何服务。** 主流程在自然交接点按实际环境启动各端，验证访问及 API 链路后报地址，无需先把 3363 改成开发代理。

开发模式用于功能和交互，不用于证明生产速度、SSR 缓存、安全代理或部署成品正常。完成一个交付批次时按 [检查范围](协作/测试与审查.md#测试范围按改动选择) 构建和验证一次；发布相关改动才使用生产模式复核。检查与 `next dev` 不能并发写同一 `.next/`：使用独立检查工作区，或由 FE 暂停自己的 dev 再检查并恢复；不要重启整个本地环境。跨端联调由相关开发端直接协作，OPS 仅处理环境阻塞；PM 核对结果，不逐次转交启动请求。

## 每轮如何记录

任务状态统一为：`待开始` → `进行中` → `待审查` → `待联调`（有跨端依赖时）→ `待验收` → `已验收`；`受阻` 须注明阻塞、负责人和可继续部分。历史 `待用户验收` 对应 `待验收`。

- 实现者自测并提供版本／diff／检查证据后进入待审查；独立 review 通过后进入联调，单端任务可直接待验收。审查或联调发现阻塞问题退回进行中，修复后按受影响范围复查。
- QA 验证集成场景，PM 核对证据与阶段门槛，用户完成业务／视觉验收。P0/P1 阻塞进入待验收；P2 须有负责人、处理计划和明确接受依据。完整职责和报告要求见 [测试与审查](协作/测试与审查.md)。
- 标清本地、CI、预发布或生产。验收通过不等于已部署；发布由 OPS 在已有授权及实际环境下执行，并记录冒烟和回滚结果。

1. **一个任务一份记录。** 在 `docs/日志/YYYY-MM-DD/角色-任务ID-主题.md` 保存简短交付；同任务的修复、复测、跨端验收追加在该文件，不按每次对话／每天／角色拆出重复报告。跨端由一位记录负责人汇总，其他角色给结果，不并发编辑同一文件。
2. 角色摘要仅在阻塞、完成或交接时更新一行状态和该日志链接；无需中途反复刷新。PM 只在阶段交付更新总进度，不复制各端全过程。
3. 变更接口、配置和维护方法才更新相应维护文档；普通修复不强制触碰 Skill、路线图和所有角色文档。历史记录不重写；确需保留的失败证据在原日志追加原因与复测。

最小模板如下，简单任务可直接使用四个条目；不要堆贴终端输出或为凑齐栏目编写材料：

```markdown
# 任务ID / 主题
- 范围与版本：负责人、基线／交付提交（未提交则注明）、环境。
- 结果：实现了什么，关键维护入口。
- 验证：实际命令／关键场景和结果；独立审查者／报告链接；失败及复测、未覆盖项。
- 交接：提交／推送／部署的实际状态，阻塞或下一步。
```

同版本已有结果直接引用；只复测受影响内容，不把旧结果冒充新版本全量通过。仅关键视觉差异保留截图；数据删除、迁移与恢复保留必要回退资料。独立审查 JSON 与门禁收据沿用 [测试与审查](协作/测试与审查.md)，无需另写同内容长报告。

历史记录从 [归档索引](归档/README.md) 查。公开日志不写密钥、会话、客户隐私或原始生产数据。

可直接给新对话的开工语：**“先读仓库 AGENTS.md，通过接手导航找到你的职责。你负责【前端／后端／后台／运维／产品项目／测试与审查】，本轮执行【任务或问题】；按统一规范交付并记录角色进度和日志。”**

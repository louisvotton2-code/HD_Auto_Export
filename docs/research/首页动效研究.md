# 首页水波与车辆卡片动效还原记录

研究日期：2026-11-05（Asia/Shanghai）。前六节区分参考站公开实现、修正依据与本站约束，第七节记录已执行的本地验证。本站最终代码、已执行检查和用户验收状态以[开发进度](../开发进度.md)为准；首页整体结构、数据边界见[首页与演示车源](../开发/模块/首页与车源.md)。

## 1. 本次纠正的问题

用户指出参考站首屏是在随机位置产生水滴扩散，点击时从点击处产生水波；车辆卡片则随鼠标位置发生三维倾斜。上一版仅实现固定圆心的动态圆环和图片放大，不能认为已经还原这两种行为。

本轮使用现有浏览器、Canvas 调用观察及公开客户端模块确认参数，无需新增插件才能实现。先前偏差来自观察和实现不够具体，不能归因为工具无法获取动画。

## 3. Hero 的实际行为与参数

### 水波产生和输入事件

| 项目 | 参考站实际行为 |
| --- | --- |
| 自动产生 | 每 1,500ms 尝试产生一组水波及粒子，位置在整个 Canvas 宽高内均匀随机 |
| 自动数量限制 | 当前仍存活的水波少于 5 组时才自动产生；点击分支没有该数量限制 |
| 初始化 | 动效初始化后开始绘制；首次自动水波等待定时器触发，没有固定居中的常驻水波 |
| 点击 | Canvas 原生 `click` 事件产生水波和粒子 |
| 点击坐标 | `x = clientX - canvasRect.left`，`y = clientY - canvasRect.top`，使用 CSS 像素坐标 |
| 鼠标移动 | 精细指针下记录 Canvas 内的相对位置，只更新光晕，不会产生水波 |
| 触屏 | 通过 `(pointer: coarse)` 禁用鼠标移动监听；源码事件处理器含 touches 分支，但实际注册的是 `click`，没有注册 `touchstart` 或 `pointerdown` |

### 每组水波

下列更新量是原站按每次 `requestAnimationFrame` 更新的数值，**不是每秒数值**。因此原站速度受刷新率影响。讨论寿命和速度时不能省略这个口径。

| 项目 | 参数或更新方式 |
| --- | --- |
| 初始半径 | 0px |
| 初始扩张速度 | 随机 2～5px／帧 |
| 初始透明度 | 随机 0.6～1 |
| 初始线宽 | 随机 1～4px |
| 每帧半径 | 增加当前速度 |
| 每帧速度 | 乘以 0.995，逐渐减速 |
| 每帧透明度 | 减少 0.003；降至 0 或更低时删除整组 |
| 圆环数量 | 每组最多三圈，半径分别为当前半径、当前半径减 15、当前半径减 30；半径非正的圈暂不绘制 |
| 三圈透明度倍率 | 1、0.7、0.4 |
| 三圈线宽倍率 | 1、0.8、0.6 |
| 描边颜色 | `rgba(182,119,73, 当前圈透明度)`，即铜色 `#b67749` |
| 波内柔光 | 中心 `rgba(200,136,88, 当前组透明度 × 0.1)`，在当前半径处衰减为透明 |

源码还声明了 80～200px 的随机 `maxRadius` 字段，但它没有参与绘制限制或删除条件。不能根据变量名把它误写成参考站的真实最大扩散半径。

### 随水波产生的粒子

| 项目 | 参数或更新方式 |
| --- | --- |
| 位置 | 以该组水波圆心为中心，随机角度及 0～60px 的径向距离 |
| 数量 | 实际约 4～8 个；源码在循环条件中反复重新取随机数，不是预先选定一个整数 |
| 初始半径 | 随机 2～10px |
| 向下速度 | 随机 0.5～2px／帧 |
| 初始透明度 | 随机 0.4～1 |
| 颜色 | 约 75% `#b67749`、25% `#9d5e34` |
| 每帧变化 | 纵坐标增加当前向下速度、透明度减 0.002、半径乘 0.999 |
| 删除 | 透明度耗尽，或纵坐标超过 Canvas 高度加 20px |
| 高光 | 粒子中心左上各偏移 0.3 倍半径，绘制半径为原半径 0.3 倍的白色 30% 透明小圆 |

原站没有对粒子施加重力加速度，向下移动速度在该粒子的生命周期内保持固定。

### 背景、指针光晕与尺寸

- 背景以 Canvas 中心为圆心，从 `#0f0f0f` 渐变到 `#0a0a0a`，渐变半径为宽度的 0.8 倍。
- 每帧另外随机绘制 15 条极淡铜色柔光笔触：长度 50～250px，线宽 10～50px，整体透明度 0.03，线条两端透明。它们不是水波的运动轨迹。
- 鼠标光晕以指针位置为中心，半径 40px，铜色中心透明度 0.15，向外渐隐。原站没有离开时清除最后位置的监听。
- Canvas 缓冲区宽高等于 CSS 尺寸乘 `devicePixelRatio`，然后将绘制坐标缩放到 CSS 像素。原站没有 DPR 上限。
- 原站监听 `window.resize`，重新设置 Canvas 宽高并缩放绘图上下文；设置宽高会重置上下文状态，不能在未重置时反复累加 `scale()`。

## 4. 车辆卡片的实际三维效果

效果作用于**整张车辆卡片**，而不是单独将汽车图片放大。鼠标移动时读取卡片矩形，以卡片中心为原点计算 `dx`、`dy`。

| 项目 | 参考站参数 |
| --- | --- |
| 透视距离 | `perspective(1000px)` |
| 上下倾斜 | `rotateX(-dy × 0.025deg)` |
| 左右倾斜 | `rotateY(dx × 0.025deg)` |
| 悬停缩放 | `scale3d(1.02, 1.02, 1.02)` |
| 变换过渡 | 400ms，`cubic-bezier(0.16, 1, 0.3, 1)` |
| 阴影过渡 | 400ms，`ease` |
| 指针光照 | 指针在卡片内的百分比位置为径向渐变圆心，白色 8% 从中心衰减，到 60% 处透明 |
| 光照层 | 覆盖整张卡片，`pointer-events: none`，不会挡住收藏、社交和详情入口 |
| 悬停阴影 | `0 20px 60px rgba(182,119,73,0.12)` |
| 悬停边框 | `rgba(182,119,73,0.3)` |
| 离开 | X／Y 旋转归零、缩放回 1，光照层改为透明 |

例如在卡片中心右侧 100px、下方 60px，目标角度是 X 轴 −1.5°、Y 轴 +2.5°。需要验证角度随着指针位置连续变化，不能只检查悬停时 `scale` 大于 1。

## 5. 本站独立实现与有意改进的边界

以下是本站实现约束及维护时应检查的行为，不是原站已经具有的能力，也不表示本次尚未执行的本站测试已经通过：

- 用本站自己的类型、生命周期管理和 Canvas 绘制组织上述行为，不把参考站压缩模块、统计代码或第三方 React 运行时引入产品。
- 用明确的整数生成粒子数量，保留相近的密度；不复制原站循环条件反复取随机数的偶然写法。
- 使用时间差并以 60Hz 为基准换算扩张、衰减与移动，避免高刷新率屏幕让动效加速。应限制恢复可见后的巨大时间差，防止一次跳帧直接结束全部水波。
- 可以限制 DPR，避免高像素密度设备的绘制成本无上限增长；点击、光照和尺寸判断始终使用 CSS 像素，不能把事件坐标再次乘 DPR。
- 页面隐藏或 Hero 离开视口时暂停不必要的动画和自动产生；恢复时不补发隐藏期间遗漏的水波。销毁时清理 RAF、定时器、尺寸和输入事件。
- 尊重 `prefers-reduced-motion`：自动水波和持续位移需要降低或停止，车辆卡片避免跟随旋转，可保留静态边框与焦点提示。已有用户暂停入口应继续有效。
- 三维卡片仅对支持悬停的精细指针启用；触屏不模拟鼠标追踪，不影响横向车源轨道滑动、详情链接或收藏按钮。
- 指针离开卡片后恢复基准变换、光照、边框及阴影，避免残留悬停视觉。键盘焦点仍须清晰，不用清除焦点来移除效果。
- 设置合理的波纹和粒子数量上限，防止连续点击导致无上限分配；该保护不是原站已有的点击限制。布局及业务区块顺序不因该保护而改变。

## 6. 验证要求与当前状态

下列是验收清单；已实际执行的子集见第七节和开发进度，不能把这些建议项全部记为已通过：

1. 自动生成的水波具有多个独立随机圆心，点击两个不同位置各自产生新圆心，页面有滚动偏移后点击位置仍正确。
2. 新波纹随时间扩张并衰减，旧组会删除；不是只有背景光晕移动，也不是固定圆心循环缩放。
3. 同一张车辆卡片在左上、右上、右下等位置具有对应的 X／Y 角度和光照位置；离开后归位，内部入口继续可用。
4. 1440px 桌面、390px 手机、DPR 变化以及 resize 后位置正确，触摸滑动和轨道控制不被动效拦截。
5. 减弱动态、暂停、页面隐藏／恢复、滚出／滚入以及路由离开时无多余 RAF／事件泄漏；这些属于本站增强，应单独注明检查结果。

截图只能证明某一时刻的外观。水波的产生位置、扩散和衰减，以及卡片的指针跟随，应结合连续帧、Canvas 调用或实际变换数值验证，不能仅用“页面未溢出”代替动效还原验证。


## 7. 本轮实现与执行验证（2026-11-05）

本地实现入口为 `home/ui/hero-canvas.tsx`、`ripple-scene.ts`、`use-pointer-tilt.ts` 与 `home-page.tsx/home.module.css`。Canvas按CSS坐标处理hero的原生click并过滤真实链接／按钮，连续点击有24波／192水滴上限；背景15条笔触保持静止，DPR上限2，按60Hz时间归一，暂停及减弱动效保留静态画面。车卡由不变形的vehicleSlot承接轨道定位，article自身变形；不能再给可倾斜article直接加snap，或监听每次scroll就强制归零，否则浏览器吸附会反过来取消倾斜。

最终96页静态构建通过。成品23项定向检查包含5项动效输出测试及首页／导航回归，另1项触屏高DPR、resize及滚动后的点击圆心验收通过。水波检查实际记录Canvas圆弧中心与半径，不只检查class；倾斜检查读取真实DOMMatrix，验证双轴符号变化、离开回正和内部导航。首轮暴露的自吸附／自重置已修复，最终轨道位置保持稳定。

此处通过的是本机Chrome及移动模拟的明确场景；Safari真机、所有设备刷新率／性能和用户视觉验收尚未完成。完整阶段状态及最终检查仍以[开发进度](../开发进度.md)为准。

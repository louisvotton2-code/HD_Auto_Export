## 页面结构与还原依据

来源为 [Kmotors 英文首页](https://www.kmotors.shop/en)。2026-11-04/05 使用 Browser Use、公开 DOM/CSS 和独立 Chrome 实际截图，桌面 1440×900、手机 390×844。工具可以观察 Canvas、自动轨道及响应式；上一版擅自改成汽车大图首屏是实现偏差，不是工具能力不足。

当前固定区块顺序：居中标题与 Canvas 首屏 → 三列快捷入口 → Kia 车源轨道 → Hyundai 车源轨道 → 灰度品牌跑马条 → 热门车型轨道 → 三项优势 → 五步购车流程横轨 → 沟通演示横轨及放大弹窗 → 计算器横条 → 电话咨询表单 → 三列页脚。

## 明确的业务差异

- HD Auto Export 的标志、品牌、中国出口、成都地址及两个电话号码沿用用户确认信息。About 链接旧官网；About/Contact 不维持栏目激活状态，键盘焦点轮廓保留。
- 首页数字是当前演示车数量、7个目的地和3种语言，不复制竞品的库存、客户数量或经营年限。
- 示例车辆主价使用 USD，韩国样例的 KRW 仅作快照补充；不是报价或落地价。保留演示标记及原图水印。
- 优势、CIF/FOB及购车流程使用本站业务内容；不照搬韩国拍卖检查承诺。
- 沟通卡是明确标注的虚构商务对话，不能当作真实评价；不采集第三方私人聊天图片。
- 电话表单仅做本地输入校验并提示尚未发送，提供真实 WhatsApp 联系入口；没有后台、发送接口、账号、购物车或支付。配件入口使用说明弹窗，不跳转空页面。
- 没有追踪Cookie，因此没有复制竞品Cookie条幅或首次自动弹出的留资窗口；真实联系方式比伪造账号入口优先。未确认的支付渠道不展示为受支持。

## 模块与目录

- `src/modules/home/index.ts`：首页公共入口；`types.ts` 定义纯展示契约。
- `home/content/`：三语同语义文案，`home/ui/`：首屏、车源轨道、Canvas、其余区块和CSS Modules；`ripple-scene.ts`独立维护波纹／水滴生命周期与绘制，`hero-canvas.tsx`管理浏览器事件、暂停、可见性和画布尺寸。组件不读取车辆 mock，不包含税率。
- `src/modules/vehicles/index.ts`：`getVehicles/getFeaturedVehicles/getVehicleBySlug/getPopularModels/filterVehicles` 公共接口。UI和页面只能经公共接口组合，边界脚本会拒绝从其他模块或路由直接导入车辆内部文件。
- `vehicles/mock/vehicles.ts`：原有11条示例；`hyundai-vehicles.ts`：新增8条，合计19条。`homepage.ts`：9条车型家族。完整来源及字段区别见 [mock 来源说明](../../../apps/web/src/modules/vehicles/mock/README.md)，新素材原URL／字节数／SHA256见 `reference-homepage-sources.json`。
- `public/demo-vehicles/`：本地图片；`public/fonts/`：本地字体及OFL。所有图片必须与型号对应，不能拿同品牌另一辆车补图；缺失图片用中性占位。
- `src/app/[locale]/page.tsx`：数据装配、三语 metadata。`cars/` 负责列表及详情静态路由，始终 noindex；首页遵循站点索引开关。
- `src/shared/ui/site-shell.module.css`：新68px外壳样式，覆盖旧品牌壳。`site-header.tsx/site-footer.tsx` 保留原联系、导航、草稿切换及无JS入口能力。

根路径进入俄文首页；`/zh/`、`/en/`、`/ru/` 是各语言首页。计算器独立入口和默认USD不变。语言／目的国／交易币种互相独立。

## 后续替换真实接口

按[车辆接口草案](../车辆接口.md)由后端 inventory 服务统一自录／第三方数据，现有 vehicles 界面通过公开契约及展示映射替换 mock；数据库与供应商请求留在独立 server-only 出口，不混入含 UI 的公共入口。映射须明确来源币种、缺失值、可售状态和更新时间；组件不能直接请求竞品或平台接口。模型家族卡与具体车源分开，避免图片或规格串车。上述接入尚未实现。

静态导出在构建时生成车辆路由和数据；库存不会自动更新。若需要实时价格、大量动态详情或持久收藏，需要另行确认接口、缓存、权限和托管方式。当前爱心仅在页面内保存展示状态，刷新不保留。车辆详情跳转计算器不会自动将演示字段作为事实传入。

## 车辆联系草稿（P1.17.3）

首页两条品牌轨道、演示目录的具体车辆卡片，以及详情页，均提供蓝色Telegram与绿色WhatsApp。热门车型家族卡是筛选入口，不伪造具体车辆编号／年份。联系方式不嵌套在详情链接里，允许键盘访问和原生新标签打开。

公共函数 `src/shared/lib/vehicle-contact.ts` 接收独立结构化事实，统一生成两个URL；不依赖 vehicles内部、浏览器或网络。账号来自 `shared/config/site.ts`：Telegram为用户确认的 `HD_Auto_CN`，WhatsApp为中国号码8618215932610；图标共用 `shared/ui/social-icon.tsx`。调整消息字段／编码只能在公共函数修改，组件不重复拼接。

预填内容包括演示编号slug、车型、年份、USD示例价、里程、动力、车身及详情URL，随当前语言切换。当前所有记录均为演示，消息也明确演示含义；接真实库存时同步更换该语义及编号契约。详情URL采用 `NEXT_PUBLIC_SITE_URL`，本地默认localhost:3000，正式发布需实际域名重建。

[Telegram官方文档](https://core.telegram.org/api/links#public-username-links)支持普通用户名链接 `?text=`（不加profile）；[WhatsApp官方说明](https://faq.whatsapp.com/5913398998672934/)支持国际号码链接 `?text=`。两者均用URL API和encodeURIComponent一次编码，中文、俄文、换行及特殊符号保持原文；草稿不自动发送。浏览器回归检查URL及内容，不声称已登录所有客户端或真实发送消息。

详情hover提亮使用伪元素opacity，不移动按钮命中区域；整卡透视仍保持。测试入口为 `tests/details-hover.spec.ts` 和 `tests/vehicle-contacts.spec.ts`。统一页面、组件与模块规范见[项目Skill](../../../.agents/skills/hd-auto-development/SKILL.md)和[使用说明](../../README.md)。

## FE-REL-03 SSR复用与分页保护

- HTML仍动态SSR，不共享整页。每次先经正式内部version端点核验当前公开版本，再按环境／固定release／API origin、规范化有效查询、价格和FX维度复用DTO；版本读取失败不使用旧值。
- 共享loader只携带静态服务身份。访客上下文只用于缓存外的version限流，requestId剥离后才入缓存，读取后恢复本次trace。禁止把员工预览、BFF、媒体、POST和错误接入该缓存。
- Node全进程64项／16MiB LRU、加载中键数有界及同键合并；最长15秒，扣除全程读取耗时，受上游原始剩余TTL、FX与签名远图到期限制。命中不续期，版本不一致最多重试一次，无stale回退。
- offset10000含边界，分页按实际pageSize限制可达尾页，total仍是真实总量。`parseCatalogPageRequest`将合法但超限深链接与非法参数分开：前者三语提示收窄条件并保留筛选的首个可达链接，不先查询全目录／facets，不报404。
- 必填运行变量、内部凭据文件、维护入口和定向浏览器测试见[官网README](../../../apps/web/README.md#fe-rel-03-ssr-dto缓存)。真实BE／网关20并发和故障验收由OPS完成，本地fixture不代替跨端证据；实际状态见FE角色日志。

## 明确的业务差异

## FE-UX-04 筛选与本地化维护

- 参数唯一清单与SSR/浏览器/BFF共用解析在`vehicles/public-query.ts`；分页和查询链接用`publicCatalogHref`。新增条件须同时核对解析、BFF白名单、原生GET、facets查询、分页/Back URL、SSR与隔离fixture，不可只改下拉框。
- `priceMin/Max` 使用原始十进制字符串，范围必带 `priceCurrency`。官网只接受 USD 表单范围，原币 API 保持原有行为。金额运算使用整数分。里程 0 有效，年款是 `modelYear`，与制造／登记日期分别展示。上下界包含端点，上限不得小于下限，限定范围排除未知值。取整后的官网筛选见下文。
- 品牌变更清车型/代次/配置，车型变更清代次/配置。合法model-only网址仍保留车型查询；空URL上的清除操作也清未Apply草稿和错误。无JS依靠原生GET，父级改动后可先提交再选择子级；不伪造客户端查询结果。
- 官网读取显式`view=localized`（服务端/首页/目录/详情/收藏）；公开BFF保留调用者不传view时的legacy形状兼容。`localized-projection.ts`要求display及全部requestedLocale一致，并核对标题/描述/详情路径语言；缺失时按服务不可用处理，不静默采用旧raw中文DTO。平铺facts/price.includes/images.alt/source的安全替换由API统一projectDisplay提供，FE信任该正式投影，不维护自己的品牌字典，不把machine改成人审。
- 首页与目录共享`shared/ui/use-pointer-tilt.ts`，组件只提供平整外壳和3D内层。layoutKey变化重置缓存；鼠标每帧写一次CSS变量，触屏/减少动效保持平面，键盘focus/卸载/窗口变化清理。不要重新加整卡translateY或在hover按钮改变几何位置。
- 本轮入口`tests/catalog-filters.spec.ts`（完整条件/原币/零值/级联/分页/Back/无JS/清空/精确金额）、`tests/catalog-motion.spec.ts`（实际矩阵/光层/按钮命中/触屏和reduce），既有限流与home/favorites/detail回归仍须按改动范围保留。实际执行次数见FE-UX-04日志，测试文件存在不代表已通过。

## FE-EXT-01 统一目录与外部资料

- `/cars/` 继续使用 `catalog=curated&view=localized`。员工发布顺序、外部记录可见性、筛选和全局分页由 API 统一决定。首页车辆轨道按后台配置读取，目录统计单独采用合并总量。无 `view` 和显式 `view=legacy` 的列表、首页和详情校验排除自动导入记录。sitemap 使用独立的 legacy 员工流分页并保留原有手工发布、可售及索引约束。
- `vehicles/localized-projection.ts` 在 SSR、BFF 与浏览器使用同一详情／列表校验。列表和首页响应不含 `external.detail`。`ui/external-vehicle-information.tsx` 渲染配置和需确认的字段。原文对照和关联挂牌从公开详情界面移除，API 契约维持兼容。语言回退按实际 `contentLocale` 标记。
- `ui/vehicle-photo.tsx` 是首页、目录与收藏的图片回退入口，`ui/vehicle-gallery.tsx` 处理详情。远程图按原 URL 直连并省略 Referer。已知过期和缺图直接显示本地替代状态。加载失败可上报媒体 ID 和修订号，由同源 `POST /api/v1/external-media/:id/failure/` 验证后交给 API。客户端有界去重并立即回退。202 表示收到信号，实际刷新取决于后端任务。画廊打开时照片全部移除会解除滚动锁并恢复焦点。
- `tests/external-catalog.spec.ts` 用共享合成契约验证总量、分页、语言、资料边界、故障回退与撤回。API／数据库联调和实际车源抽检各自记录，执行入口与版本见[联调记录](../../日志/2026-11-10/前端-FE-EXT-01-合成车源联调.md)。

## FE-UX-06 车辆标题、双币价格和详情

- 官网在 SSR 和同源数据请求显式传 `view=localized&priceView=usd`。该模式的车辆响应须带 `displayPrice`，无 opt-in 的旧 API 维持原始报价和原币筛选。
- `shared/lib/public-vehicle-title.ts` 优先使用可用中文标题。源标题回退到外语时，用公开车型字段组合中文页标题，按实际提供的品牌、车型、年款和中文配置构造。首页、目录、详情、收藏、详情 SEO 及联系草稿共用。原始译文、车型标识和接口数据由 API 管理。
- `VehiclePriceValues` 先显示原币价格，再显示可用的整美元参考价。原生 USD 只显示一行整数；有原价但汇率不可用时保留原价，缺原价显示待询价。`shared/lib/public-vehicle-price.ts` 用整数分四舍五入，询价草稿沿用该舍入。汇率日期和署名由 `VehicleRateAttribution` 输出。原 `price` 继续用于预算测算。
- 目录网站的整数 USD 边界与可见整数对应。例如 1000 至 1000 对应 API 999.50 至 1000.49。列表和筛选字典共用映射，旧书签中带非零分的 USD 边界保持精确。原币 API 和直接传价格条件的公开 API 调用继续使用精确小数。旧非 USD 目录书签清除金额条件，保留其余筛选。
- `VehicleGalleryThumbnails` 使用一行横向滚动的实图，主图直接打开原有查看器。站内媒体使用 `variant=thumb`，外部媒体无独立缩略图字段，视口及临近位置加载原图。键盘、触屏、原图链接和焦点恢复均保留。
- 主图的轻触由触摸结束事件打开查看器，避免横滑后的首次点按依赖浏览器合成点击。横滑切图，系统接管滚动时清除触摸起点。鼠标和键盘继续走链接的点击处理，无 JavaScript 时链接打开原图。
- `vehicle-equipment.ts` 把公开平铺配置分成舒适、安全、技术、其他，保留字段实际值和源语言。未归类资料进入其他。历史只列实际制造、首次登记和过户次数，公开接口缺少逐任车主记录、VIN 和车牌。见 [FE-UX-06 日志](../../日志/2026-11-10/前端-FE-UX-06-车源详情还原与双币报价.md)。

## FE-UX-07 车辆报告与详情预算

- FE-UX-08 将所在地归入「详细车辆信息」，右侧不再单独展示车源平台和地点。所在地优先展示公开地名及其语言，只有国家时按页面语言显示国家名。车源及地点仍按原公共 API 契约返回。
- 历史FE-UX-07实现（公开入口已由EXT07独立有界报告替代，员工预览仍使用共享renderer）：`vehicle-inspection-report.tsx` 在 `external.detail.inspection` 有内容时直接显示前六项，其余可展开，存在公开报告地址时展示原始报告链接。右侧在有报告时保留同页跳转，并在咨询区增加索取检测报告的 Telegram／WhatsApp 入口。`inspection-contact.ts` 在统一车辆草稿上补充报告请求，使用同一车号、稳定 ID、详情 URL 和 HD 账号。入口随公开资料失效一同禁用，报告为空时隐藏。
- FE-UX-09 中，详细车辆信息与车辆配置的外层原生 `details` 默认展开。内部配置分组继续由用户逐组展开。内联预算的目的国选项和备用计算器入口复用 `calculator/config/countries.ts` 的国旗显示事实，旗帜随国家标签装配；计算规则和车辆预填保持原调用路径。
- 内联预算用公开交易价、动力类型、排量、功率、制造日期和登记状态预填支持的输入。EXT07起仅精确制造月份直接预填，否则使用明确来源日期范围逐月报价；只有年款或无依据时留空，首次登记仍独立。旧一月推断不再沿用。未知方向盘位置及其他参数由用户补充。
- `manufacture-estimate.ts` 仅在表单层处理估算标记，计算核心接收用户可编辑月份及清关日期。旧片段和草稿可读但会移除旧猜月，范围通过完整计算器跳转／会话刷新／复制保留，手动修改制造月份后清除范围。规则及汇率维持原有口径。
- 未填必需资料时内联卡片列出缺项，产生参考结果后显示绿色费用框。具体验证和限制见 [FE-UX-07 日志](../../日志/2026-11-10/前端-FE-UX-07-车源报告与详情预算.md)。

## FE-UX-11 当前分页、历史和报告边界

- `catalog-pagination.ts` 根据公开API精确总量或accessibleTotal生成可浏览页数；`ui/catalog-pagination.tsx` 使用原生链接装配参考方格页码、必要省略号和总页数，URL继续由 `publicCatalogHref` 统一生成。未知总量不推算全库页数，不以当前页数量代替总数。
- `vehicle-history-data.ts` 优先使用正式 `history.ownershipTransfers`，明确0保留、现代null／整个history:null不回退旧过户文本；这个优先级仅针对过户字段，其他精确发布的旧风险条目仍兼容。缺失、非法和冲突不填0，检查项的faults／checked不当事故次数。制造／首登日期仍在详细信息；无明确历史隐藏整框。
- 正式合同当前只接入过户次数，其余事故、盗抢、洪水、泡水等须实际来源提供明确资料。没有逐任车主时间线或牌照档案时，不复制参考站数字及样例记录。
- `VehicleInspectionReport` 展示正式 `checks/defects` 分类、组、部位、结果和缺陷说明，分别保留0、false、null及实际文本语言。分类默认折叠并按6／12项分批挂载，旧 `entries` 保留首批。无JS有首批／分类／计数及三语继续查看说明，没有无效“更多”按钮；深层项需JS，不声称已全部SSR。右栏“查看检测项目”仍是本页锚点；空检测内容不画卡。
- 报告交互按用户在PM对话的新决定（2026-11-12）改为仅联系销售。详情只在正式 `vehicle.report?.hasReport === true` 时显示“详细报告请联系销售人员获取”及原有Telegram／WhatsApp车辆草稿，不依据检测条目数量或可达性unknown判断存在；false／缺失只省略提示，不断言没有报告。原始报告URL只留后台权限范围，官网不输出外链，不探测、不保留旧时钟／可用性链接组件。BE负责来源与车的真实绑定及公开投影不泄露嵌套旧URL；当前19 unknown不再是存在提示的阻塞项。
- `ui/vehicle-configuration.tsx` 是详情／员工预览共用的 `ConfigurationDisplay` renderer，默认展开，保留名字／值实际语言、原数字／单位／空白与source／reviewed元数据；缺项为—，空配置不画卡。公开默认不显示员工审核说明，私有预览附真实元数据。配置只在详情／预览读取，两端核验name/value.requestedLocale；首页／列表拒绝夹带大配置。canonical配置优先于旧的推断分组，避免重复框。API实施与组合验收状态见[本轮日志](../../日志/2026-11-12/前端-FE-UX-11-分页历史与经营年限.md)。

## 车辆联系草稿（P1.17.3）

首页两条品牌轨道、演示目录的具体车辆卡片，以及详情页，均提供蓝色Telegram与绿色WhatsApp。热门车型家族卡是筛选入口，不伪造具体车辆编号／年份。联系方式不嵌套在详情链接里，允许键盘访问和原生新标签打开。

公共函数 `src/shared/lib/vehicle-contact.ts` 接收独立结构化事实，统一生成两个URL；不依赖 vehicles内部、浏览器或网络。账号来自 `shared/config/site.ts`：Telegram为用户确认的 `HD_Auto_CN`，WhatsApp为中国号码8618215932610；图标共用 `shared/ui/social-icon.tsx`。调整消息字段／编码只能在公共函数修改，组件不重复拼接。

预填内容包括演示编号slug、车型、年份、USD示例价、里程、动力、车身及详情URL，随当前语言切换。当前所有记录均为演示，消息也明确演示含义；接真实库存时同步更换该语义及编号契约。详情URL采用 `NEXT_PUBLIC_SITE_URL`，本地默认localhost:3000，正式发布需实际域名重建。

[Telegram官方文档](https://core.telegram.org/api/links#public-username-links)支持普通用户名链接 `?text=`（不加profile）；[WhatsApp官方说明](https://faq.whatsapp.com/5913398998672934/)支持国际号码链接 `?text=`。两者均用URL API和encodeURIComponent一次编码，中文、俄文、换行及特殊符号保持原文；草稿不自动发送。浏览器回归检查URL及内容，不声称已登录所有客户端或真实发送消息。

详情hover提亮使用伪元素opacity，不移动按钮命中区域；整卡透视仍保持。测试入口为 `tests/details-hover.spec.ts` 和 `tests/vehicle-contacts.spec.ts`。统一页面、组件与模块规范见[项目Skill](../../../.agents/skills/hd-auto-development/SKILL.md)和[使用说明](../../README.md)。

## FE-UX-09 咨询弹框与筛选数据

- `modules/enquiries` 独立维护三语表单、30 秒停留与七天重复间隔，按角色传入 locale。语言 layout 装配 Provider，并用 `SiteHeader.enquiryAction` 注入入口，共享头部不依赖业务模块。原生 `<dialog>` 承担模态焦点，关闭恢复滚动与触发元素。
- 自动提示跳过车辆和配件详情，暂缓正在输入、页面隐藏、已有对话框和手机菜单。表单以原生 GET 打开所选 HD Telegram／WhatsApp 草稿；访客自行发送。`hd-auto:enquiry-seen:v1` 只保存展示时间，存储不可用时在当前会话内频控。
- 首页／目录的品牌、车型及其数量继续读取独立 API。宽范围 facets 字典和当前筛选结果范围依车辆接口约定区分，结果总数取 `list.meta.total`。真实每日同步当前尚未启用，后端确认与隔离验证见本轮日志。
- 详情外层详细信息及车辆配置默认展开，国家旗标复用已有 country 配置。只有 `external.detail.inspection` 已有报告链接或条目时才显示联系索取入口。相关报告草稿复用统一车辆 builder 和联系 freshness。

# 三方搜索索引维护

索引历史回补只处理 `chinacarapi` 挂牌已有的语言搜索行。它按当前公开文本规则重建品牌、车型、配置、代际标签及匹配词，屏蔽旧标题中的私有文本。它保留业务投影、人工覆盖、挂牌、原文证据和原有语言行。回补只读取当前数据库，不调用供应商或翻译服务。

使用包含当前公开文本规则的 API 成品，并确认唯一供应商 worker 已切至同版。通过已有的私有 `DATABASE_URL_FILE` 和正式发布环境向命令提供目标数据库。命令还会检查 `--database` 与连接内的实际库名一致。在 API 成品目录运行，数据库名称用实际批准的目标替换。

```sh
node dist/external/search-reproject-cli.js --apply --database hd_release_NAME --limit 25
```

单次最多处理 100 个已发布索引候选挂牌位置，按内部 UUID 升序访问。`scanned` 包括本批经过但不属目标供应商的挂牌，`changedRows` 以实际变更的语言行计。`nextCursor` 是已提交批次的最后位置，适合在运维收据中保存。下次在相同目标和版本上追加 `--after <nextCursor>`。`nextCursor` 为 `null` 表示已走完。先从默认 25 开始，在批次间按现有运维限制留出间隔。

每批跟供应商正常写入使用同一事务锁。拿锁超时或发生其他失败时，命令退出且不输出新游标。继续时使用最后已收到的成功游标。若数据库已经提交但外部中断导致收不到游标，重跑前一批也安全。命令只更新确有差异的语言行，重放和无变化批次不会推进缓存版本。含变化的提交同时更新目录和筛选的版本。

完成后用事先准备的脱敏断言确认已知历史敏感词不再匹配该挂牌，并保留品牌、车型和本站查车编号的正常匹配结果。该回补修复存量搜索词，不改变原始供应商记录的保留策略。

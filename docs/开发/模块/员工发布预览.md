# 员工发布预览

FE-ADPREVIEW-10，2026-11-12。用于 AD 发布前核对员工录入车辆。实现与验证见[本轮日志](../../日志/2026-11-12/前端-FE-ADPREVIEW-10-员工受控发布预览.md)，真实三端集成按 PM／OPS 的候选版本记录核对。

## 路由和应用边界

- 官网提供 `/staff/vehicles/{encodeURIComponent(vehicleId)}/publication-preview/?locale=zh|en|ru&loadId={UUID}`。AD 使用 `URLSearchParams` 构造查询；查询只包含语言和预览实例，不能包含草稿正文、凭据或令牌。
- `(staff-preview)` 是独立根布局，不装配公开站导航、页脚、留资弹框、联系、收藏、分享和费用计算入口。`src/proxy.ts` 的保留前缀包含 `staff`，不能将其当成未知语言重定向或拒绝。
- `modules/publication-preview` 管理参数、认证读取、状态和 iframe 生命周期，经 `vehicles` 公共入口复用图库、事实、历史及价格展示。缺失草稿不能转成 `PublicVehicle`，也不能从公开端点补齐。
- `@hd/contracts/admin` 的 `PublicationPreviewResponseSchema`、`PublicationPreviewFrameMessageSchema` 是跨端合同，BE 维护。官网严格解析，并核对车辆 ID、根语言和每项文字的 requestedLocale。实际 contentLocale、翻译来源和审核状态保留。

## 读取和显示

首个 HTML 只包含通用加载界面，不包含私有车辆资料。浏览器以员工同源会话 GET `/api/v1/admin/vehicles/:id/publication-preview?locale=...`，使用 `credentials: same-origin`、`cache: no-store`、禁止重定向。预览图片继续 GET 同源 `/api/v1/admin/media/:id/preview`，不发布私图地址，也不调用公开图片失败回报。

只有专用 DTO 中 ready 且有 URL 的图片参与图库，缺失项保留提示。价格分别表达缺失、合法零值、待询及汇率不可用；缺失金额保留币种，不以零替代。文字展示真实值、实际语言及 missing／pending／approved／stale，保留 original／machine／human／catalog 来源。BE 当前员工副本 DTO 不含外部详细配置和检测报告，FE 不从自动外部目录拼入这些块。

401／403／404／409 和读取失败采用三语粗粒度状态，错误不显示服务端原文或私有响应。请求有 15 秒期限和卸载取消。语言／车辆／实例变化期间隔离旧状态，防止旧车辆闪现；失败、离开页面后清空就绪状态。错误会终止当前实例，使用 AD 的“重新载入预览”创建新 loadId；iframe 不提供沿用旧 loadId 的局部重试。

### 图片就绪门槛（P2-INT-01）

专用图库回调观察真实当前图片 DOM 的 `decode()`，不使用缩略图或旧缓存状态作为凭据。必需封面成功解码后，当前展示的主图或全屏图也成功解码，才允许发送 ready。首次封面未解码前，staff 模式锁住切图、缩略图原生跳转、键盘／触摸切图和打开大图，保留当前封面的 15 秒期限。公开图库未传回调，保留原体验。

之后每次有效选图或主图／全屏切换先发送 loading 撤销旧回执，再等待当前图片真实解码。初始请求已发送 loading，初始图及同一 pending 图片的重复回调不重复发送；resize 不延长期限。只检查实际请求和展示的图片，不强制并发下载离屏相册。

图片请求失败、解码失败、15 秒超时或缺少可读封面都发送 `error/render_error`，当前实例终止。已知草稿和图片占位仍可读，但不能确认；后续旧 onload／onerror／decode 不能恢复资格。切图、重试、当前展示面和卸载都有独立清理，图库自身也锁定终止状态。AD 必须清除其旧计时并与 loading／ready 阶段一致，不能让固定初载计时器误杀后续切图。

## iframe 版本协议

仅嵌入时向 `window.parent` 发送官方 Schema 校验通过的消息，targetOrigin 固定为当前 `window.location.origin`。

共同字段为 `schemaVersion: 1`、`type: hd:auto:publication-preview`、`vehicleId`、`locale`、`loadId`。事件：

- `loading`：本次读取或有效的当前图片切换开始，撤销旧回执。同一 pending 阶段的重复回调不重复发送。
- `ready`：对应真实 DOM 提交，封面及当前可见图片已成功解码，并经过一帧检查后，携带 GET 返回的 `preview: { vehicleId, vehicleVersion, publicContentRevision, fingerprint, locale }`。请求成功、iframe load 或占位图片都不能代替实际渲染。
- `error`：粗粒度错误码，清除父页就绪资格。
- `disposed`：页面离开或实例销毁，清除父页就绪资格。父页自身必须在换车、换语言、版本变化和重建 iframe 前清除旧资格，不能依赖卸载消息必达。
- `resize`：ResizeObserver 测量实际内容，整数高度限制在 240～16000。只调整框架高度，不清除或建立就绪资格。

AD 校验消息来源 origin、`event.source === iframe.contentWindow`、官方 Schema、当前 loadId／车号／语言及版本指纹；旧实例消息丢弃。AD 由员工明确操作提交确认；BE 负责实际发布条件、人员与版本绑定、过期和并发。FE 不发送确认，也不把可显示的草稿当成可发布。

## OPS 同源接入

正式官网和后台域不同。iframe 必须使用**后台域相对路径**，不能指向 cars 域并假设员工 Cookie 跨域共享。本机为统一 3363 入口；生产应由后台域的代理分流：

| 请求 | 接收方及要求 |
| --- | --- |
| `/staff/vehicles/.../publication-preview/` | 本轮官网 Node／standalone，保持查询与真实状态码；禁用代理缓存 |
| `/_next/static/*` 及实际 `/_next/*` 运行资源 | 同一官网构建的资源，后台 Vite 资源路径保持原有归属，不能用旧构建文件补齐 |
| `/api/v1/admin/*`，包括 preview 和私有图片 | BE，保留员工认证、原 Cookie Path 和权限检查；禁止落到公开 BFF 或直接暴露媒体目录 |
| `/admin/*` | AD 原应用 |

预览 HTML 的响应策略为 `Cache-Control` 含 `no-store`、`X-Robots-Tag: noindex, nofollow`、`Content-Security-Policy: frame-ancestors 'self'`、`X-Frame-Options: SAMEORIGIN`、`Referrer-Policy: same-origin`。Next 可能组合自己的动态缓存头；验证实际响应而非只读配置。代理不能追加会阻断同源 iframe 的 DENY 或 `frame-ancestors 'none'`。预览不加入 sitemap。

## 验证范围

`read-preview.test.ts` 验证参数、认证请求、范围及严格响应；`publication-preview-presentation.test.ts` 验证缺失／零值／待询和私图映射；`tests/publication-preview.spec.ts` 使用隔离 fixture 及真实 Chrome iframe，覆盖三语窄屏、空 HTML、权限、错误、价格、文字状态、旧请求与 disposed。

该浏览器套件只把专用管理 GET 转发到健康标记核验后的本机 fixture，Cookie 仍由浏览器真实发送。它不是实际 AD／API／数据库闭环。真实三端还须在包含 BE `0014` 的隔离数据库中验证登录、私图、版本变更、明确确认和发布门槛，再按 PM 授权切换 3363。检查通过不代表已经部署或用户已经验收。

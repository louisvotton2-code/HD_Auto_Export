# 车辆接口与数据约定

契约 v0.1.0｜2026-11-08｜BE-01/02 已建立本地 API 和公共契约，待 FE/AD 联调。本文明确区分首批已实现能力与 G3 等后续约定；未接真实第三方、翻译服务或生产环境。

配套：[API 运行说明](../../apps/api/README.md)、[公共契约与样例](../../packages/contracts/README.md)、[后端架构](后端架构.md)、[后端任务书](../协作/后端.md)。后端维护契约；类型从 schema 推导，OpenAPI 从实际路由生成，不维护三套手写类型。

## 1. 模块与访问原则

- 公共 DTO、枚举、运行时 schema 与 fixtures 已落入 `@hd/contracts`。API 已消费；FE/AD 接入时显式声明 workspace 依赖，从 `@hd/contracts/public`、`@hd/contracts/admin` 或仅开发使用的 `@hd/contracts/fixtures` 导入，不深引源码。
- `contracts` 必须浏览器安全，不包含数据库、服务密钥、React、API 实现或启动时网络副作用。数据库模型、库存／发布业务、鉴权和媒体服务仅在 `apps/api/`；公开 DTO 不等于数据库实体。
- 官网 SSR 和浏览器、后台均通过 HTTP 使用 API。SSR 可用内网服务地址，但不得 import API 源码或直接连库；浏览器使用部署约定的公开 API／代理。路径 `/api/v1/` 是业务接口前缀，不表示它属于 Next Route Handler。
- 现有 `apps/web/src/modules/vehicles/index.ts` 仍服务官网展示和 demo；不往该出口加入数据库或密钥，也不把 demo Vehicle 当真实 DTO。FE 实现显式展示映射。
- 公开 DTO 用允许字段构造，不展开数据库行或供应商原始 JSON。管理端入口及 API 都校验员工身份与权限，最终权限由 API 强制；不存在 `admin=true` 绕过。未来 AI 只调用受控工具接口。
- API、官网与后台可独立发布，契约变更须声明版本／兼容性，提供 schema、fixtures 与受影响消费者清单。破坏变更先安排兼容期或协调发布，测试所有受影响消费者；不能把共享源码存在当作部署版本自动同步。
- 本地代理与登录约定见第 8 节；生产域名与反向代理仍须 OPS 实测。跨应用不自动允许跨域，CORS 默认关闭。

## 2. 车辆事实与来源

| 字段／概念 | 约定 |
| --- | --- |
| `id` | 自有不变标识，人工和外部均映射为不冲突的字符串；URL 不以车型名称作唯一依据 |
| `stockCode` | 人员可读的稳定询盘编号，后台唯一；不等于拥有该库存 |
| `source.kind` | `manual` 为员工维护的真实车记录；`external` 预留外部来源；`demo` 为明确展示样例、非实际库存。demo 不得伪装成 manual，见第 9 节 |
| 来源映射 | 内部保存 provider＋upstreamSource＋externalId 的唯一组合；不能仅凭外部数字 ID 去重 |
| `make`／`model`／`trim` | 规范 ID 与展示名分开；缺配置保留 null，不拼造车型 |
| `modelYear` | 年款，可为 null；不是制造时间 |
| `manufacturedAt` | `{ value, precision: year/month/day }` 或 null，严格按精度校验 |
| `firstRegistration` | 与制造日期独立，保留精度；缺失不代表从未登记 |
| `registrationStatus` | `never_registered`／`registered`／`unknown`；不凭里程判断新车 |
| 车况与动力 | mileageKm、powertrain（petrol/diesel/hev/phev/erev/bev/lpg/other/unknown）、engineCc、powerKw、body、transmission；缺失 null，单位固定 |
| `location` | 国家／城市及可公开所在地；供应商联系人留内部 |
| `availability` | `available`／`reserved`／`sold`／`unknown`；不与发布状态混为一谈 |
| 核验时间 | 人工 `availabilityCheckedAt` 与供应商 `sourceUpdatedAt`、本次 `fetchedAt` 分开；UTC ISO 时间，UI 显示有时区的时间 |
| 翻译 | `zh/en/ru` 内容及各自审核状态；用户提供的信息、翻译和系统枚举标签分开 |
| 图片 | id、排序、封面、alt、宽高、公开 URL；内部另存 objectKey、来源／许可、原图状态；外部 URL 有效期单独记录 |

金额一律十进制字符串＋ISO 币种，例如 `{amount:"23500.00",currency:"USD"}`，不使用浮点数计算金额。

- 内部成本／供应商挂牌参考价／公开展示价格／客户报价四者分开，不从一个字段静默推算其余字段。
- 公开价格为 `{kind:"asking"|"reference"|"on_request", money:Money|null, includes:string[]}`；`on_request` 的金额为 null。参考价在 UI 必须有语义提示。
- 若提供换算，附原币值、汇率来源和时间；不得换币种标签而不换金额。跨币排序必须有明确同一口径；G1/G2 默认只做发布时间排序，价格全局排序不作为验收范围。
- 不把 API 的可出口标志变成已核验资格，不向计算器补造制造日期、排量或功率。
- 公开 DTO 不含采购成本、内部备注、供应商联系方式、员工信息、凭据、完整 VIN、原始 JSON。需要增加公开字段先改契约并检查用途。

## 3. 草稿、发布与库存状态

一个车辆聚合包含可编辑草稿和已发布快照。建议分别保存 `draftRevision`、`publishedRevisionId`、`publicationState`、`version`，不以一个公开对象边编辑边覆盖。

1. 创建后为 `draft`，仅管理接口可读。
2. 保存编辑只改草稿；已发布车继续展示上一个发布快照。
3. 发布前检查必需字段、三语显示、封面图片可用、来源／公开价格口径和库存核验信息。首次发布与更新发布都在事务中生成不可变快照、更新指针和审计。
4. 真实 manual 车辆发布状态为 `published` 且 `availability=available` 才能进入首页推荐；目录显示 available／reserved，预订明确标记。第 9 节明确的 demo 样例可在 unknown 库存下展示，不能套用真实库存标签。
5. 标记 sold：立即退出首页和在售列表；原详情可保留已售提示与“咨询类似车辆”，不得继续当现货销售。库存状态以车辆主记录为准，独立于内容快照；此状态变更优先于未发布的描述草稿，必须立即影响线上。发布旧草稿不能隐式把 sold 改回 available，恢复可售必须执行明确的库存状态操作。
6. 下架 `archived`：立即撤销公开快照访问、推荐和缓存，公共详情/API 返回真实 404；后台保留历史。重新上架须重新校验并明确发布。
7. 不在首期提供永久删除；草稿垃圾图清理与已发布图引用保护分别处理。停售／下架导致的旧图片缓存要按内容和许可处理，不能以数据库删除代替 CDN 清理。

车辆修改、发布、库存和下架携带车辆 `version`；首页携带首页版本，媒体操作携带媒体版本。新建车辆和申请上传任务没有旧版本。冲突返回 409；创建及发布必须携带幂等键，具体规则见第 8 节。

## 4. 公共接口（首批已实现）

| 方法与路径 | 行为 |
| --- | --- |
| `GET /api/v1/home/vehicles?locale=ru` | 返回有序 `sections[]`，含已发布可售 manual 与明确标记的已发布 demo；无车组隐藏，不自动用演示数据填空 |
| `GET /api/v1/vehicles?catalog=curated&locale=ru&page=1&pageSize=24` | 精选目录，品牌／车型／动力筛选；发布时间倒序并以 id 作稳定次序 |
| `GET /api/v1/vehicles/{id}?locale=ru` | 公开详情；不返回草稿和内部字段；不存在／下架为 404，临时上游错误为 503 |
| `GET /api/v1/vehicle-filters?catalog=curated&locale=ru` | 对应目录实际支持的筛选字典，不混入另一目录数量 |
| `GET /api/v1/media/{id}` | 仅有当前有效发布引用的展示图片；草稿／下架后无引用为 404 |

G3 才增加 `catalog=market` 和选定供应商支持的筛选／排序；对外不要求访客知道供应商名字。阶段未开放时网站隐藏入口，接口对未支持目录返回明确错误。

详情路径保留现有 `/{locale}/cars/{slug}/` 外形，正式 slug 使用稳定 id 或带稳定 id 的不变段；canonical 与接口返回的 `detailPath` 一致。原 demo 不能悄悄指向别的真实车；演示留在隔离环境或下线，按前端任务书处理。

列表响应约定：

```json
{
  "data": { "items": [], "page": 1, "pageSize": 24, "hasMore": false },
  "meta": {
    "requestId": "example-only",
    "catalog": "curated",
    "total": 0,
    "totalKind": "exact",
    "accessibleTotal": 0,
    "dataAsOf": "2026-11-07T00:00:00Z",
    "freshness": "fresh"
  }
}
```

这是空列表结构样例，不是真实业务数据。`totalKind` 可为 exact／provider_reported／unknown，未知 total 为 null，不能伪填 0。`accessibleTotal` 表示可分页范围；外部总量有缓存延迟或访问上限时与 total 分开。`freshness` 为 fresh／stale，stale 必须在许可和最大保留期内且前台有提示。`pageSize` 公共上限 48；上游限制更严时取更小值。非法参数返回 400，超限查询不能生成无效下一页。

G3 若上游只支持游标，适配器须提供受限页映射或在契约版本中统一增加游标，不能假装能够任意跳页。价格筛选注明实际币种；跨源首期不混排。

## 5. 管理接口（首批已实现）

业务前缀 `/api/v1/admin`，由独立 API 提供；员工 UI 为 AD 维护的独立应用，默认中文。登录使用 Better Auth `/api/auth/*` 原生协议，见第 8 节。

| 方法与业务路径 | 行为 |
| --- | --- |
| `GET /api/v1/admin/me` | 当前员工、角色与权限；未登录 401 |
| `GET /api/v1/admin/vehicles` | 按草稿／发布／库存状态查询管理列表 |
| `POST /api/v1/admin/vehicles` | 创建草稿，返回 id、stockCode、version |
| `GET /api/v1/admin/vehicles/{id}` | 返回当前草稿、车辆状态和发布版本指针；当前线上内容另用 public 详情比较 |
| `PATCH /api/v1/admin/vehicles/{id}` | 按 version 更新草稿，不隐式发布 |
| `POST /api/v1/admin/vehicles/{id}/publish` | 校验并原子发布当前草稿 |
| `POST /api/v1/admin/vehicles/{id}/availability` | 立即更新库存状态与核验时间 |
| `POST /api/v1/admin/vehicles/{id}/archive` | 下架并从公开视图撤下 |
| `GET/PUT /api/v1/admin/home/vehicle-sections` | 两个首页车源区块的标题、车辆 ID 与顺序；校验车辆可展示及版本 |
| `POST /api/v1/admin/media/uploads` | 鉴权后生成限时、限制大小和类型的上传许可／任务 |
| `GET /api/v1/admin/media/{id}` | 上传状态及当前媒体版本，供断网恢复确认 |
| `PUT /api/v1/admin/media/{id}/content` | 发送图片二进制，以 `If-Match` 携带媒体版本 |
| `POST /api/v1/admin/media/{id}/complete` | 服务端核验真实文件、处理图片后才变为可发布媒体 |
| `GET /api/v1/admin/media/{id}/preview` | 员工鉴权后的已处理草稿图预览 |
| `DELETE /api/v1/admin/media/{id}` | 仅允许未被发布快照引用的媒体进入回收流程 |

账号首期仅员工，不开放公众注册。管理员负责账号启用／禁用，编辑员可录入和发布车辆；账号管理采用所选鉴权库配套能力或受控管理员命令，首期不强制开发账号管理大页面。员工禁用后会话及时失效；两种角色的权限矩阵由后端维护并测试。

图片接受 JPEG／PNG／WebP，原始单文件上限 10 MiB、解码 4000 万像素、展示最长边 2400；拒绝动画，转 WebP 并去除元数据。每个草稿最多 30 张，待上传和未引用图片也占当前配额；仅历史引用且已移出草稿的图片不阻碍替换。历史引用保护文件不被硬删。原始请求不长期存盘，处理图仍私有；公开入口验证当前发布引用。上传许可 30 分钟，过期无引用任务可由清理命令回收。禁止任意 URL 下载。

## 6. 错误、缓存与审计

统一错误 `{error:{code,message,fields?,retryable},meta:{requestId}}`；UI 根据 code 翻译，不展示数据库栈或供应商响应原文。400 参数非法，401 未登录，403 权限不足，404 不存在／不可公开，409 版本冲突，413 文件过大，422 发布业务校验失败，429 限流，503 上游或服务暂不可用。429/503 可返回 Retry-After，客户端不得无限重试。

- 管理、登录、草稿和含内部字段的响应统一 no-store；鉴权依赖成熟库并落实 HttpOnly/Secure Cookie、CSRF／Origin 校验、登录速率限制和最小权限。
- G1 公共精选查询可先 no-store，证明发布立即可见；G2 引入缓存时必须有明确失效机制和可见性时限。发布／下架完成后新请求应读到新状态，不能靠固定几小时 TTL 掩盖发布不生效。
- 第三方缓存按供应商许可单独设置 TTL、最大 stale 时间和删除策略；上游时间、抓取时间、缓存过期时间分别记录。并发相同查询合并，设置超时与总调用预算。
- 审计记录 actorId、operation、vehicleId、旧新版本、requestId、UTC 时间；日志不记录密码、密钥、完整客户消息或上传签名。
- 首期统计事件可先定义 vehicle_view／contact_click，真实采集随 G4 完成；不要把定义或浏览器 console 输出说成统计系统已经上线。

## 7. 最小数据实体与数据库约束

首批迁移包含鉴权表、`vehicles`、`vehicle_drafts`、`vehicle_publications`、`media_assets`、`publication_media`、`home_config`、`audit_events` 和 `idempotency_keys`。首页两组配置以单个版本化聚合保存；来源映射／缓存／计量表在 G3 建立，不为 AI／CRM 预建空表。

首批数据库保证车号唯一、媒体引用外键和发布快照不可变；服务校验金额非负、支持币种，并在锁与事务内递增版本。发布事务同时写入快照、当前发布指针和审计，失败整体回滚；首页读取实时过滤发布与库存状态，不修改人工排序配置。来源三元组唯一约束在 G3 来源映射建立时实施，缓存失效事件在引入缓存时实施。缓存无需和主库事实同等长期备份；精选和发布历史须可恢复。

G0 必须提供可用于消费者开发的 fixtures：草稿、公开可售、待询价、预订、已售、下架、缺制造日期、图片失败、版本冲突；G3 再补空结果／限流／上游故障／过期缓存。样例与真实运营数据隔离。

## 8. FE／AD 可直接使用的 v0.1.0 约定

### 环境、登录与响应

本地联调约定官网 3317、后台 3318、API 3320；官网可用 `pnpm --filter @hd/web dev --port 3317` 启动，普通 `pnpm dev` 仍使用 3000。后台将浏览器相对地址 `/api` 代理到 API。生产规划 `/admin/` 承载后台静态产物、`/api/` 转发独立 API；实际域名由 OPS 配置。官网 SSR 只调用公开 HTTP，不携带员工 Cookie。

| 接口 | 输入／行为 |
| --- | --- |
| `POST /api/auth/sign-in/email` | JSON `{email,password}`，可信 Origin；返回并设置 Cookie |
| `POST /api/auth/sign-out` | JSON `{}`，Cookie＋Origin；撤销当前会话 |
| `GET /api/auth/get-session` | Cookie；使用 Better Auth 原生会话响应 |
| `GET /api/v1/admin/me` | 推荐给后台判断角色与业务权限的精简响应 |

鉴权路径保持 Better Auth 原生响应及错误，不能套业务 envelope。其他 JSON 成功响应为 `{data,meta:{requestId}}`，列表另有分页信息；业务错误 `fields` 为 `{path,code,message}[]`，如 `draft.content.title.translations.ru`。所有响应 no-store。客户端用 code 翻译提示，401 回登录，403 拒绝操作，409 保留本地编辑并重新取当前版本，422 定位发布缺项；不无限重试 429/503。

管理员、编辑员均可读取和维护车辆、媒体、发布及首页；仅管理员具有 `staff:manage` 业务权限。首批账号管理通过受控本地命令，不暴露管理员插件的注册、模拟身份或删除端点。管理请求的鉴权绑定服务器实际匹配路由，路径编码不能绕过。

员工后台支持完整邮箱或短账号。短账号由公共契约 `staffLoginEmail` 映射至 `staff.hd-auto.invalid` 域，再按原形状调用 `/api/auth/sign-in/email`。`staff change-login` 保留员工 ID 和角色，原子更新登录名、密码及会话。该命令不会随构建或启动自动执行。

后台的官网展示核对读取上表之外的公开首页、列表与详情接口，核对的是当前已发布快照。未发布或已下架的车辆在管理端可读，但其公开详情按契约返回 `404 NOT_FOUND`。页面应区分这种正常结果和路由／代理错误。

### 请求形状、版本与幂等

- 创建：`POST vehicles` 发送 `{draft: VehicleDraftInput}`；草稿包含 `source/facts/price/content/media/internal`，完整字段与样例从 contracts 读取。接受 `source.kind=manual|demo`，demo 的非库存约束见第 9 节。
- 保存：`PATCH vehicles/{id}` 发送 `{version,draft}`，完整替换草稿，不是任意 JSON Patch；库存不在 draft 中。
- 发布／下架：`{version}`；库存：`{version,availability,checkedAt}`，UTC 核验时间不接受明显未来时间。
- 创建和发布必填 `Idempotency-Key`（8–128 字符，字母数字及 `_.:-`）；范围为员工＋操作＋车辆（发布时），保留 24 小时。同键同内容返回原业务结果，同键不同内容返回 409。重试必须复用原请求；超过保留期先查询结果再决定是否新建。
- 首页：`GET/PUT` 使用 `{version,sections:[{id,title:{zh,en,ru},vehicleIds}]}`，固定两组，每组车辆可为空，组 ID 及每组内车辆不重复；每组最多 30 辆。公开首页隐藏无有效车辆的组。首次创建的默认组为 `featured/recent`。
- 真实车辆、媒体及发布 ID 使用 UUID；品牌、车型和首页组使用规范字符串 ID。fixtures 的 `fixture_*` 仅供界面开发，不是可调用的真实资源 ID。
- 分页默认第 1 页、每页 24 条，上限 48，支持 `make/model/powertrain`。只支持 curated；无数据是真实空列表，超出页数返回空 items/hasMore=false。不接受任意排序或跨币价格排序。
- 管理列表 `GET /api/v1/admin/vehicles` 支持 `q/make/model/powertrain/publicationState/availability/page/pageSize`。`q` 去除首尾空白后最多 100 字符，不接受 NUL；空值等于不搜索。按稳定车号、当前草稿品牌名/车型名和标题原文做不区分大小写的字面子串匹配，`%`、`_`、反斜线不作通配符，不搜索 VIN、内部备注或联系方式。`make/model` 是规范 ID 精确匹配，`powertrain` 使用公共枚举；所有条件组合为 AND，先过滤再计算 total 和分页，仍按创建时间降序及 ID 稳定排序。变更条件时 AD 应回到第 1 页；清空条件恢复完整列表。示例：`?q=HD-000001&make=toyota&powertrain=bev&page=1&pageSize=24`。管理筛选使用当前草稿，公开列表继续使用已发布快照；本轮不新增公开关键词搜索。
- 金额最多 14 位整数、2 位小数，币种清单由 `CurrencySchema` 维护；缺制造日期、首次登记、排量、里程保持 null。待询价的 money 必须为 null。

### 三语与发布门槛

每个可翻译字段保存 `{sourceLanguage,sourceText,sourceVersion,translations:{zh,en,ru}}`。目标译文包含 `text/kind/reviewStatus/sourceVersion/humanEditVersion/engineVersion`。原文语言可为 ko、zh-CN 等语言标签，首期展示语言固定中英俄。`original` 只允许基础语言匹配且文本与原文完全一致，例如 zh-CN 可作为 zh 栏的原文；公开 `contentLocale` 保留 zh-CN，`requestedLocale` 仍为 zh。若员工改写或转换字形，改为 human 并审核，不冒充原文。

保存时保留服务返回的版本。修改原文会提升来源版本并把已有译文标为 stale；普通重保存允许保留 stale 文本。审核新原文时，目标译文须显式使用当前 sourceVersion 并提交 approved；服务维护人工版本，旧版本写入返回409。修改价格而文本未变不会增加原文版本。当前是员工内容管理，不执行翻译任务。

manual 发布要求：品牌、车型、所在地国家、原文标题；三语标题均非空、已审核且对应当前来源；如有描述则描述三语同样就绪，无描述可全部null；一个可用封面、全部引用图片处理完成且属于本车；图片使用依据已记录；来源与价格类别合法；库存已明确核验。未知制造日期和里程不是发布障碍，不补造数据。demo 采用第 9 节非库存、未声明人审的独立门槛。

公开文本只返回 `{text,requestedLocale,contentLocale,kind,reviewed}`。`kind` 是 original/machine/human，独立 `reviewed` 表示是否经人工审核，机器译文经审核后仍保留 machine 来源。内部版本、引擎信息和原始资料不公开。未来市场目录允许机器译文自动展示并标注，标题未就绪不进入对应语言目录、描述可省略；本期精选不做静默语言回退。

### 图片上传顺序

1. 创建车辆后申请上传：`{vehicleId,filename?,contentType,sizeBytes,rights:{basis:'owned'|'permission',note}}`。note 必须说明自有来源或授权依据，内部保存，不进入公开 JSON。
2. 响应提供 media（含 version）、method=PUT、uploadUrl 和 expiresAt。上传二进制，带原图 Content-Type、Cookie、Origin 与 `If-Match: <media.version>`；实际大小和格式须与声明一致。
3. 上传返回 uploaded 状态和新媒体版本；随后 complete 发送该版本，成功后为 ready。断网时先 GET 媒体状态，避免盲目重复上传。
4. 把 ready 图片 ID、alt、sortOrder、isCover 写入车辆 draft，再发布。ready 只是可用于发布，匿名读图仍要检查当前发布引用。
5. 删除用 `{version}`；草稿引用须先移除，发布历史引用永远阻止本期物理删除。替换图片时先从草稿移除旧图，旧线上快照继续可读，新发布才切换图片。处理完成但未绑定草稿的图片保留24小时，之后可由清理命令回收；有草稿或历史引用的图片受保护。

### 有界批量库存与下架

`POST /api/v1/admin/vehicles/bulk`，员工 Cookie＋可信 Origin＋`Idempotency-Key`。请求为 `BulkVehicleMutationRequest`：

```json
{
  "operation": "availability",
  "availability": "sold",
  "checkedAt": "2026-11-08T08:00:00Z",
  "items": [
    { "id": "11111111-1111-4111-8111-111111111111", "expectedVersion": 3 },
    { "id": "22222222-2222-4222-8222-222222222222", "expectedVersion": 7 }
  ]
}
```

下架为 `{operation:"archive",items:[...]}`，不发送 availability/checkedAt。每批 1–50 条，UUID 重复（含大小写变体）、非法行、超限或明显未来 checkedAt 整批 400，不执行。只处理 items 中明确选中的 ID，不接收“全部匹配”或任意条件批量操作。

成功处理请求返回 HTTP 200，`{data:{operation,results,summary:{total,succeeded,failed}},meta}`；**200 不代表全部成功**。`results` 按输入顺序逐行返回：

- 成功：`{id,status:"succeeded",version,publicationState,availability,availabilityCheckedAt}`。
- 失败：`{id,status:"failed",error:{code,message,retryable:false}}`；code 为 `NOT_FOUND`、`VERSION_CONFLICT` 或 `DEMO_RESTRICTION`。不存在、版本冲突或演示库存限制仅影响对应行；不能把失败行显示为完成。

按规范化 ID 排序锁行，保持与单车操作相同的版本/审计/公开可见规则；已成功行一次提交，业务失败行不改动。遇到数据库/审计等未知故障整批事务回滚，返回标准 5xx，不返回伪造成功结果。

幂等范围为员工＋`vehicle.bulk`＋key，整个请求（包括 operation、items 顺序、版本及库存时间）参与 hash，保留 24 小时。相同 key/相同请求精确重试返回原逐行结果，不重复递增版本或写审计；同 key/不同请求 409。重放结果是原操作结果，不承诺代表当前状态。失败行需重新读取、确认选择与版本后用**新 key**提交；不得自动覆盖新版本。不同 key 也不能绕过 expectedVersion。超过保留期先重新查询。

### 后台品牌与品牌内车型选项

`GET /api/v1/admin/vehicle-filters?make=<可选品牌ID>`，Cookie 鉴权，读取所有当前草稿（含 draft/published/archived、manual/demo），不携带成本/联系方式等字段。响应为 `AdminVehicleFiltersResponse`：

### 官网读取、图片与首页配置

## 10. BE-INT-03 回收站、人工外部挂牌与公开搜索

### 车辆回收站

- 管理车辆响应新增 `deletedAt: string | null`（UTC 时间）；旧响应未带此字段时 contracts 解析为 null，兼容保留期内的旧幂等回执。

- `DELETE /api/v1/admin/vehicles/{id}` 和 `POST /api/v1/admin/vehicles/{id}/restore` 都发送 `{version}`，必填 `Idempotency-Key`，沿用员工 Cookie、可信 Origin 与版本校验，成功 HTTP 200 返回完整 `AdminVehicleResponse`。请求 schema 分别为 `DeleteVehicleRequestSchema`、`RestoreVehicleRequestSchema`；详情查询为 `AdminVehicleDetailQuerySchema`。
- 删除后普通列表与筛选字典不包含该车，普通详情、修改、发布、库存、下架、公读及媒体访问均按不存在返回 404；仅上述回收站列表／详情可读。删除事务移除全部首页配置中的该车引用，仅当配置实际变化才将首页 version 增加 1；保留发布历史和媒体，不执行物理删除。
- 恢复清除 deletedAt，设为 `publicationState=draft`、`publishedRevisionId=null`、`publishedAt=null`、`availability=unknown`、`availabilityCheckedAt=null`，车辆 version 增加 1。历史和草稿保留，但不会自动重新发布或加回首页；manual 须重新核验库存再发布。
- 使用新 key 再次删除已删除车辆返回 404；恢复未删除车辆返回 409 `VERSION_CONFLICT`。同 key、同请求在 24 小时内重试返回冻结的原回执，不重复修改当前状态；同 key、不同内容返回 409 `IDEMPOTENCY_CONFLICT`。成功或重放后客户端应重新读取当前状态，不能把历史回执当成当前快照。旧 create／publish 等幂等回执也可能描述现已删除的车辆，这只是无副作用的历史回执兼容例外。

### 外部来源录入与公开投影

草稿 `source` 按 kind 严格区分；manual／demo 仍只传 `{kind}`，external 必须传完整元数据：

```json
{
  "kind": "external",
  "platform": { "id": "example-market", "name": "Example Market" },
  "listingUrl": "https://example.invalid/listings/synthetic-001",
  "externalId": "synthetic-001",
  "collectedAt": "2026-11-08T08:00:00Z",
  "sourceUpdatedAt": null
}
```

此例只供开发，非运营数据。platform.id 沿用规范 ID；name 为非空白、最多 120 字符；externalId 为平台内挂牌 ID 或稳定身份，非空白、最多 300 字符。listingUrl 最多 2048 字符，只允许 HTTP(S)，不含用户名／密码；不接受任意下载指令。collectedAt 必填 UTC 时间，sourceUpdatedAt 是上游更新时间，未知为 null，两者不能混用。

- source.kind 创建后不可变；external 的 platform.id／externalId 同样不可变。来源身份 `(platform.id, externalId)` 在包含回收站的全部车辆中唯一，重复返回 409 `SOURCE_IDENTITY_CONFLICT`；此约束不应用于 manual／demo。切换来源类型违反相应来源限制，返回 422 `DEMO_RESTRICTION` 或 `EXTERNAL_RESTRICTION`；external 身份变更返回 422 `EXTERNAL_RESTRICTION`。
- external 价格只允许 `reference` 或 `on_request`（后者 money=null），禁止 asking。可保存已观察到的实车事实，未知保持 null，不能套用 demo 的无实车字段规则；external 库存始终 unknown，availabilityCheckedAt=null。单车库存请求返回 422 `EXTERNAL_RESTRICTION`；批量库存逐行返回同 code、retryable=false，不自动调整版本。原有 NOT_FOUND／VERSION_CONFLICT／DEMO_RESTRICTION 逐行错误仍有效。
- external 发布需要来源元数据、品牌／车型、当前源版本三语非空标题；有描述时三语同样就绪。译文允许 pending／approved，拒绝 stale／旧来源版本；original 必须与原文文字完全一致且基础语言匹配。需一个 ready 封面、全部图片 ready 且属于本车，以及下节的逐图来源记录。公开文字一律 `reviewed=false`，不能将 Agent 校对或 pending 内容标成人工审核。manual 的三语 approved、reviewed=true 规则保持不变。
- 公开 `source`：manual／demo 仅 `{kind}`；external 为 `{kind:'external',platform:{id,name},listingUrl}`。不返回 externalId、图片依据内部备注或内部资料。公开顶层 `fetchedAt` 对应 collectedAt，`sourceUpdatedAt` 对应上游时间；公开 external 同样只允许 reference／on_request、unknown／null 库存和 reviewed=false。FE 按结构化来源显示外部资料与时间，不将其标为自有现货。
- `makeExternalVehicleDraftFixture()`、`makePublicExternalVehicleFixture()` 提供隔离开发样例，地址只用 example.invalid；中文原文、英俄机器译文均为 pending，公开不宣称人审。fixtures 不代表真实接入或授权。

### 外部图片来源与许可状态

上传的 rights 扩为 `{basis:'owned'|'permission'|'unverified',note,source?}`，note 仍为非空白、最多 500 字符。可选 source 为 `{listingUrl,imageUrl,collectedAt}`，两个 URL 均采用上述 HTTP(S)、2048 字符、无凭据限制，collectedAt 为 UTC 时间。rights 只在员工接口返回，不进入公开图片 JSON。

external 发布时每张图必须有 rights.source，且其中 listingUrl 与车辆 source.listingUrl 完全相同；imageUrl 记录原图来源，不触发服务端下载。unverified 仅表示本地资料的图片使用许可待核验，不代表生产许可已获得。manual／demo 继续执行原有 owned／permission 图片使用依据规则，不能借 unverified 绕过其发布检查。上传二进制、版本、complete、ready 与公开引用权限沿用第 8 节。

### 公开关键词查询

`GET /api/v1/vehicles` 和 `GET /api/v1/vehicle-filters` 都新增可选 q；对应 `PublicVehicleQuerySchema`、`PublicFilterQuerySchema`。去除首尾空白后最多 100 字符，拒绝 NUL，空字符串／纯空白等同不筛选。

q 在稳定 stockCode、已发布快照的当前 locale 标题、品牌 name、车型 name 中进行不区分大小写的字面子串匹配，`%`、`_` 和反斜线不是通配符；不查当前草稿、内部字段或其他语言。列表已有 make／model／powertrain 与 q 按 AND 组合，items、total、hasMore 使用同一条件。更改 q 或分类时 FE 回到第 1 页。BE-INT-03 当时不含范围筛选；后续 I18N02/FEUX04 的展示投影及范围契约见第14节，旧默认投影仍兼容。

### 固定图片缩略图

`GET /api/v1/media/{id}?variant=thumb` 返回宽度上限 240px、等比且不放大小图的 WebP 缩略图（竖图高度可超过 240px）；不传 variant 仍返回原公开图片。`PublicMediaQuerySchema` 只接受可选 `variant:'thumb'`，其他 variant、任意 width／height 参数及未知属性返回 400。图片授权与原图完全相同：未发布、已删除或不再被当前公开快照引用时返回 404，不能由缩略图缓存继续读到。

公开 `images[].url` 继续给原图地址，不新增 thumbnailUrl。FE 可按已知媒体 ID 固定构造 `` `/api/v1/media/${image.id}?variant=thumb` ``；`MediaUrlSchema` 允许这个固定本地查询形式，不允许任意图片变换参数。服务端缩略图缓存为媒体卷中的相对文件 `{UUID}.thumb.webp`，随媒体卷备份；仍通过媒体 API 鉴权读取，不直接公开卷路径。响应沿用 no-store。

## 11. BE-INT-03 分桶限流与可信访客 IP

本节记录 BE-INT-03 的可信访客协议及 BE-EXT-02 的登录、上传和翻译分桶增量。实际启用环境和验证见[后端进度](../协作/后端.md#本角色进度摘要)。

### 请求额度与重试

按API经可信代理解析、归一后的来源IP，在固定类别中计数；不是按车辆ID、图片ID、查询参数或浏览器自选身份计数。

| 类别 | 路径 | 每来源额度 |
| --- | --- | --- |
| 公开JSON | 公开车辆列表／详情、筛选、首页 | 120次／60秒，类内共用 |
| 公开媒体 | `/api/v1/media/{id}`，原图和thumb、GET和HEAD | 120次／60秒，所有图片共用 |
| 普通管理业务 | `/api/v1/admin/*` 中的普通操作，含图片状态和预览 | 120次／60秒，类内共用，仍须员工权限 |
| 上传写入 | `POST /api/v1/admin/media/uploads`、`PUT /api/v1/admin/media/{id}/content`、`POST /api/v1/admin/media/{id}/complete` | 三步共用120次／60秒 |
| 普通翻译建议 | `POST /api/v1/admin/vehicles/{id}/translation-suggestions`、`POST /api/v1/admin/vehicles/{id}/localization/translation-suggestions` | 两条路由共用20次／60秒，并执行原字符及并发限制 |
| 健康检查 | `/health/live`、`/health/ready` | 120次／60秒，独立且有界 |
| 鉴权路由 | `/api/auth/*` | 原30次／60秒保持；Better Auth自身登录规则不放宽 |

类间不挤占额度。管理请求先计额度，再检查身份／Origin，之后才读取上传体；未登录请求也消耗管理桶。IP归一沿用限流组件的IPv4映射和IPv6 `/64` 规则；同一来源IP／网段仍会共享限额，不能声称每个匿名个人都有独立额度。429保留真实 `Retry-After`，缺少值才回退60秒；503保持5秒。FE须保留429及有效等待值，避免把限流统一转换成503；客户端有限退避，不自动重放未确认的写入。

邮箱登录 `POST /api/auth/sign-in/email` 通过 Origin 校验后，另按账号在每个 API 实例内限频。大小写按 Better Auth 规则归一，同一账号跨 IP 共用60秒5次。每实例在滚动60秒内最多接纳120个新账号键，内存只保存 HMAC、计数和到期时点。已登记和未知账号按同样的规则计数，限额耗尽使用同一429格式。外部试译独立使用自己的 HTTP 限额和持久额度账本。

### 唯一可信身份链

1. OPS入口Nginx覆盖 `X-HD-Visitor-IP` 为它观察到的单一客户端IP，覆盖外来 `X-Forwarded-For` 等转发头；不追加浏览器提供的原始链。
2. Web只在服务端 `VEHICLE_API_TRUST_PROXY_IP=true` 且运行入口只能经过受控代理时启用该协议。默认关闭；开启后用严格IP校验读取 `X-HD-Visitor-IP`，拒绝列表、重复合并值、端口和畸形地址，再构造全新、单值 `X-Forwarded-For` 发往API。SSR与BFF复用这项规则，继续不发送员工Cookie或Authorization。
3. API使用 `TRUST_PROXY=<proxyIP>/32,<webIP>/32`，支持逗号分隔两个固定对端；IPv6固定对端对应 `/128`。实际部署不配置全网、动态容器大网段或跳数信任，Web/API不暴露可绕开入口的宿主端口。当前默认false不变。
4. API只依赖Fastify校验的 `request.ip`，不直接消费 `X-HD-Visitor-IP` 或调用者指定的 `X-HD-Client-IP`。非可信直接对端的伪造转发头无效；可信链最终解析为畸形IP或zone地址时，在鉴权和业务前返回400，不使用任意字符串建立新额度。
5. 缺少访客上下文的内部调用不伪造客户端来源，也不免限流，按Web服务地址进入对应有界桶。只修改API信任配置不能恢复FE已经丢弃的客户端身份；FE/OPS链路必须同步接通并验收。

双方协作验收须覆盖：图片用尽后JSON／管理／健康仍可用；更换媒体ID或thumb不能换桶；同一可信访客跨Nginx/Web路径共额度、不同来源IP分开；不可信来源和伪造头不能重置额度；BFF保留429及等待值。API进程内注入测试只能证明API边界，不能代替实际封闭入口与FE链路验收。

## 12. BE-INT-03 同服务器私有图片与 Nginx 交付

按用户后续决定，本机及首期真实服务器均使用同服务器持久化媒体目录，流量增长后再接对象存储。公网图片 URL 和员工预览 URL 不变；调用方不接触磁盘路径。此增量的源码／验证与实际启用状态见[图片交付日志](../日志/2026-11-08/后端-BE-INT-03-04-Nginx私有图片交付.md)。

### 固定协议

| 配置或响应 | 约定 |
| --- | --- |
| `MEDIA_DELIVERY` | API 服务端枚举 `direct`（默认）或 `nginx`，不接受任意 URI；本机原生开发沿用 direct |
| `MEDIA_ROOT` | API 专有持久化目录；目录 0700、文件 0600；只保存处理后的展示图及固定衍生图 |
| `X-Accel-Redirect` | 仅 nginx 模式授权成功后返回 `/_hd_media/<小写UUID>.webp` 或 `/_hd_media/<小写UUID>.thumb.webp`；无查询串、用户输入路径或绝对目录 |
| 成功上游响应 | 200、空响应体、`Content-Type: image/webp`、`Cache-Control: no-store`、`X-Accel-Expires: 0`、`X-Content-Type-Options: nosniff`；Nginx 接管文件内容和长度，HEAD 不返回正文 |
| 访问边界 | 公开读取仍检查 ready、当前发布引用、已发布且未软删；预览仍检查员工身份及未删除车辆的 ready 图片。失败响应没有内部重定向头 |

API 每次先查当前授权，再通过不跟随符号链接的文件句柄验证私有常规文件、单链接和大小；原图及已缓存 thumb 只读元数据，不将图片正文读入 API 内存。thumb 缓存缺失时才从已处理原图生成固定 240px WebP，并原子写入同一目录；即使存在 thumb，原图缺失也返回 404。请求不能选任意尺寸、文件名或外部下载地址。

### OPS 实现要求

- Nginx 只允许内部跳转进入精确白名单文件位置；`internal` 使外部直达返回 404。为 `/_hd_media/` 的其他路径设置拒绝兜底，不能落到官网或自动目录。原图和 thumb 共用媒体请求额度，内部跳转不向 API 发第二次请求。
- API 对媒体卷读写，Nginx 以同一 `APP_UID` 只读挂载；保持 0700/0600，不为方便读取放宽权限。部署前核验宿主映射、目录穿越权限、TLS 私钥权限和备份恢复后的 UID；具体 Compose 路径与 UID 由 OPS 维护，API 不写死机器绝对路径。
- 内部文件位置禁用目录列表、符号链接访问、静态缓存及 `open_file_cache`；所有成功和失败响应保持 `Cache-Control: no-store` 和 nosniff。关闭 ETag、条件修改时间处理和 Range 分片（`max_ranges 0`）；Range 被忽略，不返回分片。每次请求都先通过 API，不能据旧缓存绕过撤销。特殊 HTTP 条件头仍可能由 Nginx 在授权后给出 304／412（如 `If-None-Match: *`），不承诺任何条件请求都返回完整正文；撤销后的请求先在 API 返回 404。
- 不忽略上游 `X-Accel-Redirect`，也不把该内部头透传到浏览器。不得让 Web/BFF 直接消费 nginx 模式 API 的空图片响应；浏览器媒体和员工预览经配置好的 Nginx `/api/` 入口。JSON SSR 可继续直达内网 API，API/Web 不另开放宿主端口绕过入口。
- API 检查时缺文件返回原有 JSON 404；检查后、Nginx 打开前发生删除时，由 Nginx 返回无路径信息的 404，图片错误正文不保证 JSON。不得回退到其他文件或远端 URL。权限／卷故障不可伪装为正常空图片，具体状态由 OPS 的文件错误处理配置和联调核对。
- 撤销／下架后新请求不能拿到内部路径；已经授权且开始交付的在途响应可能完成。不能承诺追回已经发送的字节。备份必须覆盖数据库、发布引用和同一媒体卷，恢复后重新验证权限及撤销行为。

后续对象存储仍以媒体 ID 和固定衍生类型为业务接口，替换存储和发送适配层；权限查询继续由 API 持有，不把供应商 URL 写进车辆事实。若采用签名 URL／CDN，必须单独验证时效、撤销及缓存失效，不能直接放宽当前 no-store 约定。

Nginx 内部跳转和隐藏响应头的依据见[官方代理文档](https://nginx.org/en/docs/http/ngx_http_proxy_module.html#proxy_ignore_headers)，外部访问限制见[internal 文档](https://nginx.org/en/docs/http/ngx_http_core_module.html#internal)。API 注入测试不替代真实 Nginx 的文件发送、权限和断链验证。

## 13. BE-I18N-01 单车译文建议与发布差异

本节为本轮新增实现契约；实际运行启用、独立审查和消费者联调见[BE-I18N-01日志](../日志/2026-11-08/后端-BE-I18N-01-单车机器译文建议与发布差异.md)。用户已授权先实现员工明确触发的单车建议，优先本地 LibreTranslate/Argos；未包含定时采集、后台 worker 或自动发布。

### 已发布快照差异与重复发布

`AdminVehicle` 新增 `hasUnpublishedChanges: boolean | null`。新查询／变更响应都给准确 boolean：比较当前草稿的 source、facts、price、content 以及按 sortOrder 排序的 media(id/alt/sortOrder/isCover) 与当前发布快照；不比较 internal、车辆 updatedAt、availability 或 availabilityCheckedAt。图片派生宽高／服务路径不受草稿编辑，本比较不把它们当待发布修改。无当前快照为 true；archived 保留旧快照时可为 false，但仍允许重新发布。旧幂等回执缺少字段时解析为 null，表示未知，客户端不能把 null 当 false。

已 published 且无待发布修改时，使用新 key 发送 publish 返回 HTTP 200 与当前完整车辆响应，不新增 revision、不增加 version、不改 publishedAt／updatedAt，也不写 vehicle.publish 审计；只保存幂等回执。仍先验证请求 key 与 expected version，旧版本 409，复用 key 改请求 409。draft／archived 不走此 no-op，执行既有发布验证与发布事务。可售／预订／核验时间仍通过独立库存接口即时生效。

### 管理员生成译文建议

`POST /api/v1/admin/vehicles/{id}/translation-suggestions`，请求 `{version}`，必填 `Idempotency-Key`。使用现有员工 Cookie、管理请求限流、可信 Origin 与版本约束，不接受任意文本、URL、目标语言或供应商参数。请求 schema 为 `GenerateVehicleTranslationsRequestSchema`；响应为 `VehicleTranslationSuggestionsResponseSchema`，推导类型 `VehicleTranslationSuggestions`。

成功 HTTP 200：`{data:{vehicleId,version,engineVersion,content:{title,description}},meta}`。title 必有，description 源为空时为 null；非空字段结构为：

```json
{
  "sourceLanguage": "zh",
  "sourceText": "已保存的中文原文",
  "sourceVersion": 1,
  "sourceHash": "64位小写十六进制SHA256",
  "targetHumanEditVersions": {"zh":1,"en":null,"ru":null},
  "translations": {
    "zh":{"text":"已保存的中文原文","kind":"original","reviewStatus":"pending","sourceVersion":1,"humanEditVersion":1,"engineVersion":null},
    "en":{"text":"Machine output","kind":"machine","reviewStatus":"pending","sourceVersion":1,"humanEditVersion":0,"engineVersion":"libretranslate:实际配置版本"},
    "ru":{"text":"Машинный перевод","kind":"machine","reviewStatus":"pending","sourceVersion":1,"humanEditVersion":0,"engineVersion":"libretranslate:实际配置版本"}
  }
}
```

sourceHash 精确定义为 SHA256(UTF-8(JSON.stringify([sourceLanguage, sourceText])))，沿用 API content.ts；这是示意结构，示例 hash 文字不是有效 schema 值。targetHumanEditVersions 是原目标快照的 humanEditVersion，目标不存在则 null；建议中的 humanEditVersion 则沿用原目标值，不存在用 0。zh 保留 original／engineVersion=null；英俄 machine／pending；任何建议都不等于人工审核。

API 只读取已保存 title／description 的中文源（sourceLanguage 基础语言必须为 zh），仅将源文字发给翻译服务，不发送内部备注、采购成本、VIN 或联系人，也不发送现有目标译文。不替换原草稿、人工文本或审核状态。读取后等待服务期间不持数据库事务／行锁；服务结束再核对当前 vehicle.version，发生并发编辑／删除则 409／404，不返回旧建议。成功只写建议审计与幂等回执，车辆版本不变。

客户端须在采用前对照完整车辆 version、源 sourceVersion／sourceHash 以及 targetHumanEditVersions，拒绝过期响应；保留 human／approved 内容，明确采用后经现有 PATCH 保存，再执行单独审核／发布。manual 的三语 approved 门槛保持不变，pending 建议不能自动通过发布。

完整车辆草稿的JSON请求按实际传输字节计限：仅 `POST /api/v1/admin/vehicles` 与 `PATCH /api/v1/admin/vehicles/{id}` 为1 MiB（1048576字节），容纳两个10000字源及六个10000字目标文本、内部／媒体元数据和JSON转义；不截断或放宽字段schema。隔离验证的完整字段上限＋正常UTC毫秒时间戳、所有键／字符串均 `\uXXXX` 转义时为731361字节。此为有限传输上限，额外空白或任意冗长小数秒时间戳不享有无限容量；超限统一413 PAYLOAD_TOO_LARGE，原记录不变。其他JSON小请求仍沿用全局100000字节，媒体上传既有10 MiB不变。

同员工、同车、同 key、同 `{id,version}` 24小时内重放返回冻结的原建议，即使之后车辆已变更／删除或供应商已禁用；响应描述生成当时快照，必须重新核对当前状态。改 version 或同 key 改内容返回 409 IDEMPOTENCY_CONFLICT。失败不保存成功回执，也不修改草稿；无需原地自动重试未知写入。

### 供应商、预算与限制

`TRANSLATION_PROVIDER=disabled|libretranslate|aliyun`，默认 disabled。用户后续已选择现有阿里通用版国际站额度；源码不会自动启用或切换供应商。保留的本地适配须配置 `LIBRETRANSLATE_URL` 和 `LIBRETRANSLATE_ENGINE_VERSION`；API key 可选。URL 仅接受无凭据／查询／片段／路径的 HTTP(S) origin，主机为 127.0.0.1、localhost、[::1] 或容器服务名 libretranslate，固定调用 `/translate` 且不跟随跳转。ENGINE_VERSION 须记录实际固定服务／模型／配置版本，模型变化后更换它，不能把服务商未提供的模型版本伪称已知。

LibreTranslate 按[官方协议](https://docs.libretranslate.com/api/operations/translate/)发送 `{q,source:'zh',target:'en'|'ru',format:'text',api_key?}`，仅取单字符串 translatedText；语言 pivot 和模型安装属于本地服务职责，未安装支持语言时明确失败。本地开源软件无供应商逐字费用，仍消耗 CPU／内存／存储，不承诺零资源成本。

阿里须显式配置服务端 `ALI_MT_ACCESS_KEY_ID`、`ALI_MT_ACCESS_KEY_SECRET`（可选 STS `ALI_MT_SECURITY_TOKEN`），并手动选择 aliyun；不自动由本地失败回退。`ALI_MT_REGION` 仅允许 `cn-hangzhou`（兼容默认，固定 `https://mt.cn-hangzhou.aliyuncs.com/`）或 `ap-southeast-1`（本账号国际站选择，新加坡固定 `https://mt.ap-southeast-1.aliyuncs.com/`），不接收任意URL；RPC签名中的RegionId随枚举一致。API 2018-10-12、TranslateGeneral、zh→en／ru、FormatType=text、Scene=general保持。采用仍受支持的 RPC v2 HMAC-SHA1 签名（官方已推荐新项目 V3，后续升级可替换适配器），密钥／签名不进入浏览器或业务日志。engineVersion 记录 `aliyun-general:2018-10-12:general:<ALI_MT_REGION>:<ALI_MT_CONFIG_VERSION>`，避免相同源hash跨地域复用cache；只表示API／地域／配置版本，不伪称供应商模型版本。

### 公开投影与兼容

`GET /api/v1/vehicles`、`/vehicles/{id}`、`/home/vehicles`、`/vehicle-filters` 均可传 `view=localized`；省略或 `legacy` 保持旧响应形状，不添加 display 或额外 facts 键。客户端升级后必须同时在 SSR、BFF 白名单、浏览器、首页、详情、收藏和筛选请求传递 view；不能只改一处展示。旧 API 会拒绝未知 query，消费者与新 API 运行切换需要协调。

localized 车辆增加可选 `facts.generation: {id,name}|null`、`facts.drivetrain: fwd|rwd|awd|four_wd|null` 及 `display`。generation 是有员工事实依据的车型代际，drivetrain 是驱动形式，均不从车名、动力类型或旧数据推断。原字段 `facts.make/model/trim.name`、地点、`price.includes`、图片 alt、外部平台名同步返回本语言展示值；稳定 ID、金额、里程、国家代码、库存及时间保持事实值。

`display` 的精确类型为 `VehicleDisplay`：make/model/trim/generation/city/location/platform 为 `DisplayText`；priceIncludes 为 `{id:UUID,value:DisplayText}[]`，mediaAlt 为 `{mediaId,value:DisplayText}[]`。DisplayText 是判别联合：

- ready：`{status:'ready',text,requestedLocale,contentLocale,provenance:'catalog'|'original'|'machine'|'human',reviewed}`，文字非空白。
- missing：`{status:'missing',text:null,requestedLocale,contentLocale:null,provenance:null,reviewed:false}`。

缺译名称保留 ID，name 为所选语言的“待翻译”；地点空值、未备妥费用说明省略、图片 alt 为空。display 保留逐项缺译状态；不能把占位算作翻译完成。sourceHash、源文字、引擎、人工修订号、内部备注、联系方式和任务错误不进入公开 display。manual 公开机器译文经员工审核后仍保留 machine 来源；demo/external 不声称人工核验。

品牌使用 browser-safe `BRAND_CATALOG` / `findBrand` / `brandLabel`，首批37项常见品牌，明确不是全球全量。按规范ID或规范化后的完整别名匹配，不模糊推断；保留既有 manual ID，不合并不同历史ID。中英俄拼写来自同一词库，明确约定的拉丁专名可在英俄相同。GAC 为广汽通称，不凭车型猜传祺或埃安。旧快照无侧表时仅可应用已知品牌词库，其余未声明语言的文字为 missing，不能把英文外观相同当作已有翻译证明。

### 全目录筛选

list 和 filters 共用条件。HTTP 非金额数字仅接收十进制整数字符串，不接受指数、负数、空值、数组或重复键；逻辑 schema 中它们是 number。金额保留 decimal string，不使用浮点比较或隐式换汇。

| Query | 含义 |
| --- | --- |
| make / model / powertrain | 保持既有稳定 ID／枚举 |
| trim / generation | 稳定 ID；传任一项时必须同时传 make、model |
| drivetrain | fwd / rwd / awd / four_wd |
| priceMin / priceMax | 闭区间原币金额；最多14位整数、2位小数 |
| priceCurrency | 有金额界限时必填；无界限仅是单位选择，不排除其他币种 |
| mileageMin / mileageMax | 闭区间公里整数，0有效，最大10000000 |
| yearMin / yearMax | 闭区间 modelYear 年款，1886–9999，绝非制造或登记年 |

min > max 返回400；受相应范围限制时未知价格／里程／年款不匹配。SQL在分页前筛选，count/items/hasMore同一条件且列表使用 repeatable read。没有任意排序入口。

localized filters 增加 `trims[{id,name,makeId,modelId,count}]`、同形 generations、`drivetrains[{id,count}]`、`modelYears[{year,count}]`（年款降序）、`priceCurrencies[{id,count}]`。空数组表示无真实选项，FE隐藏对应控件。只传 locale/view/q 即获取该搜索的完整字典，FE可按 makeId/modelId级联元数据，不能过滤当前页车辆来冒充全目录搜索；若同时传分类或范围，API按那些条件缩窄字典。不要把所有字典数组的计数相加当总车数。

localized q 仅搜索实际投影中的品牌／车型、该语言标题、stockCode；缺译的原始外文不会被偷用来匹配。默认legacy q仍按旧原始名字。必需标题语言／审核／版本不就绪时，该语言list、count、filters、home均排除，详情404。售出／下架的即时库存规则不等待译文。

身份为 provider＋platformId＋externalId。同源 revision 单调推进，相同 revision 及内容重复只归档，冲突的相同 revision 拒绝，落后的 revision 忽略。只有明确的 `withdraw` 事件撤回，导入缺行不删除。首次自动激活或撤回后重新激活时，既有员工登记的相同平台挂牌身份进入异常队列。员工写入流独立保留，已并存的记录不做跨流合并。人工覆盖独立保存。同一挂牌的来源文字刷新后，只要该字段仍符合公开规则，人工文字继续优先，源 hash 差异在后台提示复核。修改或重新确认时需带当前 hash 和版本。品牌或车型 ID 改变时，旧人工文字暂停公开，员工可按新版本重新确认。来源字段存在争议或不符合公开规则时，继续执行已有发布校验。员工隐藏不会被来源刷新覆盖，取消隐藏不能恢复供应商撤回。

### 挂牌查询与供应商状态

`GET /listings` 接收 `q`、`platformId`、`state`、`make`、`model`、`powertrain`、`yearMin`、`yearMax`、`mileageMax`、`locale`、`page` 和 `pageSize`。车型须与品牌同时传入。属性筛选使用入库来源事实及人工修订，剔除尚无人工修订的争议来源值。此分类口径适用于全部挂牌状态。默认中文、第 1 页、每页 50 条，单页最多 100 条。状态为 `published`、`hidden` 或 `withdrawn`，省略状态时包含三类。关键词去除首尾空格，最多 2048 字符，按不区分大小写的字面文本匹配站内挂牌 ID、平台挂牌 ID、原始链接、供应商与人工标题和车型名称。站内详情路径或 HTTP(S) 详情链接中的挂牌 ID 会直接匹配，后端只解析路径。筛选条件一起生效。结果按采集时间倒序，同时间按 ID 排序。

结果为 `{page,pageSize,total,items}`。每条包含 `id`、`version`、`provider`、`platformId`、`externalId`、可空 `listingUrl` 和 `title`、`state`、`fetchedAt`、可空 `sourceUpdatedAt` 和 `publishedAt`，以及 `hasOverrides`。入库属性 `facts` 包括可空品牌、车型、年款、里程和动力。仅有撤回记录而无资料时返回 `facts:null`。保留的历史人工文字可以检索，当前来源字段符合公开规则时，显示标题优先采用人工修订。继续用同一挂牌 ID 访问详情及保存覆盖接口。

`GET /listings/overview` 返回全库的 `total`、`published`、`hidden`、`withdrawn` 及平台、品牌和年款选项。提供 `make` 时同时返回该品牌下的车型选项。概览和查询沿用员工车辆读取权限。现有挂牌资料缺少逐车出口资格状态。

`GET /provider-status` 的 `provider` 为 `chinacarapi`，`worker` 为 `not_configured`。时间和批次仅查询已保存的 ChinaCarAPI 档案。`lastBatch` 是最近的批次回执，`lastImportAt` 是最近一次实际应用记录的批次时间，`lastFetchedAt` 与 `lastSupplierUpdatedAt` 分别是当前已存挂牌的最近采集时间及上游更新时间。暂无记录的字段为 `null`。

账号探测默认返回 `not_configured`。配置仅服务端可读的 `CHINACARAPI_ACCOUNT_KEY_FILE` 后，由上述员工接口按需发起固定地址的 `GET https://api.chinacarapi.com/api/me`，使用 `x-api-key`。探测结果短期缓存，同一进程的并发请求共享一次探测。`account` 返回 `state`、`checkedAt`、`plan`、`expiresAt`、`sources`、`dailyLimit` 和 `remainingToday`。额度字段按供应商显式返回值透传，缺失时为空。探测区分 `unauthorized`、`forbidden`、`rate_limited`、`unavailable` 和 `invalid_response`，响应只提供状态和允许展示的账户字段。

## 16. BE-EXT-02 目录容量与美元展示

### 分页、计数与缓存

普通页码请求保持原样。员工发布先于导入挂牌，各流内按发布时间降序和 ID 升序排列。列表、总数和筛选采用相同的语言可见性及查询条件。筛选字典由数据库聚合，HTTP 不传原始材料、完整检测报告或任意 SQL。

`GET /api/v1/vehicles?view=localized&locale=en&pagination=cursor&pageSize=24` 启动游标分页。下一页保留相同的语言、筛选与 `pageSize`，追加响应中的 `data.nextCursor`。只有启用游标的请求才包含该字段，末页返回 `null`。游标为不透明字符串，不能与大于1的 `page` 一起提交。参数改变或游标无效返回400。公开目录版本或当前可用美元快照变化后返回409，消费者清空游标并从第一页重新读取。普通页码保持原语义。

HTTP 继续返回 `Cache-Control: no-store` 与本次 `requestId`。隔离容量模式支持内部内存／Redis 缓存。每次读取先核对数据库公共版本；数据库版本不可读返回503。Redis 不可用时使用有限并发的数据库回源；库存、隐藏、撤回或已知过期媒体不从旧版本返回。管理请求及错误响应不使用该缓存。

### 官网美元报价

列表、筛选、详情与首页都接受 `view=localized&priceView=usd`。收藏复用详情接口并提交相同参数。其他请求保持原响应。原 `price` 及供应商 `price.cny` 的含义不变；车辆响应在启用后额外提供 `displayPrice`。

### 配置输入与展示

`draft.configuration`为`{version:1,items:[{name:string,value:string}]}|null`。例：`{"version":1,"items":[{"name":"排量(cc)","value":"1989"},{"name":"挡位数","value":"8"}]}`。上限统一读取`@hd/contracts/admin`的`VEHICLE_CONFIGURATION_LIMITS`：200项、name 100、value 500、name＋value总16000，文字长度均为UTF-16 code units；原始JSON最多65536 UTF-8 bytes。由初拟40提升至200，容纳较多配置；不得静默截断。只填有依据资料，缺失不猜数值、0或false，也不把配置塞进trim。

`VehicleConfigurationSchema`严格拒绝未知属性、非字符串、空白或首尾空白、重复名称（NFKC/trim/lowercase比较），不改写实际名称/值。`parseVehicleConfigurationJson`额外拒绝重复JSON属性（含转义同名）、围栏、解释文字、过深结构。导出`vehicleConfigurationExample`与`vehicleConfigurationJsonSchema`，JSON Schema覆盖结构与单项界限，重复名称和总长仍由运行时schema核验。错误path相对配置根，如`items.2.name`；写接口前缀为`draft.configuration`。

Create/Save写入契约同一字段可接收原始粘贴字符串；`VehicleDraftWriteSchema`只验证输入，服务用`parseVehicleDraftWrite`转换后仅存canonical对象。空字符串或null明确清空；旧客户端遗漏字段保留已有配置，不能用默认null覆盖。`VehicleDraftInputSchema`／管理读回不接受raw字符串。无配置草稿可保存，员工发布必须有有效非空配置。旧发布快照缺此字段视为无配置，不追溯下架、不编造回填。

## 19. BE-REL-03 目录缓存与分页契约

本节契约随REL03增量交付，运行状态见[后端摘要](../协作/后端.md)；不代表UX11冻结版本或3363已升级。

内部`GET /internal/public-catalog/version?priceView=usd`只由官网服务端通过下述鉴权通道访问；省略priceView表示原币。公网代理必须拒绝整个`/internal/`路径。接口保持`Cache-Control:no-store`，每次从数据库读取公共版本，返回`PublicCatalogVersionResponse`，不进入API内容缓存。正常响应的`data`与公开列表、详情、筛选、首页新增的可选`meta.catalogCache`共用`PublicCatalogCacheStamp`：

| 字段 | 含义 |
| --- | --- |
| version | 64位小写十六进制不透明标识，绑定恢复epoch、数据库公共revision、公开投影版本、目录读取范围、价格模式和当前有效汇率身份；客户端只比较是否相等 |
| priceView | `original`或`usd`，语言与价格模式独立 |
| fx | 原币固定null；USD无有效快照为null，否则为`{version:UUID,expiresAt:UTC时间}`；不返回汇率表、密钥或供应商余额 |
| checkedAt | 本次校验的后端UTC时间 |
| validUntil | 可复用DTO的最晚UTC时间，严格晚于checkedAt、最多15秒，且不能越过汇率或返回内容中远程图片的有效期 |

`meta.catalogCache`只描述本次实际返回的数据版本，不能用另一次版本读取的结果给旧数据贴标签。旧服务或样例可省略该字段；缺失时不能跨请求复用。API回源前后核对版本，变化时至多重读一次，持续变化返回503；数据库不可用时即使L1/Redis有命中也返回503，Redis不可用允许有界数据库回源。错误、后台数据及员工预览不缓存，响应仍为no-store；浏览器和CDN不据此缓存。

FE在**每次匿名SSR请求**中先读取内部当前版本，再以路由、完整规范查询（含locale/view/priceView）和version查找DTO缓存。版本请求不可跨请求缓存；每个请求仍进入既有`public-json`/客户端IP限流桶，可信转发链由OPS明确配置，不能让共享缓存命中绕开入口限流。回源DTO的version必须匹配期待版本；不匹配则重新读当前版本并重试一次，持续不匹配不写缓存且返回503。请求身份、Cookie、IP、headers和requestId不进入缓存函数、键或值；每个HTTP响应仍使用当前请求的requestId。

有效期按后端`validUntil-checkedAt`扣除版本读取／回源耗时，以本机单调时钟保守换算；沿用已经存储的绝对单调到期点，不因命中而续期。USD无有效汇率时version不同于此前有效状态，禁止复用旧换算价格。内容中的更早媒体到期时间同样收紧有效期。只有同版本、未到期且schema通过的匿名公开成功DTO可以复用。

公开列表偏移量`(page-1)*pageSize`最大10000（包含10000）；超过返回400 `INVALID_REQUEST`，使用既有localized游标继续读取，游标规则不变。公共包导出`PUBLIC_CATALOG_MAX_OFFSET`与纯函数`isPublicCatalogOffsetAllowed(page,pageSize)`，必须传入实际pageSize，不能用默认24推算。最后允许的offset页仍按完整pageSize返回，只有真实数据不足才缩短，不在第10000条截断。`meta.total`和`accessibleTotal`继续为真实匹配数量（游标可继续访问），不截断为10000，也不伪造分页总数；上限只约束offset查询成本。FE可用该函数区分合法格式的超界深链并提示缩小筛选，不能把它当车源不存在。筛选数量使用同一可见性与语言规则。


### 内部SSR回源协议

内部只读别名与原公共路由复用处理器、schema、可见性及公共缓存，不复制管理数据投影：

| 内部GET路径 | 对应公共GET路径 |
| --- | --- |
| /internal/public-catalog/vehicles | /api/v1/vehicles |
| /internal/public-catalog/vehicles/:id | /api/v1/vehicles/:id |
| /internal/public-catalog/vehicle-filters | /api/v1/vehicle-filters |
| /internal/public-catalog/home/vehicles | /api/v1/home/vehicles |

查询参数及成功/错误envelope不变。只允许GET，不提供POST、媒体、管理或preview别名。`version`也必须经过同一服务鉴权，但每次实际访问数据库，不缓存版本。

FE/API仅在服务端读取同一个`HD_SSR_SERVICE_SECRET_FILE`私有文件，内部请求附静态`X-HD-SSR-Key`。API要求密钥有效且**原始socket连接地址**符合`HD_SSR_SERVICE_PEERS`的显式IP/CIDR，两者同时成立才接受；地址验证不使用X-Forwarded-For。未配置、缺凭据、伪造或错误连接来源返回404。该密钥头在普通`/api/v1/*`没有任何特权，不改变其限流；不得进NEXT_PUBLIC、浏览器、缓存键/值、错误或日志。OPS必须使API无公网监听入口、对公网整个`/internal/`返回404，只允许官网所在内部网络/受控连接，定期换密钥不改缓存数据身份。

数据别名使用独立且有界的单API进程令牌桶：持续30请求/秒、最多突发40、无等待队列，耗尽返回429及`Retry-After:1`；底层数据库回源最多4并发，正式模式最多16个等待key，共享原请求3秒期限；队列满/超时返回503，超时等待不再启动回源。这个服务额度不取代访客入口限流：每个匿名SSR/RSC请求先调用内部version；version继续使用既有`public-json`桶按可信解析访客IP计120次/分钟，与普通公开JSON共用，OPS只信实际FE代理链。版本请求的访客头由FE在缓存函数外处理；匿名共享数据loader只携带静态服务身份，不携带访客IP、Cookie、动态headers或requestId。伪造来源/密钥不能转入服务桶。容量验证分别记录正常吞吐和限流行为，不能用429降低P95后宣称正常读性能达标。

部署缓存身份由OPS显式注入`HD_DEPLOYMENT_ENV=production|local|test`及`HD_RELEASE_ID`（40至64位小写commit标识，或`sha256:`加64位镜像摘要），后端只在不透明version中绑定，不回显原值。生产、正式缓存启用及实际main入口（含非生产）缺值报配置错误；仅明确test且所有内容缓存关闭的纯函数/隔离fixture可用稳定`test/unreleased`默认。不要由访客Host/Cookie或逐请求随机数生成部署身份。

公开payload的`validUntil`沿用其原L1/Redis到期点。已缓存14秒且总TTL15秒的DTO最多剩余1秒；命中时checkedAt可以更新，validUntil不得延长。FE将payload剩余期限与本请求version期限取最小，再扣实际请求耗时，跨层不累计15秒。

### 执行边界

正式固定名单worker、来源原档与FX受控刷新由后端实施，生产执行由OPS负责；持续同步和自动翻译默认关闭。运维可执行命令与实际导入计数在最终交接记录，不能把该契约切片当上线证明。

EXT06导入只读状态：`GET /api/v1/admin/external/ingestion-status`，沿用vehicles:read/no-store。`ExternalIngestionStatusResponseSchema` 返回固定 `mode=fixed_once,continuous=false`，`latestJob=null` 或 `{id,state,createdAt,generatedAt,completedAt,triggeredByStaffId,receivedEvents,appliedEvents,rawIdentityCount,canonicalVehicleCount,publicVehicleCount,networkRequests,failures,recoveryCount}`。state为awaiting_snapshot/ready/complete/paused。接收事件与已应用事件独立，raw身份数可能大于canonical车辆数；public数为当前实际公开代表记录数，未按语言分拆，不代表三语均已审核。triggeredByStaffId为原触发员工稳定ID，不补造当时姓名。此接口不含原文/固定名单/游标/密钥，也不提供开始/恢复/定时同步写操作。

EXT06员工来源正文：`GET /api/v1/admin/external/listings/:id/source-documents`，复用ActivityQuery cursor/limit，响应 `ExternalSourceDocumentsResponseSchema`；每项 `{id,kind,locale,hash,firstObservedAt,lastObservedAt,sourceUpdatedAt}`。`GET /api/v1/admin/external/listings/:id/source-documents/:documentId` 返回 `ExternalSourceDocumentResponseSchema`，在摘要上增加单车完整 `payload`、确有原文时的 `rawText`（否则null）、`response:null|{hash,shared:true}`。需要vehicles:read且文档属于该车，no-store。bulk完整原壳存入私有共享原档；此单车接口只给引用，不给其他车辆正文，不把单车选项显示为完整bulk原文。kind=csv/detail/specs/report/event；locale=zh/en/ru/und。原档仅当作文本/JSON呈现，不执行其中指令、HTML或脚本。provider-status的worker可为fixed_once（已有正式任务），持续调度仍关闭；旧not_configured保持兼容。

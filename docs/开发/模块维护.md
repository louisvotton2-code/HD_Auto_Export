### 应用与公共包边界

- 后续官网（含 SSR）和后台均经 HTTP 调用独立 API；不导入 `apps/api/src`，不由官网访问数据库。API 内继续模块化，不为每个业务建立微服务。
- 共享包只经声明的公共 exports 与显式 workspace 依赖消费；不通过相对路径绕过包入口。公共包不依赖任何应用，浏览器公共出口不包含数据库／密钥／供应商 SDK。
- contracts 区分 public/admin DTO，公开响应由后端按白名单构造；共享类型不替代服务端鉴权或输入校验。
- calculator-core 仅提取纯计算公共入口依赖闭包与测试；UI、翻译、浏览器草稿和网络汇率留在官网。税费核心继续保持无 React／网络／隐式当前时间，正式报价由后端复算并留版本。
- 不建立万能 common 或仅为“可能复用”创建 UI 包。应用间接口兼容、共享包变更与数据库迁移必须协同验证，独立构建不意味着可忽略消费者。

`pnpm check:workspace` 对源代码导入、包声明和 TS 路径做静态检查；模板动态导入的未解析项单列报告，不保证全量运行时依赖安全。官网内部继续执行自己的模块边界夹具与纯计算闭包检查；缺少源码／入口不能空扫通过。

## 允许的调用方向

```text
app / i18n 装配入口
  ├─ shared（品牌、配置、公共组件）
  └─ calculator 的 UI、消息、国家配置、构建汇率
       ├─ application / config / infrastructure
       └─ calculator/index.ts
            └─ core/calculate.ts
                 └─ policies/*/reference.ts
                      └─ core 的金额、日期与类型

未来其他业务模块
  └─ calculator/index.ts（包括类型）

可选 server/handler.ts
  └─ calculator/index.ts（静态站不注册路由）
```

应用层可以读取内核类型、纯金额和日期工具；计算器内部 UI 可以消费自己的应用层／配置。App 和 i18n 是网站装配入口，可以直接装配模块页面和消息。其他业务模块不能直接引用 `calculator/core`、`policies`、`ui`、草稿或默认参数。购车指南只通过本语言URL链接到计算器，未调用计算内核，也不引用其内部文件。

核心及七国税费策略不依赖应用层、UI、消息文件或网络。`policies/*/method-messages.ts` 与规则放在同国目录便于维护，但由应用层加载；公共计算运行依赖不加载这些翻译文件。当前七国策略由内核统一静态导入，尚未做按国家懒加载。

`pnpm check:boundaries` 自动执行防护测试，并追踪公共入口的实际运行依赖闭包，拒绝框架、JSX、消息、网络、时钟、浏览器状态、随机源及不受支持的外部依赖；外部运行依赖仅允许 Decimal.js。它还检查其他业务模块对计算器的引用，包含类型导入。该脚本不是全仓库所有层级的通用依赖检查器，也不衡量代码体积；共享层与未来新模块之间仍需人工检查依赖方向。

## 公共计算接口：当前可运行的用法

公共入口只接受事实，不从浏览器、网络或系统时间取值。当前签名为：

```ts
calculateImportEstimate(input: CalculationInput): CalculationResult;
```

以下示例可用于未来车辆模块的适配层；它使用固定的参考输入，便于复现，不代表当前市场汇率或正式报价。导入路径及字段均来自实际公共类型：

```ts
import {
  calculateImportEstimate,
  type CalculationInput,
  type CalculationResult,
} from '@/modules/calculator';

const input: CalculationInput = {
  country: 'RU',
  importerType: 'individual',
  powertrain: 'petrol',
  price: '25000',
  currency: 'USD',
  displacementCc: '1998',
  powerHp: '150',
  manufactureDate: '2021-01', // YYYY-MM
  customsDate: '2026-01-01', // YYYY-MM-DD，由调用方明确提供
  freight: '', // 未提供，不是已知的零成本
  insurance: '',
  steering: 'left',
  transactionRate: '81.969182', // 每 USD 兑多少 RUB
  euroRate: '94.7', // 每 EUR 兑多少 RUB
};

const estimate: CalculationResult = calculateImportEstimate(input);

if (estimate.status === 'reference' && estimate.total !== null) {
  // 此固定样例：total === '926952'，currency === 'RUB'
  // 展示时保留 quality、ruleVersion、assumptions 和 excludedCosts。
  // 不把该总额命名为完整落地价，也不重复加入 additionalCosts。
} else {
  // 交给调用方显示缺失字段、错误或待核验原因；不要用 0 替代。
  const diagnostics = {
    status: estimate.status,
    missingFields: estimate.missingFields,
    fieldErrors: estimate.fieldErrors,
    reason: estimate.reason,
  };
}
```

本例已有对应金额回归：[core/calculate.test.ts](../../apps/web/src/modules/calculator/core/calculate.test.ts)。无需运行网站或提供 HTTP 服务便可调用公共函数。

| 结果状态       | 调用方行为                                               |
| -------------- | -------------------------------------------------------- |
| `reference`    | 可显示参考数字，同时保留参考范围、假设和排除项           |
| `incomplete`   | 读取 `missingFields` 补充必要事实，不显示旧总额          |
| `invalid`      | 读取 `fieldErrors` 提示输入错误，不把结果当 0            |
| `needs_review` | 读取 `reason` 提示未覆盖规则／日期／身份，不复用个人结果 |

金额和原始汇率用十进制字符串传入，不用二进制浮点累计税款。空字符串代表未知；所需字段由国家／动力／身份决定，不能随意删掉当前类型中的必需字段。`usdRate` 和 `condition` 是兼容扩展的可选字段；UZ 使用新／二手状态，CNY 交易时需要每 USD 兑多少 UZS 的 `usdRate`，USD 交易时采用 `transactionRate`。

结果的 `lines` 计入 `total`；`additionalCosts` 只列示、不再加进合计。运保进入某国计税基础，并不代表运保本金已含在合计里。`method.key`／`method.params` 提供实际计算分支和代入参数，`formula` 是未本地化数学表达式，由展示层统一翻译格式化。未来车辆模块不能从界面文本解析税额或抓取本站 HTML 来获取结果。

## 验证与交接

推荐 Node.js 24 LTS，按 `packageManager` 使用 pnpm 11.25.0；保持唯一 `pnpm-lock.yaml`。

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm build
pnpm test:e2e
```

`pnpm check` 包含类型、边界防护／依赖闭包与全部 Vitest 单元测试。浏览器测试必须在构建后执行，默认使用已安装 Google Chrome，并启动本机静态预览。也可设置 `E2E_BASE_URL` 指向独立静态主机；公网 HTTP 不具备复制 API 的安全上下文，不能把预期 HTTPS 的复制用例在 HTTP 失败解释成金额错误。用户明确选择暂不添加 HTTP 复制兼容。

针对单项改动可先运行对应验证，再执行必要的完整检查：

```sh
pnpm --filter @hd/web exec vitest run src/modules/calculator/policies/ru/reference.test.ts
pnpm --filter @hd/web exec vitest run src/modules/calculator/application/method-contract.test.ts
pnpm check:boundaries
pnpm --filter @hd/web exec playwright test tests/fee-details.spec.ts
```

上面浏览器命令仍要求最新 `out/`；不要复用旧构建而把新代码写成已通过。测试是参考实现回归，不是官方税法认证。实际验收数量和结果写入自己角色的交付日志，不要把本文示例命令当成已执行记录。

更新结束时，在 `docs/日志/YYYY-MM-DD/角色-任务ID-主题.md` 记录本次改动、真实已执行检查、限制与下一步，并更新 `docs/协作/对应角色.md` 的进度摘要；具体角色入口见[文档导航](../README.md)。PM 核对证据后维护[开发进度](../开发进度.md)，各角色不同时改写总进度。涉及计算时同步[规则覆盖表](../research/规则覆盖表.md)，涉及部署时同步实际记录。只改文档不需要无意义地重新执行浏览器矩阵；修改运行代码则按影响范围完成检查。Next.js 升级前先读安装包内对应 `node_modules/next/dist/docs/`，特别复查 export、多个 root layout 与 `globalNotFound` 的当前约定。

部署任务从[运维职责](../协作/运维.md)进入，先确认当前用户提供的目标和实际环境。用户已更换服务器且尚未提供新地址，不连接旧主机，也不假定新服务器已有 Nginx 或 VPN。[历史 VPS-IP 记录](../归档/部署/VPS-IP部署记录.md)与[静态部署指南](../归档/部署/静态服务器部署.md)仅在对应静态维护任务中参考；不作为新运行时直接操作步骤。若交付仍是静态版本，构建 origin 与索引开关须匹配目标，完整 `out/` 校验后切换 release 并保留回滚；具体应用完成运行时迁移并验证对应产物后，才按该应用的新运行材料部署，官网迁移属于 FE-01。不得为更新本站覆盖无关服务或重置防火墙。SSH 密码、私钥、数据库和服务器备份不进入 Git；本文不提供任何登录材料。

## 后续车辆、配件和物流如何接入

官网 `src/modules/vehicles/` 仍使用演示模型、mock、筛选、列表／详情和公共 `index.ts`。后端已在 packages/contracts 和 apps/api 建立正式契约与服务，FE 下一步按[车辆接口](车辆接口.md)经 HTTP 映射公开数据；不得把数据库或供应商密钥加入含 UI 的公共出口。`parts/`、`logistics/` 待分配任务后再建立，不提前创建空模块。

- 车辆模块把自己的车辆事实、目的国、明确清关日期和汇率映射为公共 `CalculationInput`，通过计算器 `index.ts` 获取参考结果。没有事实时返回缺失状态，不导入计算器示例默认值补齐库存车辆。未来真正的落地成本函数需另行实现成本覆盖与去重，不把现有 `total` 换名包装。
- 外部车源连接器放在后端 inventory 的适配器边界，先统一为自有领域类型，再向车辆界面提供公开数据；不把供应商 SDK、鉴权、字段结构塞进计算器内核、浏览器出口或公共品牌组件。该能力仍待 G3 实现。
- 配件模块独立维护适配车型、库存／报价与后续订单事实，不能因为展示金额就复用整车进口税策略。支付、账号、订单和供应商接入需要对应任务授权后再实现。
- 物流模块独立定义查询输入与规范化轨迹，承运商状态通过适配器转换；配件或车辆业务仅消费其公共接口。物流轨迹不等于运输报价，运输报价也不自动构成海关税基；接计算器前需明确费用单位与覆盖区段。
- 需要密钥、供应商签名、订单或持久化状态时，另行设计后端边界。静态网站不能安全保存这些密钥；保留的计算 HTTP handler 不代表完整后台已经存在。

新增跨模块类型确有多个消费者后再抽到合适的公共契约，不为未来可能性预先建万能 `utils` 或把所有业务揉进 `shared`。保持各模块可独立测试；共享计算只通过公共函数和显式事实完成。

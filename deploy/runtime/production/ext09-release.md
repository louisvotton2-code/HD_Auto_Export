# EXT09 单机平滑发布

普通发布不创建全库副本，也不做全库恢复或不断变化的生产表指纹对比。代码审查和 CI 后，在服务器串行构建；新旧 API/web 槽短时共存，数据库、Redis和单worker共享保留，公网 Nginx 不重建。

## 部署入口

`release-slots.py` 从实际 Compose 解析结果生成 blue/green 私网槽：固定地址不得冲突，不开放宿主端口。新 API 挂载独立可读目录，600权限的 mode 文件归应用用户所有，通过同目录临时文件+原子rename变更 candidate/active/draining；候选启动前必须已有 candidate 文件。应用和构建使用同一最终SHA，官网构建参数 `HD_DEPLOYMENT_ID` 由 `RELEASE_ID` 提供。

`gateway_files()` 保留已有私有媒体、可信代理及限流规则，只换受审槽名，后台冻结仅限其 API 入口。`gateway-reload.py` 先保存旧配置，校验新配置后 graceful reload；失败恢复旧配置。root私有 `/srv/hd-auto/staging/gateway` 为可重建状态源。首次现有proxy容器不重建，只复制配置/资产；未来显式重建时追加 `compose.stable-gateway.yaml` 的宿主挂载。重启已有容器保留其文件层，不把需要重新创建的容器当无状态。

`immutable-assets.py` 合并当前与前一版 Next 静态资源；相同URL不同内容拒绝。旧哈希文件先保留，不能切换后就随旧槽删除。Nginx只为此目录设immutable缓存，不缓存HTML。Next deploymentId识别RSC跨版本；`?dpl`本身不负责选槽。后台静态产物也保存在gateway/admin，不强刷未保存表单。

### 官网根域

根域发布使用 `https://hongdingauto.com`。构建前将 `SITE_ORIGIN`、`WEB_SITE_ORIGIN` 和 `ANALYTICS_ORIGINS` 均设为该来源。用实际 Compose 输出生成应用槽，并将同一官网来源作为 `website_origin` 传给 `gateway_files()`。保持 `ADMIN_ORIGIN=https://admin.hongdingauto.com`，登录与员工 Cookie 沿用现有域。根域和 www 使用 `/run/tls/apex/current`，后台使用 `/run/tls/admin/current`。两个独立的 Certbot 证书在现有 ACME 挂载下续期。

切流和回退前核对根域两套网关配置都能提供首页、目录与 API，www 跳转保留路径和查询参数。现有旧版回退材料若生成于换域前，先用该版 Web 和同版受信 API 验证根域入口，再切换；保留原配置供回退复查。上线后核对三语 canonical、已准入的站点地图、首页缓存及两条同源统计入口。两条统计入口只用缺字段的合成请求验路由，使用包含根域的 API 原生配置后移除临时代理映射。

## 可选的内网首页缓存

同版 Web 和 API 的 CACHE-300 联调通过后，可为该应用槽构建 `deploy/runtime/Dockerfile` 的 `html-cache` 目标，并标记为 `hd-auto-html-cache:<发布SHA>`。生成槽配置时，`release-slots.py` 同时接收 `--html-cache-ip` 和 `--html-cache-secret-file`。使用应用私网内未占用的固定 IPv4，避开动态分配区。Web 与缓存容器共用一个应用用户可读的独立 owner-only 密钥文件，两个容器均按只读秘密挂载。缓存容器仅接受固定 Nginx 私网地址的连接，依同槽 Web 的固定地址回源。

生成网关时，显式传 `html_cache_host='html-cache-blue'` 或 `'html-cache-green'`，与 `web_host` 对应。默认模板继续动态渲染。配置仅涉及中文、英文和俄文的规范首页，无查询参数的匿名 GET 才可复用。切回动态网关时沿用相同配置文件集合，正常 reload 即可。

命中前从 Web 私有 `/internal/public-html/version/?locale=...` 读取目录和筛选的实时版本。未命中时由 `/internal/public-html/render/` 发起当次渲染。两个内网请求必须确认同一协议，并使用独立 nonce。网关在完整 HTTP EOF 后验收私有渲染的单个 `X-HD-HTML-Proof`，核对发布标识、目录和筛选版本、汇率身份及到期时间。每个槽最多保留三个健康匿名 HTML 文档，每个最多 512 KiB，并限制同时验证请求。

首页缓存默认协议 2，最长 300 秒。同版的 Web、API 和缓存通过协议 3 联调后，在生成该槽时显式指定 `--html-cache-protocol 3`，最长 600 秒。实际复用期限取实时版本证明、渲染证明和协议上限中最早的时间，命中沿用原到期点。混版无法确认同一协议时走动态渲染。切流前验证 300 秒后仍可命中、600 秒上限，并分别验证撤车及目录、筛选、汇率版本变化导致旧 HTML 立即失效。公网 RSC、带查询参数和私有请求继续走现有旁路。

版本检查失败、旧服务和不完整响应会走动态路径。实时版本或私有渲染返回 429 时，保留 `Retry-After` 并直接返回。对外首页保持 `no-store`，私有控制头在代理两跳剥离，公网 `/internal/` 返回 404。缓存使用现有入口限流。

## 单一写入交接

后续受控版本：先旧槽 draining，读取旧 `/health/serving` 等真实副作用请求计数为0，再将新槽 active并切后台路由；不能同时两个active。不因客户端断线推断付费调用结束。新API按双投影兼容旧FE，扩展迁移先做，破坏性移除另排。worker待新API正常后同版本交接，不开第二worker，持久 paused=true 保留。

首次旧e623不认识mode：新candidate公开读健康后，将公开web/API先接新槽；冻结旧后台全部API（含auth GET）并禁止所有可能副作用入口。至少保留旧进程150秒，检查translation_plans/segments running=0、预算预留不再增长；有不确定状态就停在此阶段协调，不自动杀调用或重试翻译。随后优雅停止旧API确保唯一写入，再提升新active、后台切新。旧SSR公共请求要在停止旧API前排空。公网读保持可访问；后台写入短暂停顿如实记录。

新写入后的回退是兼容应用切换，使用当前数据库与媒体。新 API 和 worker 均识别备份租约之后，才启用新版在线每日备份。

### 发布后的运行槽保留

发布收尾后，本机应用镜像库只留现用签版和一个已经验证可立即回滚的签版。选定实际回退版本，以部署清单记录其镜像与网关配置。发布中的候选镜像随构建和验收临时保留，未接流且已被取代的候选按相同规则清点。观察至少 10 分钟并完成本版验收后，检查实际代理与回退配置、统计与定时任务、备份入口，以及其他运行容器的直接引用。基础设施和备份或定时任务明确引用的镜像继续保留，并记录用途。共享静态指纹资源按独立保留策略处理。

择低负载时段，用发布锁与备份锁防止同切流和备份重叠。对已排空且无运行引用的历史槽，按版本小组停止其 API、Web 和首页缓存容器。停用验收阶段保留原容器、网络、配置和镜像，以便同版重新启动。每组检查官网、旧静态文件、报价、匿名后台鉴权和唯一 worker，再处理下一组。验证失败时恢复当前小组并记录。对确实有额外运行用途的槽，登记调用方和保留原因。停用前后用同口径记录目标容器的内存和 CPU，以及宿主可用内存与 I/O 等待。

在新镜像加载前、切流和收尾后记录系统盘与数据盘实占和可用量。构建缓存已经独立落数据盘，加载后的运行镜像仍需系统盘空间。回收已被替代的构建产物时，锁内核对容器可写层、镜像 ID、回退包、备份任务及旧指纹静态文件所需资源。对确认无引用、可按原 Compose 重建且镜像已归档校验的历史版本，分批回收精确镜像和对应已停用容器，记录系统盘实际释放量。

开始正式构建及加载镜像前运行 `storage-alert.py --release-gate`。系统盘达到 80% 时先归档或腾出足够空间，再按原流程发布。现有存储计时器同时记录系统盘，达到 75% 时在宿主机记录告警。正式发布源码保留 `/srv/hd-auto/releases` 路径，由生产数据盘持久绑定挂载；Docker、备份和统计启动读取该挂载。重新启用历史版时按归档清单校验镜像和 Compose。用数据盘归档恢复过期的版本镜像，现用版、即时回退版和备份固定镜像留在本机镜像库。

已用 systemd drop-in 运行系统盘探针的主机，迁移到新版 service 模板时核对生效的 `ExecStart` 和 `ExecStartPost`。确认新脚本与状态目录可用后，在同一次 service 更新中移除重复的旧探针并执行 `daemon-reload`，复查计时器和两块盘的独立状态记录。

## 资源和验证

Build/restore/双槽串行，避免3GiB构建器与双槽、恢复库叠加。新槽沿用API640MiB/web768MiB限额和有限数据库连接池；现场核对资源后执行。不承诺单机故障高可用。

实际交付记录应包括最终SHA、候选只读/收费拒绝、旧在途排空证据、公开页面连续采样、旧哈希资源请求、proxy未重启、worker同版且paused，以及备份/清理独立结果。不要把unit通过当实际线上切换完成。

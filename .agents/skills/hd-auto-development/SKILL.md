# HD Auto Export 项目协作

本 Skill 随仓库交接。当前用户指令决定本轮范围；遵循已有授权，不额外增加审批，也不因规划存在扩大外部操作、采购或部署范围。

## 开始与定位

1. 本文件上溯三级为仓库根。先读 [AGENTS.md](../../../AGENTS.md)、[接手导航](../../../docs/README.md) 与 [当前进度](../../../docs/开发进度.md)；已经读过的内容无需重复。
2. 从导航选择自己的角色任务和进度摘要：前端、后端、后台、运维、测试与审查或产品项目。只补读该任务需要的接口、模块说明和相关代码，不要求全员通读历史规划或研究。
3. 先查工作树、已有实现和依赖；保护未提交改动。开工运行 `pnpm hooks:check`，新 clone／未启用时先 `pnpm hooks:install` 再核验；旧工作区缺脚本时协调共同基线，不跳过保护。并行与共享文件按导航的负责人约定执行。实际能力以代码与验证证据核对，路线图和接口草案不等于已实现。
4. 写 Next.js 代码前读本地已安装 `apps/web/node_modules/next/dist/docs/` 对应指南。依赖、启动与检查命令以 `package.json`、锁文件和 README 为准。

## 多端工作如何分派

- 沟通采用阻塞／协助／完成时汇报：各端独立推进，开发中途不持续向 PM 汇报；仅遇到阻塞、需要跨端协助或完成交付时集中提供信息。PM 不反复催问或高频轮询，不转述无变化状态；最后核对提交和验收证据，向用户提交一份精简结果。需要用户决策的风险及时说明。

- PM 按 FE、BE、AD、OPS 等职责，把持续开发、运维和跨轮修复交给侧栏中已有的对应项目对话。按角色与仓库核对对话再分派。涉及单一职责且可独立完成的小改动，沿用该角色对话，无需为每个步骤新开窗口。
- 交接写清任务 ID、共同基线 SHA、文件归属、相关契约、验收条件、执行环境和回报位置。跨端先确认 API 契约和集成顺序；不同文件可并行，同一文件、锁文件、构建目录和测试资源由指定负责人串行协调。各角色把实际结果写入仓库角色摘要和日志，PM 用证据汇总并验收。
- 临时子 Agent 适合独立审查、定向验证和范围明确的短调查。若固定对话无法访问或继续，先告知 PM／用户具体情况及替代方式；使用临时子 Agent 接手实现时，说明它不会更新侧栏中的角色对话，并通过角色日志保留交接。创建新的用户可见对话按用户的明确要求执行。

## 按任务加载规范

- 修改页面、组件、车辆 UI 或动效：读 [页面与模块模式](references/component-and-module-patterns.md)，再定位对应模块说明。
- 选择检查、记录交付或准备 Git／部署：读 [验证与交接](references/verification-and-handoff.md)。纯产品整理无需读页面实现规范。
- 真实车源、后端和后台任务：按角色文件读取 [车辆接口](../../../docs/开发/车辆接口.md)。服务端出口、鉴权、发布和状态以同一契约协作，不在不同对话另造接口。
- 后台界面、车辆编辑与发布操作：按需加载 [后台工作入口](../hd-auto-admin/SKILL.md)，按后台架构和现行管理契约实施。
- 后端 API、数据库、来源接入、翻译任务或 AI 查询：按需加载 [后端工作入口](../hd-auto-backend/SKILL.md)，定位现行架构与分阶段任务，不提前执行后续接入。
- 修改税费才读 [规则覆盖表](../../../docs/research/规则覆盖表.md)、[参考研究](../../../docs/research/计算器参考研究.md) 和对应策略／测试。参考站复算与官方核验分别登记。

## 必须保持的边界

- 官网路由在 `apps/web/src/app/`，官网业务仍按其 modules 组织；独立后台和 API 分别属于 `apps/admin`、`apps/api`。应用不得互相导入内部源码；公共包不得依赖应用。业务数据通过 API 契约获取，数据库、权限与秘密归 API。
- 官网 `shared/` 不反向依赖业务模块。历史静态演示隔离在官网 `vehicles/mock/`，不混入当前目录；车辆统一消费API自有契约，当前公开范围按用户最新产品决定。后续外部来源也由后端适配，页面不绑定供应商原始字段。
- 当前官网计算调用仍走 `@/modules/calculator`；`packages/calculator-core` 只是预留包，实际提取时要保持纯函数边界和所有消费者回归。核心不依赖 React、翻译、网络、浏览器或系统当前时间，日期与汇率显式输入。缺失、非法、未覆盖与已知零值区分，参考合计不是完整落地价。
- 中英俄语义 key 与占位符一致，沿用现有消息装配。语言、交易币种和目的国互相独立。品牌及联系配置复用官网 `shared/config/site.ts`；车辆草稿复用官网 `shared/lib/vehicle-contact.ts`，客户自行发送。
- 工作区已建立，官网当前使用 Node／standalone 并经 HTTP 消费公开 API；API、contracts 与独立 React/Vite 后台均有本地实现，具体能力与联调证据按角色摘要核对。calculator-core 仍预留。官网生产成品与后台静态产物分别验证，不沿用历史 out/；单端检查通过不代表三端已验收或已部署。
- 公开文案、样例下架、取消focus／visibility激活核对及同服务器图片交付遵循[当前产品约定](../../../product/路线图.md#当前公开展示与交互)，不继续执行已被用户替换的旧公开标签／激活刷新规则。内部来源、未知库存、核验时间、图片许可与machine／pending等事实不因展示调整而改变，不伪造现货、已核验或人审；manual门槛不放宽。API发布／媒体权限按车辆契约执行，Nginx传图不能直接暴露完整媒体目录；具体实施与验收状态以进度为准。

- 功能交付按 [测试与审查](../../../docs/协作/测试与审查.md) 完成实现者自测、独立 review、相应集成验证和 PM 证据核对。用户确认真实业务与视觉；生产发布仍按任务授权。审查者报告具体版本与未覆盖项，不以“没发现问题”保证没有缺陷。实现者主动安排独立 Reviewer Agent；最终推送按同一文档的“推送前检查”执行实际验证和报告登记，绑定完整 SHA。不得伪造独立审查／测试记录或自行绕过 hook。main 走 PR＋CI，用户不安排第二 GitHub 审批账号，不能把 Agent 报告冒充 GitHub 账号批准。

## 每轮交付

按 [统一记录规则](../../../docs/README.md#每轮如何记录) 更新自己的角色进度摘要，并新增本轮日志；PM 汇总总进度，其他角色不重复改写。日志写实际版本、变更、执行检查、失败／限制、Git 与部署状态、依赖及下一步。维护文档随实际变化同步；不修改无关历史记录，不把历史通过数量当本轮检查。

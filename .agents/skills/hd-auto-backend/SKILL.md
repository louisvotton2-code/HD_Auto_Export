# HD Auto 后端工作入口

这是项目协作规范的后端补充，随仓库交接；只执行当前分配任务，规划中的后续阶段不等于已实现或获准连接外部服务。

日常本地开发由本角色自行运行 `pnpm dev:api` 并维护开发进程，不等待 OPS 逐次部署；允许独立开发端口，交付时报实际地址，具体约定见 [本地开发分工](../../../docs/README.md#本地开发与部署分工)。

1. 先完成 [项目协作入口](../hd-auto-development/SKILL.md) 的开工流程，已读取的公共说明不重复加载；从 [后端任务书](../../../docs/协作/后端.md) 确认任务 ID、当前状态和消费者依赖。
2. 架构、数据库、来源接入、翻译或 AI 任务读取 [后端架构](../../../docs/开发/后端架构.md) 对应章节；接口实现与消费者交接以 [车辆接口](../../../docs/开发/车辆接口.md) 为唯一契约说明，再核对实际 schema、迁移和代码。
3. 先明确本次触及的公开/管理数据、事务与版本边界，再实施。新增查询必须复用允许字段投影；AI 任务只读取公开数据。未来来源、翻译和任务系统的约束按架构按需加载，不提前预建空模块。
4. 变更契约时同时更新可检查 schema、接口资料和必要样例，列明 FE/AD 影响；数据库变更交付可复现迁移与实际验证结果，不以文档描述替代运行证据。
5. 按 [测试与审查](../../../docs/协作/测试与审查.md) 完成自测、独立审查及对应联调；按开发期范围检查，将版本、限制和下一依赖记入同任务记录，交付／阻塞时更新角色摘要链接。各步骤与推送规则沿用项目入口，不另造第二套流程。

日常用法：给出本轮任务或问题后使用 `$hd-auto-backend`。具体运行命令以 API 的 README 与 package scripts 为准；进度、接口和架构各在上述入口维护，避免复制相互漂移的清单。

# HD Auto 后台工作入口

这是随仓库交接的 AD 专用入口；沿用当前用户授权，按可验证阶段推进，不因规划新增外部采购、真实消息或部署动作。

1. 完成[项目协作入口](../hd-auto-development/SKILL.md)的开工检查，已读资料不重复加载。读[后台任务与进度](../../../docs/协作/后台.md)，核对代码和最新日志后确定下一项可执行工作；旧总进度不能代替实际核对。
2. 工程、路由或模块设计读[后台架构](../../../docs/开发/后台架构.md)；运行与检查读[应用说明](../../../apps/admin/README.md)。车辆任务再读[车辆接口](../../../docs/开发/车辆接口.md)，使用 `@hd/contracts/admin` 等正式出口，不复制请求类型或导入其他应用内部源码。
3. 实施一个可验证切片。权限由 API 强制；保存草稿与发布、库存状态与发布状态分开；保留未编辑字段、null、金额字符串和三语版本。409 保留输入，创建／发布的重试保持原请求和幂等键；不把加载失败显示成空库存或已完成。
4. 客户／标注或 AI 任务按架构对应章节先核对 BE 契约及数据范围。首版员工 AI 只读公开车源，客户资料不默认进入模型；未来模块不预建空表或假成功页面。缺少其他端能力时列出字段、权限、请求与验收依赖，并继续不受阻部分。
5. 按[测试与审查](../../../docs/协作/测试与审查.md)做自测、独立 review 和对应联调；更新后台角色摘要与本轮日志。注明 fixtures／请求拦截和真实 API 验证的区别，分别记录 Git 与部署状态；总进度交 PM 汇总。

日常使用：给出当前任务后调用 `$hd-auto-admin`，或直接读取本文件。架构、任务状态和执行证据分别在上述唯一入口维护，不在 Skill 内复制长期待办。

# 员工管理后台

独立 React／Vite／TypeScript 与 Ant Design 6 员工工作台，默认中文。包含员工会话、车辆草稿、图片、中文来源与英俄译文、库存、发布、首页配置、回收站和外部车源管理。AD-UX-11 在本轮工作树接入结构化详细配置、统一多语工作区、费用确认和来源报告入口；实际检查与交付状态以角色摘要及本轮日志为准，客户资料与员工 AI 仍为后续规划。

Vite 的 `http://127.0.0.1:3318/admin/` 仅供内部开发；用户验收统一通过 `http://127.0.0.1:3363/admin/`。实际同版组合以当前进度和运行核验为准。车辆配置、标题、车况和其他公开文案通过同一份中英俄 JSON 导入。

维护入口：[后台任务与进度](../../docs/协作/后台.md) · [后台架构](../../docs/开发/后台架构.md) · [车辆契约](../../docs/开发/车辆接口.md)。实际验证看角色日志，不以文档或 fixtures 代替真实接口联调。

## 隔离开发与本机入口

日常由 AD 自行启动 Vite，修改后热更新，不逐次交 OPS 构建。按 [统一本地开发分工](../../docs/README.md#本地开发与部署分工) 复用共享环境；仅首次或依赖变更时安装，contracts 仅首次或源码变化后构建。在仓库根执行：

```sh
pnpm install --frozen-lockfile
pnpm --filter @hd/contracts build
pnpm dev:admin
```

以上是 AD 自行运行的内部开发服务，3318 不作为用户验收地址；用户统一通过 `http://127.0.0.1:3363/admin/` 验收。端口占用时核对归属再协调，不停止他人进程；交付时明确 3363 实际对应的版本和 API 连接。登录支持员工短账号与已有工作邮箱；账户见本机私有资料，API 受控员工工具见 [API 运行说明](../api/README.md)。`AUTH_BASE_URL` 与 `TRUSTED_ORIGINS` 按实际登录入口及明确的开发 origin 配置，不包含 `/admin` 路径；保留 Cookie／CSRF 校验，不使用任意跨域放行。无服务时显示连接错误，不填演示库存或提供绕过登录入口。

隔离源码开发时，Vite 默认将 `/api` 代理到内部 `http://127.0.0.1:3320`，不改写浏览器 Origin；需要隔离测试时可由启动环境设置 `ADMIN_API_TARGET`。开发时 `/staff` 和 `/_next` 默认代理本机 3317，可用 `ADMIN_WEB_TARGET` 指向对应 FE 版本；隔离成品预览仅在显式设置时代理官网；AD／BE 按实际开发端口配置应用代理，普通源码修改无需再交 OPS；确有共享基础设施问题时再协调。该参数仅供本机开发／测试代理，不把服务密钥或第三方地址写进客户端。Cookie 由 API 管理，不使用 localStorage token。

## 检查与成品

```sh
pnpm --filter @hd/admin check
pnpm --filter @hd/admin build
pnpm --filter @hd/admin test:e2e
# 先构建 API；本机 PostgreSQL 55432 需可用
pnpm --filter @hd/api build
pnpm --filter @hd/admin test:e2e:live
```

发布保护和公开多语验证的桌面／窄屏截图共用 `tests/fixture-evidence.ts`，保留各自测试输出路径、整页溢出检查及视口恢复。

`test:e2e` 使用 Chrome 和最新 `dist/`，在 3319 启动预览，拦截 API 请求验证界面契约与故障场景；这不等于后端联调。`test:e2e:live` 用本机 `/postgres` 维护连接创建随机 `hd_admin_test_*` 数据库，运行迁移、创建合成测试员工，以 3322 API 与 3319 后台验证真实 Cookie、草稿持久化、公开隔离和退出，结束清理自己创建的数据库与临时媒体。它不读取业务数据库。真实浏览器场景覆盖基础草稿、manual完整发布、demo／首页／批量，以及external至少八图／删除／回收站／恢复闭环；实际通过情况以本轮日志为准，所有车辆与图片均为合成测试资料。测试连接可使用 `API_TEST_DATABASE_URL`，只允许本机 `/postgres`。端口占用时退出，不结束其他人的进程。 隔离联调若用 Next 开发进程作为预览上游，将 `ADMIN_LIVE_WEB_DEV=1` 与已有的回环 `ADMIN_WEB_TARGET` 一起传给 `test:e2e:live`；Playwright 才会为其 3319 预览进程开启精确的 `/_next/hmr` WebSocket 转发。Standalone 上游使用默认设置。

3319／3322 仅为自动化隔离测试端口，不作为试用入口；写测试不得指向 3363 或业务数据库。端口、构建和输出目录由本轮负责人协调，测试结束释放本次资源。历史共享试用库中的样例及首页由当轮负责人维护，不覆盖他人记录或配置。

首次安装浏览器可执行 `pnpm --filter @hd/admin exec playwright install chrome`。浏览器测试需要先 build；不会把旧开发服务当成最新成品。根检查、构建与浏览器命令已纳入后台；共享锁文件仅由当轮集成人维护。

产物为 `apps/admin/dist/`。生产由 OPS 在 `/admin/` 提供静态文件，并把后台深层路由回退到 `/admin/index.html`；`/api/` 单独转发 API，不能回退为 HTML。后台入口和管理 API 不缓存敏感响应，生产 Cookie／可信 Origin／HTTPS 及安全响应头由 API 与代理共同配置验证。Vite preview 仅用于本机成品检查。本轮 UX11 尚未部署，历史生产版本与本机运行版本分别由 OPS 记录。

## 源码约定

- `src/main.tsx`：路由装配、权限入口与 React 挂载。
- `src/modules/auth/`：应用壳、员工会话、登录与退出；会话过期用弹层锁定编辑，同账号登录恢复输入，换账号清除旧页面。
- `src/modules/vehicles/`：草稿、详细配置、统一多语工作区、媒体恢复、库存／发布和公开数据核验；不含 API 实现。
- `src/shared/api/`：同源 HTTP、schema 校验、统一错误；不自动重试写入。
- `tests/`：界面契约和真实隔离联调；合成数据不进入运行页面。

完整替换草稿时保留未编辑的图片和三语版本；金额使用字符串，未知事实保持 null。创建结果不明时保留原请求和幂等键，不让修改后的内容冒充原请求。409 比较最新草稿并保留本地输入；员工明确放弃后才载入最新版本。内存中的未保存内容在关闭页面后不恢复，不把内部资料写入浏览器持久存储。

图片管理从 `/api/v1/admin/vehicles/:id/media-uploads` 读取当前车辆的名额与待处理任务。刷新后，已上传的图片可继续处理或加入草稿。只有上传许可、文件尚未发送时，可回收任务后重新选图。保存草稿或完成图片操作后重新读取列表。旧接口返回 404／405 时继续使用原上传和草稿流程。回收使用最新媒体版本，服务端核对草稿和发布历史引用。原文变化需先保存，再在车辆配置页复制该草稿当前版本的提示词。

当前 UI 为 Ant Design 6.7/icons 6.3 统一黑金主题，后台使用与官网一致的 Logo 并独立提供静态资源：车辆表格含缩略图、名称／车号／价格和状态；员工创建／最近人工修改并入原日期列，1200宽桌面不增加短横滚，390窄屏只在表格内部滚动。姓名完整换行，键盘聚焦或悬停可读取完整员工ID、日期年份及UTC；详情保持完整追溯。车型下拉合并现有管理字典与按品牌整理的常用车型建议，可输入名称新增。录入分为基础资料、车辆配置、价格与内部信息、图片管理、发布预览五个分组。车况描述在基础资料填写，内部备注保留在价格与内部信息。批量库存／下架最多 50 辆、保留选择时版本和固定幂等意图，成功项移出选择、失败项保留，冲突须核对后新请求。首页区块在 `/admin/home-sections`，需要 home:write 权限。排序支持拖动手柄、键盘（空格拿起，方向键／Home／End 移动，Enter 放下，Escape 取消）、上下移动、指定序号及置顶／置底。新选车辆可加入顶部；保存前顺序只在本地草稿，失败或冲突保留当前顺序。

新增固定为真实人工车源。品牌、车型、中文标题、配置款型、年款、里程和车辆所在地齐备后，点击下一步保存草稿并进入车辆配置，里程 0 有效。登记默认为已登记，国家默认中国，员工填写实车所在地。历史缺所在地的车辆可继续保存其他字段，补录所在地时按实车填写。提示词自动带入基础资料，动力类型由 AI 按标准值整理，员工确认后随配置保存。新填价格只接受整数。公开字段英俄译文可分批保存，发布前须补齐。新录公开报价和采购成本固定 CNY，历史币种和车辆事实随记录保留。人工车图片直接上传，由服务端记录默认授权及上传员工、时间；外部图片继续按图记录来源和依据。三语导入将排量、功率、原始马力、变速箱和车身形式保存为详细配置项目。将这些配置同步至独立筛选字段需要扩展配置导入 API。

首页精选可加入已发布且可公开展示的可售、已预订和已售自有车。库存变化为预订或已售时保留已有选择与顺序，后台按实际状态标识。保存时复核所选车辆，最终保存与公开资格由首页接口判定。

首页配置分别提供「添加精品车辆」和「添加三方车辆」。精品入口读取员工已发布车源，三方入口搜索同步挂牌的 ID、询价编号、车型或标题。两类车源在同一区块中统一排序、保存，三方车源加入和保存前均复核公开资格。真实混合保存和官网展示需要配套首页 API。

删除与下架分别处理：下架保留普通档案，删除移入 `/admin/recycle-bin` 并撤销公开访问／首页引用，保留历史和图片。回收站只读且不加载图片；恢复仅回到未发布草稿、库存待核验，需要重新发布，不自动加回首页。删除／恢复结果未知时保留原版本和幂等键，成功或重放后再读取当前状态，不把历史回执当成最新状态。

外部挂牌使用完整source元数据，平台身份与原挂牌身份创建后不可改。价格仅为来源参考或待询价，库存未知，公开文字不会标成人工已审核。上传前逐行填写与本次文件顺序一一对应的原图URL，每张图均保存挂牌地址、原图地址和UTC采集时间；来源地址只记录，不自动下载。许可待核验只供本地资料整理，生产使用前核验。

## 三方 API 状态与车源管理

`/admin/external-sources` 展示 ChinaCarAPI 账户连接、探测时间、套餐、到期和覆盖平台，以及本地最近成功入库和已知来源时间。账户探测与入库记录分别显示，自动同步当前为未配置。未配置账户探测时，页面说明需要配置的连接。连接正常时，套餐或额度等缺项显示为供应商未返回。

`/admin/public-catalog` 显示全库挂牌、已展示、人工隐藏和来源撤回数量。出口资格显示待核验。关键词可与来源平台、挂牌状态、品牌、车型、动力、年款及里程组合，筛选与分页均由管理 API 执行。列表展示入库参数、修订标记和原站链接，详情返回时恢复筛选与页码。具备车辆写权限的员工可分别编辑车辆事实及公开文案，16 个事实字段和 9 项三语文案全部展开，核对原值、语言和版本后直接编辑保存。跟随来源、显式未知和各语种清除分别处理；来源撤回时不开放人工修订入口。

`/admin/external-sources/batches` 保留历史导入、来源追溯及试译测算。管理员可导入已规范化的 JSON（每批至多 250 行、8 MiB）、查看受保护原档和提交固定 100 条试译测算。挂牌修订使用当前管理版本。品牌或车型事实改变时先提交事实，再重新核对车型译文。批次内仍可批量隐藏或取消隐藏。访客视角的公开车源核验入口位于 `/admin/public-catalog/verification`。

隔离真实接口用例需要 BE 提供同版已构建的合成 API。先构建后台，再运行：

```sh
ADMIN_LIVE_EXTERNAL=synthetic-only ADMIN_LIVE_TRANSLATION_PROVIDER=disabled \
  pnpm --filter @hd/admin test:e2e:live --grep '(?:^| )real external catalog supports admin import, trial and override$'
```

该用例仅启动本机 3319／3322，使用独占随机 `hd_ext_ad_*` 数据库和合成管理员。默认浏览器真实联调模式跳过此例。

## 车辆配置和三语展示（REL-103）

先填写并保存基础资料。品牌和车型候选合并本地车型名录及已有草稿字典，可用中文、英文或别名搜索，缺项可手动新增。车辆配置页可复制带入基础资料与同车公开字段的提示词，由外部 AI 检索同款技术资料并整理三语 JSON，多个候选影响匹配时先确认款型。上传 UTF-8 JSON 或直接粘贴，后台为仅含 `name`、`value` 的配置项目生成编号，并按字段路径显示错误。预览使用字段、中文、英文、俄文四列，逐项调整文件后重新预览。保存或刷新后以该车服务端已保存的三语资料回显。

「确认并保存三语资料」使用同一份预览文件与绑定车辆、员工、车辆版本及多语修订的令牌，在一个事务里保存草稿。文件提供 `items` 时替换整份配置，省略的其他段落按契约保留。已发布快照沿用既有发布流程。失效或冲突时保留输入并重新预览，网络中断可先读当前版本核对结果。后台没有在线翻译操作。协议和字段格式见 BE 的配置导入契约。

动力类型可在车辆配置单独填写，也可随三语 JSON 导入。标题和车况描述原文在基础资料维护，译文对应 `content.title` 和 `content.description`。车型、公开图片说明等其他已有公开文字对应 `display`，使用该车提示词内的字段引用。复制三语提示词后，AI 按要求提供可下载的 `vehicle-configuration.json`，可直接上传核对。发布检查的多语缺项链接会打开车辆配置、提示具体字段和语言并定位 JSON 输入框。

## 发布预览与明确发布

manual 和员工维护的 external 副本发布前需要品牌、车型、中文标题、配置名称、有效详细配置、年款、已知动力、里程（0 有效）、正数价格及币种、正数内部采购成本及币种、有效图片、车况描述和所需英俄译文。manual 用公开报价，员工 external 副本保留来源参考价与库存未知；自动外部挂牌不进入该员工发布流程。可先保存未完成草稿，空报价保留报价意图与已选币种；不追溯改写旧已发布快照。采购成本、供应商和内部备注不进入公开预览。

年款、制造／登记日期和来源时间使用日期组件，保持实际精度；标明 UTC 的选择器按所选墙钟时间保存 UTC。服务端 `hasUnpublishedChanges` 决定是否有待发布修改，不能用更新时间猜测；内部资料与库存更新不要求重复发布。

在最后的「发布预览」分组显示发布操作和检查结果。网页预览是按需打开的辅助项，打开后从同源 `/staff/vehicles/:id/publication-preview/` 读取员工鉴权的草稿投影。继续核对 frame 消息来源、实例、车辆、语言及版本来显示真实预览状态，失败后可以重新载入或收起。

发布预览中的「发布检查」按服务端回执显示待补资料，可点击定位到对应分组和字段。多语缺项显示具体字段和语言。保存后重新读取当前版本的发布检查。

当前资料已保存、服务端发布检查通过且账号有发布权限时，可点击「确认并发布」。后台用同一份发布检查返回的 revision／fingerprint／locale／version 执行现有版本确认，确认通过后提交同一版本。全部必填、库存、有效图片和三语检查仍由服务端执行。确认失败或草稿版本变化会停止发布，结果未知时仍使用原请求和幂等标识恢复。网页预览未打开、载入中或失败时也可按已保存资料确认。

## 网站分析

管理员从「网站分析」查看 `GET /api/v1/admin/analytics/overview?days=7|30` 的同源汇总。菜单、直达路由和服务端读取都使用 `staff:manage` 权限。日期范围按北京时间自然日，页面显示服务端的采集开始时间，开始前的日期标为未采集。切换日期范围或刷新时保留所选趋势指标。一个查询结束后才读取最新选中的日期范围。

页面浏览（PV）计入公开车辆详情浏览。热门车辆显示服务端提供的综合前 20，可按车辆卡片点击、详情浏览、主动联系点击在这 20 条内排序，并沿编号进入对应车源。主动联系点击统计官网已接入的 WhatsApp、Telegram 入口，用于了解联系意向。空窗口、首次尚无采集、读取失败和权限不足各有状态。

## 员工与系统操作追溯（EXT06）

车辆列表、回收站及详情、三方列表及详情复用只读操作记录抽屉，沿用 `vehicles:read`；不为查看历史放开车辆写入路由，不新增账号管理或审计修改功能。轻摘要消费正式 `activity`：创建、最近人工修改与首次系统导入／批次、最近同步分开，缺少历史如实显示未知，不用 `updatedAt` 或当前登录人补齐。

历史分别读取 `GET /api/v1/admin/vehicles/:id/activity` 和 `/api/v1/admin/external/listings/:id/activity`，默认每页20条，使用正式游标。显式刷新返回第一页；关闭、换车、401会中止请求，晚回包不合并，登录失效立即清除已读取的历史。重新登录后需显式刷新。403／网络失败不显示空历史。时间明确显示北京时间并保留DB UTC原值，员工姓名与ID来自操作时快照。

每条事件以正式event.id识别；车辆与图片记录的版本可能重叠，不能以版本区间当事件唯一标识。图片申请上传、文件上传、处理完成、删除分别显示中文动作，未知操作保留文本回退。

展开事件只展示BE提供的字段前后值，不拿当前草稿倒推旧记录。未知历史、记录无差异、字段未记录、明确null、空字符串、0和false分别显示；长文本与图片稳定ID保持完整，按文本渲染，不加载历史URL。查看记录不改变未保存的车辆／多语输入。当前UI契约模拟不替代两员工真实数据库、事务与权限联调，不标记已部署。员工维护的external副本保留创建信息，系统来源信息另列；自动三方挂牌以首次系统导入为主。

## 正式同步状态与供应商原档（EXT07）

三方 API 状态复用 `/api/v1/admin/external/sync-status`，分开展示最新全量快照与同步已登记来源记录、增量接收和处理数、当前撤回、待补资料及最后成功时间。快照总行数未核定时仍显示实际暂存数。首次入库进度和改价事件数没有独立统计时，标明当前资料的覆盖范围。待补详情、语言项和报告使用各自的统计单位。刷新失败或登录失效时移除旧读数。

仅管理员显示暂停／恢复入口，服务端仍负责实际权限。确认后以当前version和固定UUID幂等键提交 `/sync-control`；操作中禁止重复提交，结果未知保留原正文与原键。安全刷新不重发POST或丢弃原意图；结束重试须明确确认且不撤销可能已执行的请求。409／403须重新读取。成功回执只确认本次请求，随后GET最新状态，不把历史幂等回执当作当前进度；恢复后容量保护仍可能保持暂停。此页不创建任务或启用旧synthetic同步。

历史批次仍通过 `/api/v1/admin/external/ingestion-status` 显示固定名单的一次导入任务，明确标为历史；旧手动样本另列，不替代正式全量进度。供应商账户有独立刷新，套餐／额度与入库／来源时间不混用。三方列表及详情使用BE给出的完整询价短编号，保留来源、原链接、原平台编号及旧UUID搜索和详情路径，不自行推导编号。

三方详情的“供应商原档与历史”按需读取 `source-documents` 游标目录，员工选择后才读取该车文档。支持CSV、详情、规格、报告与事件的zh/en/ru/und历史，保留hash和首次／最近观察时间。正文只按纯文本／JSON显示，不执行脚本、不自动打开其中URL或抓取报告。共享批量响应仅显示归档hash，不把它冒充完整bulk原文。当前车文档归属由BE验证；404／失败清除旧正文，可显式重试；换车／401与历史抽屉复用私有请求隔离。真实正式原档完整性仍由BE／OPS验证。

EXT07本机只编辑／提交，应用检查、构建与浏览器模拟由OPS在准确SHA的服务器隔离环境执行，真实接口权限、暂停期间撤回及查询连续性须同版联调；未执行前不声称通过。`tests/sync-cases.ts` 覆盖计数分离、员工只读、管理员确认、防重、结果未知的原请求恢复、409／403、保护暂停和短编号搜索；fixture通过不替代真实API或正式全量完成。

原始马力 `powerHp` 与 `powerKw` 独立，保留草稿中的旧值、空值、0 或旧记录省略。三语配置可收录资料直接提供的 hp，和以 kW 提供的不同功率口径分别展示。三方详情展示契约给出的 hp 和单位。

## 来源报告入口

员工车辆详情（含有真实来源关联的 external 副本）与第三方挂牌详情只读取正式鉴权字段 `report.url`。有合法安全 HTTPS 原始地址才显示“打开来源报告”，使用普通 `<a target="_blank" rel="noopener noreferrer">`，保留完整原始 href，不拼接、不归一化、不自动 fetch／prefetch。它不表示正文或链接可用性已核验，也不依赖公开 `reportAccess.available`。`hasReport:true` 但 `url:null` 合法，此时没有打开按钮；公开详情及鉴权预览只消费 `report.hasReport` 并提示联系销售，不暴露地址。

员工副本的绑定由 BE 按 platform、externalId 和原始 listingUrl 精确匹配，界面不从公开字段或候选数据猜 URL。来源身份有未保存修改时隐藏旧报告入口。历史 mutation 回执可能省略 report，成功后只 GET 详情并合并报告元数据；核对车辆、版本及来源绑定，不用迟到的详情覆盖新输入，也不继承旧来源链接。完整含参数地址不写入公共日志。相关组件为 `src/shared/ui/source-report-link.tsx`，没有报告探测请求。
